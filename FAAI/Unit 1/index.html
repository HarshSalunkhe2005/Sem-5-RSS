Introduction to Intelligent Agents & Autonomous Systems

What is an Intelligent Agent?

5–6 marks

1Definition / Introduction

An Intelligent Agent is any entity that perceives its environment through sensors, reasons about what it perceives, and acts upon that environment through actuators to achieve specific goals. In short: Agent = Perception + Reasoning + Action. It is autonomous (acts without constant human input), goal-driven, rational (chooses the best available action), reactive (responds to real-time changes) and adaptive/learning (improves from experience). Classic thought experiment: ChatGPT can generate text, but it cannot on its own book a flight, compare hotel prices, and pay for you — that extra "something" (planning + memory + tools + autonomous action) is exactly what turns a language model into an agent.

The loop never stops: environment changes → sensors detect it → reasoning decides → actuators respond → environment changes again.

↺ Continuous Perceive–Reason–Act Cycle

3Step-by-Step Working

  1. Sense: Sensors (camera, GPS, microphone, API polling) collect raw percepts from the environment.
  2. Interpret: Raw percepts feed into a knowledge base / internal representation.
  3. Reason: The reasoning engine (rule set, search, or an LLM) evaluates the percept against the agent's goal.
  4. Decide: The best available action is selected.
  5. Act: Actuators (motors, brakes, speakers, API calls) execute the chosen action back on the environment, and the cycle repeats.

4Real-World Example

Tesla Autopilot: cameras/radar/GPS perceive the road every second → the AI model reasons about obstacles, lane markings and speed → brakes/steering/throttle act in real time → the road changes and the cycle repeats. Other everyday agents: Alexa/Siri (voice → intent → skill execution), Google Maps (traffic percepts → routing reasoning → turn-by-turn actuation), Amazon warehouse robots.

5Conclusion / Key Advantage

An intelligent agent's defining strength over a plain program is autonomy under a continuous feedback loop — it does not just compute an output once, it keeps sensing and adapting, which is the foundation every later topic (PEAS, environments, architectures, and finally LLM-powered agents) builds on.

Agent–Environment Interaction & the PEAS Framework

PEAS Framework

5–6 marks

1Definition / Introduction

PEAS is a systematic framework used to fully specify a task environment before designing an agent, standing for Performance measure, Environment, Actuators, Sensors. Defining PEAS forces a designer to be precise about what "success" means, where the agent operates, how it acts, and how it perceives — before a single line of the agent program is written.

2Neat Labeled Diagram — PEAS applied to a Self-Driving Taxi

🎯 Performance

Safety, speed, legal driving, passenger comfort, minimal fuel

🌍 Environment

Roads, traffic, pedestrians, signals, weather

🦾 Actuators

Steering, accelerator, brake, horn, display

📡 Sensors

Cameras, GPS, speedometer, LiDAR, engine sensors

3Step-by-Step Working — Component Anatomy

ComponentRoleExample
EnvironmentEverything surrounding the agentRoad, home, hospital
SensorCollects raw dataCamera, GPS, radar
AI Model (Reasoning)Processes data, makes decisionsNeural network / rule engine
ActuatorExecutes the physical/digital actionMotor, brake, speaker

Without sensors the agent is blind; without actuators it is powerless. The full loop is Perception → Reasoning/Planning → Action → Feedback, and feedback (e.g. a customer rating) is used to refine future decisions.

4Real-World Example

Food-delivery agent: Performance = fast & accurate delivery, customer satisfaction; Environment = city roads, restaurants, traffic; Actuators = driver-assignment messages, route display, notifications; Sensors = order data, GPS location, restaurant prep-time feed. It perceives an order → reasons about restaurant/route options → assigns a driver → uses ratings as feedback to keep improving.

5Conclusion / Key Advantage

PEAS gives a reusable checklist for specifying any agent — from a thermostat to a self-driving car — which is exactly why it is the standard first step in agent design, and it directly feeds into classifying the environment (next topic).

Environment Types & Classification

The 6 Dimensions of Task Environments

6 marks · high-yield

1Definition / Introduction

The Agent Environment is the external world the agent perceives and acts in. Its properties along six fundamental dimensions determine how complex the agent's program must be — whether it needs memory, search/planning, or probabilistic reasoning.

2Neat Labeled Diagram — The 6 Dimensions (Simple ↔ Complex)

DimensionSimpleComplex
ObservabilityFully ObservablePartially Observable
DeterminismDeterministicStochastic
Episode StructureEpisodicSequential
Time DynamismStaticDynamic (Semidynamic in between)
State SpaceDiscreteContinuous
Agent CountSingle-AgentMulti-Agent

3Step-by-Step Working — Architectural Impact of Each Dimension

  1. Fully vs Partially Observable: Chess = fully observable (board fully visible). Poker / driving in fog = partially observable (hidden cards, blind spots). Consequence: partial observability mandates internal state / memory to track a belief state.
  2. Deterministic vs Stochastic: Next state fully determined by current state+action (deterministic) vs randomness/noise present (stochastic, e.g. dice, sensor noise). Consequence: stochastic worlds need probabilistic policies and contingency plans.
  3. Episodic vs Sequential: Spam classification = episodic (each email independent). Chess/driving = sequential (current move constrains the future). Consequence: sequential worlds demand lookahead planning — greedy choices cause long-term disaster.
  4. Static vs Dynamic: Crossword = static (world waits while you think). Autonomous driving = dynamic (world changes while you deliberate); chess-with-a-clock = semidynamic (world frozen, but your score/time ticks). Consequence: dynamic worlds need real-time event loops.
  5. Discrete vs Continuous: 64 chess squares = discrete. Steering angle/speed = continuous (infinite real values). Consequence: continuous state needs discretization/embedding buckets.
  6. Single-Agent vs Multi-Agent: Solitaire = single-agent. Poker/self-driving traffic = multi-agent (competitive or cooperative, game-theoretic dynamics).

Bonus distinction: Known vs Unknown ≠ Observability. Known/Unknown is about whether the agent knows the rules/physics of the world (e.g. a fully-visible video game you've never played before is Fully Observable but Unknown — the agent must explore to learn the transition function).

5Conclusion / Key Advantage

The hardest possible environment is Partially Observable, Stochastic, Sequential, Dynamic, Continuous, Multi-Agent (e.g. real-world autonomous driving) — because it simultaneously demands memory, probabilistic policies, lookahead planning, real-time responsiveness, and negotiation with other agents. This is exactly why modern agentic-AI systems (LLM + tools + memory) are needed instead of simple reflex programs.

Types of Agents: Simple Reflex → Model-Based → Goal-Based → Utility-Based → Learning

The 5 Agent Architectures

6 marks · very high-yield

1Definition / Introduction

Agent architectures describe the internal data structures and reasoning engines that convert incoming percepts into outgoing actions. They range from stateless reflex agents to self-improving learning agents — each layer adds a new capability on top of the last.

3Step-by-Step Working — Each Architecture

1. Simple Reflex Agent

Operates purely on Condition-Action rules: IF condition THEN action. No memory of past percepts. Fatal flaw: perceptual aliasing — in a partially observable environment, two different real states can produce the identical percept, trapping the agent in an infinite loop. Example: a thermostat.

2. Model-Based Reflex Agent

Maintains an internal state combining the current percept with past observations, using two knowledge pieces: how the world evolves on its own, and how the agent's own actions affect the world. State update: s_t = UPDATE(s_t-1, a_t-1, p_t). Overcomes perceptual aliasing. Example: a robot vacuum that remembers a room map.

3. Goal-Based Agent

Combines the world model with explicit goals — desirable future situations — and performs search/planning (forward simulation) to pick actions that lead there. Limitation: binary decision metric (goal reached: yes/1 or no/0) — cannot weigh trade-offs between multiple valid paths. Example: GPS routing, Chess AI.

4. Utility-Based Agent

Uses a continuous utility function U(s) that scores how desirable a state is, choosing a* = argmaxa Σ P(s'|s,a)·U(s'). This allows optimal trade-offs when goals conflict — e.g. a route 3 min slower but ₹20 cheaper and 80% safer can score higher than the "fastest" route. Example: ride-share dispatch, algorithmic trading.

5. Learning Agent

Adds a Critic that evaluates performance against a fixed standard, a Learning Element that updates the agent's policy based on that feedback, and a Problem Generator that suggests exploratory actions to discover better strategies over time. Example: AlphaGo, autonomous robotics, recommendation engines.

5Conclusion / Key Advantage

Each architecture solves the previous one's limitation: memory fixes perceptual aliasing, goals fix "no direction", utility fixes "can't compare options", and learning fixes "can't improve over time." Modern LLM-powered agents (Topic 6) are essentially Learning + Utility + Goal-based reasoning implemented with a language model as the reasoning engine.

Traditional AI vs Agentic AI & the 4 Agent Design Patterns

Why Do We Need Agentic AI?

5–6 marks

1Definition / Introduction

Imagine asking an AI assistant: "Plan my 4-day Goa trip under ₹30,000 — book flights, reserve a hotel, check the weather, and prepare an itinerary." Classical/Traditional AI is designed for single, specific tasks: no multi-step planning, no memory across steps, and no autonomous tool access — it always needs continuous human guidance. Agentic AI is an AI system that understands goals, reasons about problems, plans multiple connected steps, uses external tools, and executes tasks autonomously — behaving like a skilled digital employee rather than a simple chatbot.

2Neat Labeled Diagram — Traditional AI vs Agentic AI

Key takeaway: Traditional AI solves a single problem. Agentic AI completes an entire workflow — from goal to result.

3Step-by-Step Working — The 4 Agent Design Patterns

👤 Single-Agent

One agent handles the entire task end to end. e.g. ChatGPT answering a question.

🧭 Planner–Executor

One component plans; another executes the plan. e.g. AI project-management assistant.

🧩 Multi-Agent

Multiple specialized agents collaborate on sub-tasks. e.g. AI software-development team.

🪞 Reflection

The agent reviews and critiques its own output before responding. e.g. AI proofreading an essay.

Characteristics that make a system "agentic": Autonomy (operates without constant oversight), Planning & Reasoning (decomposes complex goals into actionable steps), Tool Integration (connects to search engines, APIs, databases), Memory & Feedback (remembers context and improves from outcomes).

4Real-World Example

Case study — AI Research Assistant: Prompt: "Prepare a report on Electric Vehicles in India." The agent autonomously (1) understands the goal, (2) searches academic databases, (3) collects & filters relevant papers, (4) summarizes key findings into a structured, professional report — with no step-by-step hand-holding.

5Conclusion / Key Advantage

Classical AI has limits — single-task, reactive systems cannot handle complex real-world workflows. Agentic AI is autonomous: it reasons, plans, uses tools, and completes entire workflows independently. The architecture equation is LLM + Planner + Memory + Tools + Feedback = a complete agentic system — and the LLM is what supplies the reasoning "brain" (next topic).

LLM-Powered Agents: Architectures & Applications

From Passive Chatbots to Autonomous Agents

5–6 marks

1Definition / Introduction

An LLM-Powered Agent is an intelligent system that uses a Large Language Model as its reasoning engine, combined with memory, planning, and external tools, to complete tasks autonomously. The LLM alone only understands and generates language; wrapping it with planning + memory + tools + environment access is what turns it into a true agent.

The LLM sits at the center, orchestrating Planner ↔ Memory ↔ Tool-Executor ↔ Feedback to act on the Environment.

3Step-by-Step Working

Classroom example: "Summarize this PDF and email it to my manager." → (1) reads & parses the PDF, (2) summarizes key content, (3) drafts a professional email, (4) sends it via an email tool. The LLM is the brain; planning, memory and tools enable the real-world action.

4Real-World Example — Applications

🗣️ Virtual Assistants

Siri, Alexa, Google Assistant — reminders, scheduling, smart-device control.

🔎 Research Assistants

Automating literature review, summarizing papers, structured reports.

📈 Productivity Automation

Email drafting, calendar scheduling, meeting summarization at scale.

Industry spread: Healthcare (report summarization), Finance (fraud detection), Education (AI tutors), Retail (recommendations), Logistics (route optimization), Legal (contract review).

Benefits: saves time, faster decisions, higher productivity, scales to complex workloads. Challenges: hallucinations, unsafe tool usage, privacy/security risk, high compute cost, ethical concerns.

5Conclusion / Key Advantage

An LLM becomes far more powerful when combined with memory, planning and external tools — this is the single biggest idea of Unit 1, and it is the direct bridge into Unit 2, which studies how the LLM reasons (Chain-of-Thought, Self-Consistency, ReAct) and how it plans and calls tools reliably.
