Unit 1 — Introduction

Likely Questions

Q1What is an intelligent agent? Explain the perceive–reason–act cycle with a diagram. 5–6

An agent perceives its environment through sensors, reasons, and acts through actuators to achieve goals; it is autonomous, goal-driven, rational, reactive and adaptive. Diagram: Environment → Sensors → Reasoning/Decision → Actuators → Environment (continuous loop). Example: Tesla Autopilot — cameras/radar sense the road, the model decides, brakes/steering act.

Q2Explain PEAS with an example. 5

PEAS specifies a task environment: Performance measure, Environment, Actuators, Sensors. Self-driving taxi: P = safety, speed, legality, comfort; E = roads, traffic, pedestrians; A = steering, accelerator, brake, horn; S = cameras, GPS, LiDAR, speedometer.

Q3Classify environments along the six dimensions; give examples. 6

Fully/partially observable (chess / poker); deterministic/stochastic (chess / driving); episodic/sequential (spam filter / chess); static/dynamic (crossword / driving); discrete/continuous (chess squares / steering angle); single/multi-agent (solitaire / poker). Real-world driving is the hardest: partially observable, stochastic, sequential, dynamic, continuous, multi-agent.

Q4Explain the types of agents (simple reflex → learning) with limitations and examples. 6

  • Simple reflex: condition-action rules, no memory; fails under perceptual aliasing (thermostat).
  • Model-based: keeps internal state of how the world evolves/actions affect it (robot vacuum).
  • Goal-based: uses goals + search/planning; binary success only (GPS routing).
  • Utility-based: maximises utility U(s), handles trade-offs (ride dispatch).
  • Learning: critic + learning element + problem generator (AlphaGo).

Q5Traditional AI vs Agentic AI; list the 4 design patterns. 5–6

Traditional AI: single task, reactive, no planning/memory/tools, needs frequent user input. Agentic AI: whole workflows, proactive, multi-step planning, memory, tools/APIs, autonomous. Patterns: Single-agent, Planner–Executor, Multi-agent, Reflection.

Q6What is an LLM-powered agent? Draw its architecture and give applications. 5–6

An agent that uses an LLM as its reasoning engine, combined with planner, memory and tools. Diagram: User goal → LLM → {Planner, Memory, Tools/APIs, Feedback} → action. Applications: virtual assistants (Siri/Alexa), research assistants, productivity automation. Challenges: hallucination, unsafe tool use, privacy, cost.

Unit 2 — LLM Strategies

Likely Questions

Q7Explain Chain-of-Thought reasoning with benefits and limitations. 5–6

The LLM generates intermediate reasoning steps before the final answer (Understand → Step 1 → Step 2 → Answer). Benefits: accuracy, explainability, handles multi-step problems. Limitations: slower, more tokens/cost, wrong assumption → wrong conclusion, overkill for simple queries.

Q8Compare CoT, Self-Consistency and Tree-of-Thought. 6

CoT = single reasoning path. Self-Consistency = several independent paths, majority vote on the final answer. ToT = branching exploration where each branch is evaluated, weak ones pruned, strongest continued (search with backtracking). Example: tech-fest budget — compare options A/B/C, prune the over-budget one.

Q9Explain the ReAct framework / agent loop with termination controls. 6

ReAct interleaves Reason and Act: Decide → Execute tool → Observe → loop until a final answer. Termination: final answer generated, MAX_STEPS reached, tool-failure limit, high-risk action requiring human approval. Tool registry (allowlist) prevents calling unregistered functions. Dependent tools run sequentially; independent ones in parallel.

Q10Explain agent planning: decomposition, sequential, hierarchical, long-horizon; static vs dynamic planning. 5–6

Decomposition splits a goal into sub-tasks (avoids attention dilution); sequential = ordered pipeline; hierarchical (HTN) = goal → tasks → primitive actions; long-horizon = hundreds of steps needing checkpoints. Static Plan-and-Solve crashes if a step fails; dynamic replanning (interleaved ReAct, Reflexion's verbal self-critique) adapts to observations.

Q11Why do agents need tools? List tool types and the tool-selection process. 5–6

LLMs have a knowledge cutoff, no external access, weak math, and cannot act. Tools: search engine, APIs, databases, vector DB, code interpreter, productivity tools (email/calendar). Selection: understand intent → identify capability → match tool → execute & return. Challenges: wrong tool choice, API failures, security, cost.

Q12What is function calling / structured output? Why JSON? 6

Free-text output is unparsable and inconsistent; structured output forces machine-readable JSON. Function calling: (1) app exposes function schemas, (2) LLM emits a JSON call, (3) app validates & executes, (4) result returned to the LLM. The LLM only requests; the app executes — a security gatekeeper. JSON is machine-readable, key-value structured, language-independent, API-compatible.

Q13What are hallucinations and knowledge cutoff? How are they mitigated? 5

Hallucination: confident but wrong output from next-token prediction. Cutoff: no knowledge after training date or of private data. Mitigation: retrieval grounding (RAG), search/API tools, citations, self-consistency, verification; process documents (clean, chunk, embed) into a vector DB.

Unit 3 — RAG & Agent Strategies

Likely Questions

Q14Explain the context window and why LLMs "forget" in long conversations. 5

Context is a fixed token budget shared by system instructions, conversation and retrieved docs. In long chats older content is truncated/summarised, so it is no longer available — an architectural limit, not human-like forgetting. This motivates agent memory and RAG.

Q15Explain agent memory architectures (short-term, long-term: episodic, semantic, procedural). 6

Short-term/working memory = in-context scratchpad (current goal, plan, tool results; fast, ephemeral). Long-term = external persistent store: episodic (past events), semantic (facts/user profile), procedural (how-to skills). New facts go through a relevance/consistency check → insert/update/ignore. Retrieval ranks by recency + importance + relevance; reflection turns raw events into insights.

Q16What are embeddings and vector databases? Name similarity metrics. 6

An embedding is a dense vector capturing semantic meaning (similar meaning → nearby vectors). A vector DB (FAISS, Chroma, Pinecone, Milvus) stores them and does nearest-neighbour search by meaning, unlike SQL's exact match. Metrics: cosine similarity (angle), Euclidean distance, dot product.

Q17Explain RAG architecture with a diagram, chunking trade-offs and RAG vs fine-tuning. 6 — anchor question

Offline: ingest docs → chunk → embed → store vectors. Online: query → embed → top-k match → inject into prompt → LLM gives a grounded answer. Small chunks = precise but incomplete; large = continuity but noisy/costly; overlap preserves context across boundaries. Fine-tuning bakes knowledge into weights (slow, costly); RAG retrieves at inference (cheap, easily updated). Grounding reduces hallucination.

Q18Write short notes on ANN search and indexing strategies. 4–5

Exact search compares with all vectors (slow). ANN trades slight recall for speed. Indexes: Flat (exact), IVF (cluster then search nearest clusters), HNSW (layered navigable graph — fast, high recall, memory heavy), PQ (compression).

Q19Explain hybrid retrieval, re-ranking and multi-hop retrieval. 5–6

Hybrid = BM25 keyword + dense vector, fused (e.g. RRF). Re-ranking = cross-encoder re-scores top-N candidates (query+chunk jointly) and keeps the best few. Multi-hop = iterative retrieve → reason → new sub-query → retrieve, to chain facts across documents.

Q20Describe the knowledge ingestion pipeline. 4

Data preprocessing (parse, clean, metadata) → document indexing (chunk, embed, store in vector + keyword index) → retrieval optimization (tune chunk size/overlap/top-k, filters, hybrid, re-rank, evaluate recall@k, refresh index).

Unit 4 — Multi-Agent Systems & MCP

Likely Questions

Q21What is a multi-agent system? Why use it over a single agent? 5

A distributed AI system of multiple autonomous agents that interact to solve a problem (collaborative intelligence). Benefits: specialisation, parallelism, modularity, robustness (no single point of failure), better handling of complex tasks. Costs: coordination overhead, more tokens/latency, harder debugging.

Q22Explain agent communication: message passing and protocols. 5

Agents exchange structured messages (sender, receiver, intent/performative such as request/inform, content) directly (message passing) or via a shared store (blackboard). Protocols define format and order (e.g. FIPA-ACL style, JSON messages, agent-to-agent protocols). Can be synchronous or asynchronous.

Q23What is Model Context Protocol (MCP)? Explain its architecture and compare with traditional API integration. 6 — likely

MCP is an open standard for connecting AI applications to tools and data in a uniform way. Without it every agent×tool pair needs custom glue (N×M); with it, N+M. Architecture: Host/Client (the AI app) ↔ MCP Server exposing resources (data), tools (actions) and prompts, over JSON-RPC (stdio/HTTP). Compared with traditional APIs: standard discovery of capabilities, one protocol instead of bespoke APIs, reusable servers, interoperability across agents/models.

Q24Describe agent roles and collaboration models. 5–6

Roles: Planner (decomposes goal), Executor (performs actions/tools), Research (gathers information), Critic (reviews/validates output). Models: hierarchical (manager delegates to workers), role-based (fixed specialised roles), cooperative problem solving (peers share results toward a common goal).

Q25Explain swarm intelligence and give applications of multi-agent systems. 5

Swarm intelligence: many simple agents follow local rules with no central control (decentralised coordination) and complex global behaviour emerges (emergent behaviour) — ant colonies, bird flocks, drone swarms. Applications: autonomous research assistants, software-development agents (planner/coder/tester/critic), business-automation agents.

Q26What are the deployment considerations for agent systems? 4

API-based deployment (expose the agent as a service), monitoring and logging (traces, tool calls, errors, cost, latency), scaling (concurrency, queues, caching, rate limits, horizontal scaling).

Unit 5 — Evaluation, Safety & Governance

Likely Questions

Q27Why is evaluating agents hard? Explain the key metrics. 6

Agents are non-deterministic, multi-step and tool-using, so judging only the final text is not enough. Metrics: task completion (success rate), tool efficiency (correct/necessary tool calls, redundant calls), latency and cost (time, tokens, $ per task). Use benchmarks and repeated runs to compare systems.

Q28How can hallucination be mitigated in agents? 5

Fact verification (cross-check claims against trusted sources/tools or a verifier agent) and retrieval grounding (RAG with citations). Also constrain outputs, lower temperature, self-consistency.

Q29What are agent guardrails? Explain output validation and tool access restrictions. 6

Guardrails are controls that keep agent behaviour safe and within bounds. Output validation: check schema/format, safety and policy before using or showing output. Tool access restrictions: allowlist, least-privilege permissions, sandboxing, and human approval for high-risk/irreversible actions.

Q30Explain security risks: prompt injection, data leakage, tool misuse. 6 — likely

  • Prompt injection: malicious instructions in user input (direct) or in retrieved web pages/documents (indirect) hijack the agent. Mitigate: separate instructions from data, input filtering, restrict tools, confirm risky actions.
  • Data leakage: agent reveals sensitive/private data via outputs or tool calls. Mitigate: access control, redaction, least privilege, logging.
  • Tool misuse: agent calls tools wrongly or with excessive authority (delete data, send emails). Mitigate: allowlists, argument validation, sandboxing, human approval.

Q31What is Responsible AI? Explain bias mitigation and transparency/explainability. 5

Building AI that is fair, accountable and trustworthy. Bias mitigation: diverse/representative data, fairness testing across groups, monitoring. Transparency and explainability: reveal reasoning traces/sources, keep audit logs, provide citations so decisions can be inspected.

Q32Draw a defense-in-depth safety pipeline for an agent. 5

User input → input guardrail (injection/PII filter) → agent (LLM + planner) → tool gate (allowlist, validation, approval) → tool execution (sandbox) → output guardrail (validation, grounding check) → user; monitoring & logging across every stage.
