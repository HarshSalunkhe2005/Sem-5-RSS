02 · What NLP actually is

Introduction to NLP

NLP is the branch of AI that gives computers the ability to understand, generate, and manipulate human (natural) language, in both text and speech form.

📐Syntax

Structure of sentences — grammar rules, parse trees.

💡Semantics

Meaning of words and sentences in context.

🎯Pragmatics

Intent & context beyond the literal meaning.

Core challenges of NLP

  • Ambiguity: "I saw the man with the telescope" — who had the telescope?
  • Context: same word, different meanings ("bank" = riverbank or financial institution)
  • Sarcasm & irony: "Oh great, another Monday!"
  • Low-resource languages: billions of speakers, minimal digital data

Why do we need NLP?

80% of enterprise data is unstructured text. Real-world uses: chatbots & dialog (ChatGPT, Alexa), sentiment analysis (reviews, Twitter/brand monitoring), machine translation (Google Translate — 7000+ languages), healthcare & legal (clinical notes, contract review).

Step-by-step, with code

  1. Lowercasing: "NLP" → "nlp"
  2. Remove punctuation: "Hello, world!" → "Hello world"
  3. Remove stop words: "the cat sat on mat" → "cat sat mat"
  4. Remove HTML/noise: "<p>Buy now!</p>" → "Buy now"
  5. Normalize numbers: "I have 3 cats" → "I have NUM cats"
import re, nltk
from nltk.corpus import stopwords
from nltk.tokenize import word_tokenize

def preprocess(text):
    text = text.lower()
    text = re.sub(r'[^\w\s]', '', text)
    text = re.sub(r'\d+', 'NUM', text)
    stop = set(stopwords.words('english'))
    tokens = word_tokenize(text)
    return [w for w in tokens if w not in stop]

preprocess("The Cat SAT on 3 Mats!!")
# ['cat', 'sat', 'NUM', 'mat']

Punctuation Removal

Python's string library has a predefined list of punctuation marks to strip.

Lowercasing

Common, but not always safe — e.g. in sentiment analysis, UPPERCASE can signal frustration/excitement, and lowercasing loses that.

Stop Word Removal

Common words (I, me, my, the, is, ...) carry little meaning and are removed — NLTK ships a standard English stopword list.

Decontracting Words

Expanding contractions ("don't" → "do not") standardizes text — especially useful for Twitter data / product reviews in sentiment analysis.

Normalization — regex & contractions

  • Expand contractions: don't → do not, I'm → I am
  • Standardize spellings: colour → color, normalise → normalize
  • Handle URLs/emails: https://sit.edu → URL_TOKEN
  • Remove accents: café → cafe, naïve → naive
  • Whitespace cleanup: 'hello  world' → 'hello world'
import re, unicodedata
CONTRACTIONS = {"don't": "do not", "i'm": "i am", "won't": "will not"}

def normalize(text):
    text = text.lower()
    for k,v in CONTRACTIONS.items():
        text = text.replace(k, v)
    text = re.sub(r'https?://\S+','URL', text)
    return text

normalize("I don't visit https://sit.edu")
# → "i do not visit URL"

Tokenization

Tokenization is splitting a phrase, sentence, paragraph, or document into smaller units — words or terms. Each smaller unit is a token.

word_tokenize(text)

tok.tokenize(text)

Methods to perform tokenization in Python

  • Python's split() function — breaks a string at each space (separator configurable)
  • Regular expressions (re module)
  • Libraries: NLTK, spaCy, Keras, Gensim

Regex for tokenization

A regular expression is a sequence of characters used to find/replace patterns in a string. Common re methods: re.match(), re.search(), re.findall(), re.split(), re.sub(), re.compile().

07 · Words as numbers

Vectorization & Word Embeddings

Word embeddings map words/phrases from a vocabulary to a corresponding vector of real numbers, used to find word predictions and word similarity/semantics.

Famous Word2Vec analogy (Mikolov et al., 2013): king − man + woman ≈ queen

One-Hot Encoding

Each word gets its own isolated position in the vocabulary.

WordVector
Cat[1 0 0 0]
Dog[0 1 0 0]
Car[0 0 1 0]
Apple[0 0 0 1]

Problem: Distance(Cat, Dog) = Distance(Cat, Apple) — every word is equally different. Identity is captured, but meaning is not.

Word2Vec

Instead of huge sparse vectors, each word gets a dense vector (e.g. 100-300 dimensions). The model learns by observing surrounding words repeatedly — words that appear in similar contexts get similar vectors ("dog" ends up near "barks", "puppy", "plays"; "hospital" near "doctor", "nurse", "medicine").

from gensim.models import Word2Vec
sentences = [
    ["king","rules","the","land"],
    ["queen","rules","the","kingdom"]
]
model = Word2Vec(sentences, vector_size=100, window=5, min_count=1)
model.wv['king']                       # dense vector, shape (100,)
model.wv.most_similar('king', topn=3)   # [('queen',0.97),('land',0.82)...]

BERT — contextual embeddings

Word2Vec gives one vector per word, regardless of context. BERT gives different vectors depending on the sentence:

Sentence"bank" means
"He deposited money in the bank."financial institution
"The fisherman sat on the river bank."side of a river

One-Hot vs Word2Vec vs BERT

MethodMeaning CapturedContext Aware
One-HotNoNo
Word2VecYesNo
BERTYesYes

The evolution is identity → meaning → context. This is one of the biggest milestones in modern NLP.

More Word2Vec analogies (good exam examples)

  • Paris − France + Italy ≈ Rome
  • Tokyo − Japan + India ≈ Delhi
  • Walking − Walk + Swim ≈ Swimming
  • Brother − Man + Woman ≈ Sister

Code: similarity & analogy

# Find similar words
from gensim.models import Word2Vec
model = Word2Vec(sentences, vector_size=50, window=2, min_count=1)
print(model.wv.most_similar("dog"))
# [('puppy', 0.91), ('barks', 0.74), ('plays', 0.61)]

# Word analogy: king - man + woman ≈ queen
result = model.wv.most_similar(positive=['king','woman'], negative=['man'])

# Cosine similarity
print(model.wv.similarity("dog", "puppy"))  # 0.89 — high, similar meaning
print(model.wv.similarity("dog", "car"))    # 0.14 — low, unrelated

2-minute classroom explanation (memorize this): "Imagine every word as a point on a map. In One-Hot Encoding, every word is isolated, so the computer knows only that they are different. Word2Vec changes this by placing similar words close together — 'king' near 'queen', 'doctor' near 'hospital', 'cat' near 'dog'. BERT goes further: it understands the same word can mean different things depending on the sentence — 'bank' in 'river bank' vs 'bank account' gets different representations. This evolution — One-Hot → Word2Vec → BERT — is one of the biggest milestones in modern NLP."

08 · Roots and grammatical roles

Stemming, Lemmatization & POS Tagging

✂️ Stemming

Text standardization step — words are reduced to their root/base form (e.g. 'programmer', 'programming', 'program' → 'program'). Disadvantage: the stemmed root may lose meaning or not be a proper English word.

📖 Lemmatization

Also reduces words, but ensures meaning isn't lost — uses a pre-defined dictionary that stores context and checks the word against it.

WordStemming (Porter)Lemmatization (WordNet)
runningrunrun
studiesstudi (not a real word!)study
fliesfli—
betterbettergood
corporacorporacorpus
 
from nltk.stem import PorterStemmer, WordNetLemmatizer
stemmer = PorterStemmer()
lemma   = WordNetLemmatizer()

for w in ["running","studies","better","corpora"]:
    print(w, stemmer.stem(w), lemma.lemmatize(w, pos='v'))
# running  stem:run    lem:run
# studies  stem:studi  lem:study
# better   stem:better lem:good
# corpora  stem:corpora lem:corpus

POS Tagging

Part-of-Speech tagging is a labeling mechanism where each word in a corpus is tagged grammatically — noun, verb, adjective, adverb, etc., including fine-grained tags (e.g. noun-plural) and tense. Applications: text-to-speech, word sense disambiguation.

09 · Grammar and structure

Syntactic Parsing & Grammar

Syntactic analysis (parsing) draws exact/dictionary meaning from text, checking it against the rules of formal grammar. E.g. "hot ice-cream" would be rejected by a semantic analyzer.

Concept of a Parser

A parser is a software component that takes input text and produces a structural representation after checking syntax. Roles: report syntax errors, recover from errors, create the parse tree, create a symbol table, produce intermediate representations.

Types of parsing (by derivation)

⬇️ Top-down Parsing

Starts building the parse tree from the start symbol, then transforms it toward the input. Most common form uses recursive procedures — main disadvantage is backtracking.

⬆️ Bottom-up Parsing

Starts with the input symbols and tries to construct the parse tree up to the start symbol.

  • Left-most derivation: the sentential form is scanned/replaced left → right
  • Right-most derivation: scanned/replaced right → left

Parse Tree

A graphical depiction of a derivation — the start symbol is the root; leaf nodes are terminals, interior nodes are non-terminals. In-order traversal of a parse tree reproduces the original input string.

Concept of Grammar

Noam Chomsky's 1956 mathematical model: a grammar G is a 4-tuple (N, T, S, P):

  • N — set of non-terminal symbols (variables)
  • T — set of terminal symbols
  • S — the start symbol, S ∈ N
  • P — production rules, of the form α → β

10 · Finding real-world entities in text

Named Entity Recognition (NER)

Chunking & Chinking

Chunking groups individual pieces (nouns, verbs, adjectives, adverbs) into larger units called chunks — most common: Noun Phrase (NP) chunking ("the cat," "a book") and Verb Phrase (VP) chunking ("ate breakfast," "is running"). Steps: POS-tag the sentence → group words into chunks based on their POS tags.

Chinking excludes certain words/phrases from a chunk (e.g. prepositions, conjunctions, determiners) — marked with tag O (outside) in an NER system.

What is NER?

NER identifies and categorizes words/expressions/names in unstructured data into predefined categories — persons, organizations, locations, etc.

Steps in NER

  1. Extracting the information: detect and prepare named entities — POS tagging, sentence boundary detection, capitalization rules, co-reference resolution.
  2. Searching the entities: search entity candidates in the document — balancing accuracy and recall while keeping the entity set small enough to be efficient.

Different NER systems

📖 Dictionary-based

Simplest approach — uses a vocabulary dictionary and basic string matching to check if an entity occurs. Limitation: dictionary must be constantly updated/maintained.

📏 Rule-based

Uses a pre-defined set of rules — pattern-based rules (depend on morphological patterns) and context-based rules (depend on surrounding context). E.g. regex for phone numbers, emails, capitalized names.

Sequence Labelling & the IOB format

Sequence labeling assigns a categorical label to each element in an input sequence — used for speech recognition, video analysis, and NLP tasks like POS tagging, NER, chunking. Traditionally needs heavy hand-engineered features; neural approaches now achieve state-of-the-art results.

The IOB format (Inside-Outside-Beginning) tags tokens for chunking tasks like NER — similar to POS tags but describing a word's position within a chunk:

  • B-NP: beginning of a noun phrase
  • I-NP: inside the current noun phrase
  • O: outside any chunk
  • B-VP / I-VP: beginning/inside of a verb phrase

import nltk, spacy, re
from nltk.corpus import stopwords
from nltk.stem import WordNetLemmatizer

def nlp_pipeline(text):
    text = text.lower()
    text = re.sub(r'[^\w\s]','',text)
    stop = set(stopwords.words('english'))
    tokens = [w for w in text.split() if w not in stop]

    lem = WordNetLemmatizer()
    tokens = [lem.lemmatize(w) for w in tokens]

    nlp = spacy.load('en_core_web_sm')
    doc = nlp(' '.join(tokens))
    return doc  # has .pos_ per token and .ents for NER
