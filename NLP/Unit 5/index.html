01 · The task

What Is Machine Translation?

No Moodle deck was posted for NLP Unit 5: written from standard content to match the official question bank; check against your lecture notes.

Machine Translation (MT) automatically converts text from a source language (f, foreign) into a target language (e, English in the classic notation). It is the standard example of a sequence-to-sequence problem: a variable-length input sentence must become a variable-length output sentence, and the two lengths need not match.

Why MT is hard

  • Lexical ambiguity: "bank" (river / money) has different translations depending on context.
  • Word-order divergence: English is SVO ("I eat rice"), Hindi/Marathi are SOV ("मैं चावल खाता हूँ"), so words must be reordered.
  • Morphology and gender/agreement: one source word may map to several target words or vice versa (not one-to-one alignment).
  • Idioms and culture: "it's raining cats and dogs" cannot be translated word by word.
  • Evaluation: many valid translations exist for one sentence, so there is no single "correct" answer to compare against.

Rule-Based (RBMT)

Hand-written dictionaries and grammar rules. Direct (word-by-word), transfer (parse → transform syntax → generate) or interlingua (source → language-neutral meaning → target). Precise and explainable, but needs linguists, and rules never cover all exceptions.

Example-Based (EBMT)

Stores a database of past translated sentence pairs; to translate, finds the most similar stored example and recombines its matching fragments. Works when the new sentence resembles old ones; weak otherwise.

Statistical (SMT)

Learns translation probabilities from a large parallel corpus (aligned sentence pairs). Dominant roughly 1990s to 2015. Phrase-based SMT translates chunks of words, not single words.

The noisy-channel idea behind SMT

Imagine the source sentence f is a "corrupted" version of an original English sentence e. We want the e that most probably produced f. By Bayes' rule:

ê = argmax_e P(e | f) = argmax_e P(f | e) · P(e)  /  P(f)
  = argmax_e P(f | e) · P(e)          (P(f) is constant for a given input)
  • P(e) — language model (Unit 2 n-grams): is this fluent target-language text?
  • P(f | e) — translation model: learned from the parallel corpus using word/phrase alignments (IBM Models 1-5, phrase tables): is f a plausible translation of e? (adequacy)
  • Decoder: searches for the e maximising the product (beam search over phrase combinations).

Phrase-based SMT adds a phrase table (e.g. "kick the bucket" ↔ its idiomatic equivalent as one unit) and a reordering model.

03 · The first neural MT architecture

Seq2Seq: Encoder-Decoder

A sequence-to-sequence model (Sutskever et al., 2014; Cho et al., 2014) uses two RNNs (usually LSTM/GRU, Unit 4):

  1. Encoder: reads the source tokens x₁…x_n one by one, updating a hidden state h_t = f(x_t, h_{t−1}). The final state h_n is the context vector c, a fixed-size summary of the entire sentence.
  2. Decoder: an RNN language model for the target, initialised with c. At each step it computes s_t = f(s_{t−1}, y_{t−1}, c) and a softmax P(y_t | y_<t, x) = softmax(W·s_t) over the target vocabulary.
  3. Generation starts from a <sos> token and stops when <eos> is produced.

The model directly estimates P(y | x) = ∏_t P(y_t | y_1…y_{t−1}, x) and is trained end to end by minimising the cross-entropy (negative log-likelihood) of the reference translation.

Worked trace (simple translation)

Source "I love NLP" → encoder reads I, love, NLP, <eos> and produces c. Decoder: input <sos> → "मुझे", then "NLP" → "पसंद", then "है"… until <eos>. Each emitted word is fed back as the next input.

Teacher forcing

During training, the decoder is fed the true previous target word y_{t−1} rather than its own prediction, so the model learns quickly and errors do not compound. At inference no reference exists, so it must use its own previous output. The mismatch is called exposure bias.

The context-vector bottleneck

Squeezing a whole sentence (10 words or 60) into one fixed-length vector loses information, and BLEU falls sharply as sentences get longer. Also, gradients must travel through many time steps (vanishing gradient). This motivated attention (next section).

Decoding: greedy vs beam search

GreedyBeam search (width k)
IdeaPick the single most probable word at every stepKeep the k best partial translations at every step
CostO(T · V)≈ k times greedy
QualityCan be locked into an early mistakeCloser to the true best sequence; k = 4-10 typical. Not guaranteed optimal.

Tiny example. Step 1: P(A)=0.5, P(B)=0.4. Then P(X | A)=0.4 but P(Y | B)=0.9. Greedy picks A then X: 0.5 × 0.4 = 0.20. Beam k=2 keeps both A and B, finds B Y with 0.4 × 0.9 = 0.36, which is better. Scores are summed as log-probabilities (ln 0.20 = −1.609, ln 0.36 = −1.022) and usually length-normalised so long outputs are not unfairly penalised.

04 · Looking back at the source

Attention Mechanism

Idea (Bahdanau et al., 2014): instead of one fixed context vector, let the decoder look at all encoder states h₁…h_n and decide, at each output step, which source words matter most. When producing a word, it focuses on the aligned source word(s).

  1. Score each encoder state against the current decoder state s: e_i = score(s, h_i).
  2. Softmax the scores into attention weights: α_i = exp(e_i) / Σ_j exp(e_j) (weights are positive and sum to 1).
  3. Context vector for this step: c_t = Σ_i α_i · h_i (weighted average).
  4. The decoder uses c_t together with s_t to predict the next word. A new c_t is computed at every step.
VariantScore function
Bahdanau (additive / concat)score(s, h) = vᵀ · tanh(W₁s + W₂h)
Luong dotscore(s, h) = sᵀ h
Luong generalscore(s, h) = sᵀ W h

Numeric example (dot-product attention)

Decoder state s = (1, 0). Encoder states h₁ = (1, 0), h₂ = (0, 1), h₃ = (1, 1).

scores   e = (s·h₁, s·h₂, s·h₃) = (1, 0, 1)
softmax  α = (e¹, e⁰, e¹) / (e¹ + e⁰ + e¹) = (2.718, 1, 2.718) / 6.437
           = (0.4223, 0.1554, 0.4223)
context  c = 0.4223·(1,0) + 0.1554·(0,1) + 0.4223·(1,1) = (0.8446, 0.5777)

The decoder pays 42% attention each to h₁ and h₃ and only 16% to h₂. Plotting α for every (source, target) pair gives an alignment matrix, which makes NMT partly interpretable (e.g. it shows the word reordering in English-Hindi).

Benefits: removes the bottleneck, better on long sentences, gives soft alignments, and shortens the gradient path. Cost: O(n·m) scores per sentence (n source, m target words).

Vaswani et al. (2017) removed recurrence entirely: the model is built only from attention and feed-forward layers, so all positions are processed in parallel.

Self-attention with Query, Key, Value

Each token vector x is projected into a query q = xW_Q ("what am I looking for?"), a key k = xW_K ("what do I contain?") and a value v = xW_V ("what do I pass on?"). For the whole sentence stacked into matrices Q, K, V:

Attention(Q, K, V) = softmax( Q Kᵀ / √d_k ) · V

Dividing by √d_k stops the dot products growing large with dimension, which would push softmax into near-one-hot, tiny-gradient regions.

Numeric example (d_k = 4, one query): q = (1, 0, 1, 0); keys k₁ = (1,0,1,0), k₂ = (0,1,0,1), k₃ = (1,1,1,1); values v₁ = (1,0), v₂ = (0,1), v₃ = (1,1).

q·k = (2, 0, 2)       scale by √4 = 2  →  (1, 0, 1)
softmax → (0.4223, 0.1554, 0.4223)       (without scaling it would be (0.468, 0.063, 0.468))
output = 0.4223·v₁ + 0.1554·v₂ + 0.4223·v₃ = (0.8446, 0.5777)

Multi-head attention

Run h attention "heads" in parallel (h = 8, each with d_k = d_model/h = 64 in the base model), each with its own W_Q, W_K, W_V; concatenate the outputs and project with W_O. Different heads learn different relations (syntax, coreference, nearby words).

Positional encoding

Self-attention has no sense of word order (it treats the sentence as a set), so a position signal is added to each input embedding. The original uses fixed sinusoids:

PE(pos, 2i)   = sin( pos / 10000^(2i/d_model) )
PE(pos, 2i+1) = cos( pos / 10000^(2i/d_model) )

Example with d_model = 4: PE(1) = (sin 1, cos 1, sin 0.01, cos 0.01) = (0.8415, 0.5403, 0.0100, 1.0000); PE(2) = (0.9093, −0.4161, 0.0200, 0.9998). Low dimensions oscillate fast, high dimensions slowly, giving every position a unique pattern, and relative offsets are easy to learn. Many later models use learned position embeddings instead.

Architecture

  • Encoder stack (N = 6 layers): each layer = multi-head self-attention → add & layer-norm → position-wise feed-forward network (512 → 2048 → 512) → add & layer-norm. Residual connections around each sub-layer.
  • Decoder stack (N = 6): masked self-attention (a token cannot see future tokens) → encoder-decoder (cross) attention (queries from decoder, keys/values from encoder output) → feed-forward.
  • Final linear layer + softmax over the target vocabulary; training uses teacher forcing with the mask, so all target positions are trained in parallel.

Transformer vs RNN

PropertyRNN / LSTM seq2seqTransformer
Parallelism over sequenceNone: sequential, O(n) stepsFully parallel: O(1) sequential operations
Path between two distant wordsO(n)O(1)
Cost per layerO(n · d²)O(n² · d)
Long-range dependenciesWeak (vanishing gradients)Strong (direct links)
Word orderBuilt in through recurrenceNeeds positional encoding
Training speed on GPUsSlowMuch faster, scales to huge data
WeaknessBottleneck, forgettingMemory grows as n²; very long inputs are costly

For n = 50 and d = 512: n²d = 1.28 million vs n d² = 13.1 million, so at ordinary sentence lengths self-attention is actually cheaper per layer; the n² term only dominates once n exceeds d. The base model has about 44 million parameters in its encoder + decoder layers (≈ 3.15M per encoder layer, ≈ 4.2M per decoder layer) plus roughly 19M for a shared 37,000 × 512 embedding table, in line with the ~65M reported for the paper's base model.

06 · How good is a translation?

Evaluating MT: BLEU

BLEU (Bilingual Evaluation Understudy) compares a candidate translation with one or more human references using modified n-gram precision and a brevity penalty:

BLEU = BP · exp( Σ_{n=1..N} w_n · ln p_n ),   usually N = 4, w_n = 1/N
BP   = 1                    if c > r
     = exp(1 − r / c)       if c ≤ r        (c = candidate length, r = reference length)

Modified (clipped) precision: each candidate n-gram is credited at most as many times as it appears in the reference, so repeating a correct word cannot cheat. Candidate "the the the the the the the" vs reference "the cat is on the mat": "the" appears twice in the reference, so p₁ = 2/7, not 7/7.

Worked example

Reference: the cat is on the mat (r = 6). Candidate: the cat sat on the mat (c = 6).

nCandidate n-gramsMatched in referencep_n
1the, cat, sat, on, the, matthe, cat, on, the, mat (5)5/6 = 0.833
2the cat, cat sat, sat on, on the, the matthe cat, on the, the mat (3)3/5 = 0.600
3the cat sat, cat sat on, sat on the, on the maton the mat (1)1/4 = 0.250
43 four-gramsnone (0)0/3 = 0

c = r, so BP = 1. BLEU-2 = 1 × exp(½ ln 0.833 + ½ ln 0.6) = √(0.833 × 0.6) = 0.707. Standard BLEU-4 is 0 here because p₄ = 0 (short sentences give zero 4-gram matches), which is why BLEU is meant for whole test sets (corpus-level) or uses smoothing.

Brevity penalty example: candidate the cat on the mat (c = 5, r = 6): p₁ = 5/5, p₂ = 3/4, BP = exp(1 − 6/5) = 0.819, BLEU-2 = 0.819 × √(1 × 0.75) = 0.709. Without BP the short candidate would score 0.866.

Limits of BLEU: ignores meaning and synonyms, ignores word importance, depends on the number and quality of references, and correlates only loosely with human judgement at sentence level. Other metrics, mentioned by name: METEOR (uses stems, synonyms and recall) and chrF (character n-gram F-score, good for morphologically rich languages). Human evaluation of adequacy and fluency remains the gold standard.

07 · One model, many languages

Multilingual Machine Translation

Instead of training one model per language pair (N languages → N(N−1) directed pairs), a single multilingual NMT model translates between many languages. Johnson et al. (2016) showed this needs no architecture change: just prepend a target-language tag to the source (e.g. <2hi> I love NLP).

Shared vocabulary / subwords

A joint BPE / SentencePiece vocabulary splits words into subword pieces so many languages share one token set and rare or unseen words are still representable. Vocabulary budget is split across languages and scripts.

Cross-lingual transfer

Related languages (Hindi-Marathi, Spanish-Portuguese) share structure, so training on a high-resource language helps a low-resource one.

Zero-shot translation

If trained on EN↔HI and EN↔MR, the model can often translate HI→MR without ever seeing HI-MR pairs, because it learns a shared representation. Quality is usually lower than for seen pairs and can drift into the wrong output language.

Efficiency

One model to deploy and maintain instead of hundreds of bilingual systems.

Challenges

  • Low-resource languages: little parallel data (many Indian and African languages), so translations are poor; back-translation, pivoting through English and transfer help.
  • Language imbalance: English-heavy data lets high-resource languages dominate; fix by temperature-based sampling that up-weights small languages.
  • Capacity / "curse of multilinguality": adding languages makes them compete for the same parameters, hurting high-resource pairs unless the model is made larger.
  • Different scripts, morphology and word order (Devanagari, Arabic, Latin; agglutinative languages).
  • Vocabulary issues: a shared subword vocabulary over-segments low-resource languages.
  • Evaluation: few high-quality test sets; BLEU poorly suited to morphologically rich languages (chrF is often preferred).
  • Zero-shot errors: off-target language output and poor fluency; also cultural bias and gender bias from skewed data.

08 · Pre-trained models and LLMs

Recent Advancements in NLP

Modern NLP follows a pre-train, then fine-tune recipe: train a big Transformer on huge unlabelled text with a self-supervised objective, then adapt it to a task with a small labelled set.

Model familyArchitecturePre-training objectiveTypical use
BERT (2018)Transformer encoder, bidirectionalMasked Language Modelling (mask ~15% of tokens, predict them) + next sentence predictionClassification, NER, QA, sentence embeddings
GPT seriesTransformer decoder, left-to-rightNext-token predictionText generation, chat, few-shot tasks
LaMDA (Google, 2021)Transformer decoder, dialogue-tunedNext-token prediction on dialogue + web text, then fine-tuned for safety, quality and factual groundingOpen-ended conversational AI (it powered Google Bard)
T5 / BART / mT5Encoder-decoderSpan corruption / denoisingTranslation, summarisation (text-to-text)

ELECTRA: replaced token detection Not in ESE syllabus · optional

BERT's masked LM learns from only the ~15% of tokens that are masked, which wastes compute. ELECTRA (Clark et al., 2020) changes the objective:

  1. A small generator (a mini masked LM) fills in the masked positions with plausible words, so some tokens are replaced.
  2. The main model, the discriminator, reads the corrupted sentence and labels every token as "original" or "replaced" (binary classification).
  3. After pre-training the generator is discarded and the discriminator is fine-tuned for downstream tasks.

Example: "the chef cooked the meal" → generator swaps in "ate": "the chef ate the meal"; the discriminator should flag "ate" as replaced and all others as original. Because the loss is defined over all tokens, ELECTRA is more sample- and compute-efficient than BERT of the same size. It is not a GAN, since the generator is trained with ordinary maximum likelihood, not adversarially.

Large Language Models (LLMs) and prompting

  • LLMs are very large decoder-style Transformers (billions of parameters) trained on web-scale text; scale gives emergent abilities such as few-shot learning.
  • Prompting: zero-shot (instruction only), few-shot (add examples in the prompt), and chain-of-thought (ask for step-by-step reasoning), with no weight updates.
  • Instruction tuning and RLHF align the model with human preferences. Parameter-efficient fine-tuning (LoRA, adapters) adapts large models cheaply. Retrieval-augmented generation (RAG) grounds answers in documents to reduce hallucination.
  • Limits: hallucination, bias, high compute cost, privacy concerns, and the need for careful evaluation.

09 · Choosing a model

Which Model for Which Scenario?

ScenarioChoiceJustification
Translate EN to Hindi for a news site, lots of parallel dataTransformer NMT (fine-tuned pre-trained, e.g. mT5 / MarianMT)Best BLEU/fluency, parallel training, mature tooling
Marathi to English with very few sentence pairsMultilingual pre-trained model + fine-tune, back-translationTransfer from related high-resource languages (Hindi); data augmentation
Offline translation on a phone / tiny deviceSmall distilled Transformer or GRU seq2seq with attentionLow memory, no server; accept lower quality
Sentiment or spam classificationBERT / ELECTRA encoder fine-tunedBidirectional context; ELECTRA cheaper to pre-train
Chatbot or content generation, little task dataLLM with prompting (few-shot) or RAGNo training needed; RAG grounds facts
Legal or medical translation, errors costlyDomain fine-tuned NMT + human post-editing, glossary constraintsAccuracy and traceability matter more than speed
Very small corpus, strict budget, domain with fixed phrasesRule-based or example-based / translation memoryPredictable output, no big data needed

A design recipe for any translation problem

  1. Define languages, domain, latency and quality requirements.
  2. Collect and clean data: parallel corpus, deduplicate, normalise, handle scripts.
  3. Tokenise with a subword model (BPE / SentencePiece).
  4. Choose model: pre-trained Transformer where possible; multilingual if low-resource.
  5. Train / fine-tune with teacher forcing, label smoothing; decode with beam search (k = 4-5) and length normalisation.
  6. Evaluate with BLEU/chrF on a held-out test set plus human review; iterate (back-translation, domain data).
