01 · The problem embeddings solve

What Is Word Embedding, and Why Do We Need It?

A word embedding represents words as numerical vectors that capture meaning and relationships — similar meanings end up as similar vectors. One-hot vectors ("cat"→[1,0,0,0]) tell us words are different but carry zero sense of how they relate; embeddings fix exactly that.

One-HotWord Embedding
DimensionsVocabulary size (e.g. 10,000)100–300 (a model setting)
Similarity capturedNone — all pairs equally "unrelated"Semantic + syntactic relationships
SparsityExtremely sparseDense — every dimension carries information

Why word embeddings matter — 4 reasons

1. Semantic representation

Similar words sit close together in vector space — King↔Queen, Car↔Vehicle, Happy↔Joyful.

2. Lower-dimensional representation

One-hot needs thousands of dimensions (word → 10,000 dims); embeddings compress the same vocabulary into 100–300 dims.

3. Captures relationships

Learned directly from large amounts of text — the classic example: King − Man + Woman ≈ Queen.

4. Useful for NLP tasks

Sentiment Analysis, Named Entity Recognition, Machine Translation, Text Classification, Question Answering, Recommendation Systems, and Transfer Learning (pre-trained embeddings reused for new tasks, especially useful when training data is small).

Frequency-Based Methods

Rely on how often words occur (in documents or alongside each other): TF-IDF, Co-occurrence Matrix (Unit 2 territory, count-based).

Prediction-Based Methods

Learn vectors by predicting words from context: Word2Vec (CBOW / Skip-gram), FastText, GloVe (hybrid — this unit's focus).

02 · The model that changed NLP

Word2Vec

Introduced by a Google research team led by Tomas Mikolov in 2013, Word2Vec represents words as dense numerical vectors using a simple two-layer neural network, learning meaning purely from which words tend to appear near each other.

1. Converts text to numbers

Turns raw text into a numerical form ML algorithms can process.

2. Learned via deep learning

Uses a neural network to map semantic meaning into a geometric embedding space.

3. Groups similar meaning

Words sharing contextual meaning end up positioned close together in that space.

Architecture flow

Input Layer (one-hot encoded word) → Hidden Layer (computes vectors from surrounding context) → Output Layer (produces the final word vectors/embeddings). Two matrices are learned: W (used when a word is a context/input word) and W′ (used when a word is the target/output word being predicted) — separate roles let the model learn both "how does this word help predict another?" and "how well can this word be predicted?"

03 · Context → Target

CBOW — Continuous Bag of Words

Uses surrounding context words to predict the missing target word — "The cat ___ mat" → "sat". Faster to train; works well for frequent words.

  1. Embedding lookup: Each context word's vector is looked up in matrix W.
  2. Average: All context word vectors are averaged into one hidden vector h.
  3. Score every word: h is compared against every vocabulary word's output vector (in W′) via a dot product.
  4. Softmax: Raw scores are turned into probabilities that sum to 1.
  5. Loss: Cross-entropy loss compares the predicted probability of the true target word against 1.
  6. Backpropagation: The gradient is split evenly across the context words (since they were averaged) and both W and W′ are updated via gradient descent.

A complete numeric walkthrough of every CBOW step (forward pass, softmax, loss, backward pass, weight update) is on the Numericals page.

04 · Target → Context

Skip-gram

The reverse of CBOW: given a target (centre) word, predict the surrounding context words within a fixed window. "The cat drinks milk quickly" (window=2) → predicts "The", "cat", "milk", "quickly".

Unlike CBOW, there's no averaging — the target word's own vector is used directly, and each context word forms its own separate training pair, so one target word occurrence generates multiple training pairs (more gradient updates per rare word than CBOW gives it).

Positive & Negative Sampling

Instead of a full softmax over the whole vocabulary, Skip-gram-with-negative-sampling turns training into a simple yes/no question repeated many times: each (target, other word) pair becomes its own example, labeled 1 if they're real neighbours, 0 if the other word was chosen at random.

Positive samples

Real (target, context) pairs → label 1. E.g. (drinks, cat) → 1, (drinks, milk) → 1.

Negative samples

(target, random word) pairs → label 0. E.g. (drinks, umbrella) → 0, (drinks, Paris) → 0.

Architecture: two embedding layers (target, context) → dot product → sigmoid classifier — far cheaper to train than full softmax over the vocabulary.

05 · Choosing between them

CBOW vs. Skip-gram

FeatureCBOWSkip-gram
InputContext wordsTarget word
OutputTarget wordContext words
Training speedGenerally faster (1 example per window)Generally slower (multiple pairs per window)
Best forFrequent words, huge corpora, speed-priorityRare/domain-specific words, sparse data

Real-world scenario reasoning

E-commerce catalog

Frequent products (laptop, mouse) → CBOW (trains fast, plenty of data). Rare long-tail items (niche stylus refill) → Skip-gram (more training pairs per rare occurrence).

Voice assistant, tight compute

Billions of common commands, strict compute window → CBOW. It needs fewer training examples per window, and common words already have plenty of data.

Legal precedent search

Core value is finding obscure, rarely-cited precedents → Skip-gram. Worth the extra training cost for better rare-term representations.

06 · Word2Vec in practice

Gensim

Gensim is a Python library for working with large amounts of text — it helps a computer understand relationships between words and documents by converting them into vectors.

Word Embeddings

Converts words into meaning-capturing vectors.

Topic Modeling

Finds hidden topics inside a document collection.

Document Similarity

Identifies documents discussing similar things.

Large-Text Scale

Built to handle huge text collections efficiently.

Popular techniques inside Gensim

TechniquePurpose
Word2VecLearns relationships between words
FastTextLearns word representations, including parts of words (sub-word)
Doc2VecCreates representations for entire documents
LDAFinds hidden topics in documents
LSIIdentifies relationships between words and documents

Training pipeline

  1. Build the corpus — raw sentences.
  2. Preprocess: lowercase everything, keep only alphabetic tokens, remove stopwords.
  3. Train: Word2Vec(sentences, vector_size=100, window=5, min_count=1, sg=1) — sg=1 means Skip-gram, sg=0 means CBOW.
  4. Evaluate: model.wv.similarity('galaxy','star'), model.wv.most_similar('space', topn=5), analogy queries like moon+orbit−earth.
  5. Visualize: PCA compresses each word's 100-dim vector to 2D for a scatter plot — words in similar contexts land near each other.

07 · Global statistics instead of local windows

GloVe (Global Vectors for Word Representation)

An unsupervised algorithm that turns words into dense vectors by analyzing how often words co-occur across the entire corpus — blending count-based and prediction-based strengths.

Word2VecGloVe
SignalPredictive — local context windowCount-based — global statistics
What it seesA few words at a time (sliding window)The whole corpus's co-occurrence counts at once

GloVe pipeline (6 stages)

  1. Preprocess — tokenize raw text into words.
  2. Vocabulary — collect unique words + frequency.
  3. Co-occurrence matrix — using a context window, count how often every word-pair appears near each other.
  4. Dot product — compare vectors via dot product against the observed co-occurrence/PMI.
  5. Training — optimize vectors so dot products match observed co-occurrence statistics as closely as possible.
  6. Embeddings — output the final dense vectors (one row per vocabulary word).

Full worked example (co-occurrence matrix construction) is on the Numericals page.

Pre-trained GloVe data

Stanford NLP provides ready-to-use vectors — no training required. Trained on 6 billion tokens from Wikipedia + Gigaword, 400K vocabulary, available as 50d / 100d / 200d / 300d vectors, downloadable as a single flat text file (one word + vector per line).

50d

Fast prototyping, small models, classroom demos.

100d

Balanced accuracy and speed for coursework.

200d

Richer semantics for mid-size classification tasks.

300d

Best accuracy; heavier memory and compute cost.
