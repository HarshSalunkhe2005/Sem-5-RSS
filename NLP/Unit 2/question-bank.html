Official Question Bank

Unit 2: Feature Extraction & Language Models (CO2)

Symbiosis Institute of Technology — Course Code 0701260505

Q1Apply Bag of Words and TF-IDF on a dataset and compare the feature vectors.

BoW gives raw occurrence counts per word per document — simple but treats all words equally. TF-IDF multiplies that count by an inverse-document-frequency weight, so common words (the, is) shrink toward 0 and rare, document-specific words get boosted. Same vocabulary size and same document-term matrix shape, but TF-IDF's values better reflect which words are actually distinctive to each document.

Q2Analyze the differences between CountVectorizer and TF-IDF with examples.

CountVectorizer outputs raw word counts (BoW) — e.g. "the" might get count=5 in a long document just because it's long. TfidfVectorizer outputs TF×IDF scores — "the" gets suppressed toward 0 regardless of count, since IDF≈0 for words in nearly every document, while a rare domain term keeps a high score. Same API shape (fit_transform → matrix), different value semantics.

Q3Given a sentence corpus, compute unigram and bigram probabilities.

Unigram: P(w) = Count(w) / Total words — no context. Bigram: P(wᵢ|wᵢ₋₁) = Count(wᵢ₋₁,wᵢ) / Count(wᵢ₋₁) — conditions on exactly the previous word. See the Numericals page for a full worked corpus example computing both.

Q4Apply Naïve Bayes for text classification and interpret the results.

Compute Prior P(class) from class proportions in training data, Likelihood P(word|class) from word counts within each class (Laplace-smoothed), multiply them together treating words as independent (naive assumption) to get an unnormalized score per class, then pick the class with the higher score. See Numericals for full spam/sentiment worked examples.

Q5Analyze the limitations of N-gram models in language modeling.

Only a fixed, short window of previous context (can't capture long-range dependencies) · exponential growth of possible N-grams as N increases · sparsity — most N-grams never appear in training data, giving zero probabilities without smoothing · large storage/computation requirements for higher-order models.

Q6Compare generative and probabilistic models for NLP tasks.

Probabilistic (N-gram) models predict the next word from raw co-occurrence counts within a fixed window — simple, fast, but limited context and severe sparsity at scale. Generative neural models (RNN/LSTM/Transformer/GPT) learn dense representations and can condition on much longer — even unlimited (Transformer attention) — context, at the cost of far more training data and compute.

Q7Evaluate smoothing techniques in handling unseen words.

Add-One/Laplace: adds 1 to every count — simple, no tuning, but can over-smooth with large vocabularies. Add-k: a tunable, gentler version of Laplace. Good-Turing: re-estimates probability mass from the frequency of frequencies — needs a reasonably large corpus. Backoff/Interpolation: fall back on lower-order (more reliably estimated) n-gram probabilities when higher-order counts are missing — often the best practical choice.

Q8Given a dataset, select an appropriate feature extraction method and justify your choice.

Need raw frequency, small dataset, simplicity → BoW. Need to identify distinctive/important words for ranking or classification → TF-IDF. Need to preserve some local word order (e.g. detect negation like "not good") → N-Grams (Bag-of-N-Grams) on top of BoW/TF-IDF. Need semantic similarity between words → move beyond this unit to Word2Vec/GloVe (Unit 3).

Applied Practice

One-Hot Encoding & Bag-of-Words

Q9What is one-hot encoding, and what is its major limitation for text?

Represents every unique word as a binary vector with a single 1 at that word's position, 0s elsewhere. Major limitation: every pair of one-hot vectors is orthogonal (cosine similarity = 0), so it carries zero notion of similarity — "cat" and "dog" look exactly as unrelated as "cat" and "airplane".

Q10A catalog one-hot encodes 5 categories; 6 months later a 6th category is added. What problem does this create?

One-hot vector length equals vocabulary size, so adding a category changes every vector from 5-dim to 6-dim. Every existing encoded vector must be regenerated, and any downstream model trained on 5-dim input must be retrained since its input shape changed. Fix: reserve extra slots in advance, or switch to embeddings, which don't need a fixed closed vocabulary.

Q11Explain the Bag-of-Words model. Why is word order lost?

BoW represents a document as an unordered collection (multiset) of its words — typically a vector of word counts over a fixed vocabulary. Because it only records how many times each word occurs, not where, two sentences with identical words in different order ("dog bites man" vs "man bites dog") produce the exact same vector.

Q12A spam classifier uses BoW on single words. Compare "not good" vs. "good" — what weakness does this expose, and what's one fix?

BoW treats "not" and "good" as two independent features with no link between them — the same two features would also appear in "good, not bad". It can't capture that "not" negates the very next word. Fix: use bigrams (so "not_good" is its own feature, distinct from "good"), or move to embeddings/contextual models that encode local word order.

Applied Practice

TF-IDF

Q13Define TF-IDF and explain what problem it solves compared to raw counts.

TF-IDF weighs a word by how frequently it appears in one document (TF) multiplied by how rare it is across the whole corpus (IDF) — TF-IDF = TF × IDF. Raw counts over-weight universally common words like "the"/"is" that carry little discriminative meaning; IDF specifically down-weights those while boosting words that are frequent locally but rare corpus-wide.

Q14Search engine: Doc A repeats "programming" 20× but never says "python"; Doc B says both once each, for the query "python programming". Which scores higher?

Doc B. TF-IDF scores are computed per query term and combined — Doc A racks up a large score from "programming" alone but contributes zero for "python" (only partial match). Doc B contributes a score for both terms, covering the full query intent rather than one repeated keyword.

Q15A word "python" appears in 1 of 3 documents. Compute its IDF (natural log) and explain the implication.

IDF = ln(3/1) = ln(3) ≈ 1.0986. Being rare across the corpus, "python" gets a relatively high IDF — it will be weighted heavily wherever it does appear, since it's a discriminative, topic-specific word.

Q16A word "the" occurs in all 5 documents (N=5, DF=5). Compute IDF and its implication for TF-IDF weight.

IDF = log(5/5) = log(1) = 0. Since TF-IDF = TF × IDF and IDF = 0, the TF-IDF score for "the" is 0 regardless of how often it occurs in any document — correctly reflecting that appearing in every document gives zero discriminative power.

Applied Practice

N-Grams & Smoothing

Q17Define an n-gram; give a bigram and trigram from "I love natural language".

An n-gram is a contiguous sequence of n words (or characters). Bigrams: (I,love), (love,natural), (natural,language). Trigrams: (I,love,natural), (love,natural,language).

Q18What are skip-grams, and how do they differ from a simple n-gram?

A skip-gram generalizes an n-gram by allowing some words in the window to be "skipped" — the chosen words needn't be strictly contiguous. This lets the model capture longer-range or non-adjacent associations (e.g. "not ... good") that a standard consecutive n-gram would miss.

Q19Why is smoothing necessary when estimating n-gram probabilities?

Under raw Maximum Likelihood Estimation, any n-gram never seen in training gets probability exactly 0. Since a sentence's probability is the product of its bigram probabilities, a single unseen bigram collapses the entire sentence's probability to 0. Smoothing redistributes a little probability mass to unseen events so the model generalizes.

Q20A researcher trains a bigram model on a small medical corpus; a test sentence gets probability exactly 0. What's happening and what's the fix?

Data sparsity — one bigram in the test sentence never appeared in training, so its MLE probability is 0, and since sentence probability multiplies all bigram probabilities together, one zero wipes out the whole product. Fix: apply a smoothing technique (Laplace, Good-Turing, Kneser-Ney, Backoff, or Interpolation).

Q21A chatbot's bigram model zeroes out several valid but rare queries. How does Add-One smoothing fix this?

The formula becomes P(wᵢ|wᵢ₋₁) = (C(wᵢ₋₁,wᵢ)+1) / (C(wᵢ₋₁)+V), adding 1 to every bigram count and V (vocabulary size) to every denominator. Now every possible bigram — including unseen ones — gets a small non-zero probability, so a rare-but-valid query no longer breaks the chatbot.

Q22A language model trains on just 200 sentences, where many valid pairs will be unseen. Which smoothing technique(s) fit best?

Add-One (Laplace) is the safest default for very small corpora — no tuning needed, guarantees non-zero probabilities everywhere. Backoff/Interpolation are strong complements, since they let a sparse higher-order model fall back on more reliably estimated lower-order n-grams. Good-Turing is less reliable here since it typically needs a larger corpus to work well.

Applied Practice

Naive Bayes

Q23Apply the Naive Bayes independence assumption to "not good service" — why can this misclassify sentiment?

Naive Bayes treats every word as an independent feature: P(not|class)·P(good|class)·P(service|class), with no link between "not" and "good". Since "good" alone strongly indicates Positive, its high likelihood can dominate the product even though "not good" is actually negative — the negation isn't modeled. This exposes Naive Bayes's core inability to capture word dependencies (negation, sarcasm, word order).

Q24Outline the full Naive Bayes workflow (Prior → Likelihood → Evidence → Posterior) for a movie-review sentiment classifier.

1) Prior: P(Positive), P(Negative) from the proportion of each class in training data. 2) Likelihood: P(word|class) for every vocabulary word from word counts within each class, Laplace-smoothed. 3) Evidence/scoring: treat each word in a new review as independent, multiply P(class)×∏P(word|class) to get an unnormalized score per class. 4) Posterior/decision: compare scores (optionally normalize by dividing by their sum) and assign the class with the higher score.

Quick Recall

True/False & Fill-in-the-Blank

Q25One-hot encoded vectors capture semantic similarity between words.

False — all one-hot vectors are mutually orthogonal, encoding zero similarity information; embeddings are needed for that.

Q26The Bag-of-Words model preserves word order.

False — BoW only counts occurrences and discards sequence entirely.

Q27TF-IDF gives higher weight to words frequent in one document but rare across the corpus.

True — that's precisely TF-IDF's design goal.

Q28CountVectorizer produces a dense matrix by default for large vocabularies.

False — it produces a sparse matrix by default, since most documents contain only a small fraction of the vocabulary.

Q29A first-order Markov model assumes the next state depends on the entire history.

False — it depends only on the current (most recent) state; that's the defining Markov property.

Q30Higher-order n-grams (e.g. 5-grams) always suffer less from data sparsity than lower-order ones.

False — the opposite: higher-order n-grams have exponentially more combinations, so sparsity gets worse, not better.

Q31Smoothing techniques assign non-zero probability to unseen n-grams.

True.

Q32________ encoding represents a word as a binary vector with a single 1 and the rest 0s. ________ model represents text as unordered word counts.

One-Hot encoding; Bag-of-Words (BoW) model.

Q33In TF-IDF, 'TF' stands for ________ and 'IDF' stands for ________. The scikit-learn class for token counting is ________.

Term Frequency; Inverse Document Frequency; CountVectorizer.

Q34The simplest smoothing technique, adding 1 to every count, is called ________ smoothing. ________ predicts a target word from context; ________ predicts context from a target word.

Laplace (add-one) smoothing; CBOW predicts target from context, Skip-gram predicts context from target.

Q35A spam filter using raw CountVectorizer finds common words ("the", "is", "a") dominate feature importance, drowning out "winner"/"lottery". What should they switch to, and why?

Switch to TF-IDF. It automatically down-weights near-universal words via the IDF term while up-weighting words frequent in specific documents but rare corpus-wide — exactly "winner"/"lottery" vs. "the"/"is".
