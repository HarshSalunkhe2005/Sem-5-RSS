Cloud Security, CSPM & SSO

Q46–Q60 · security fundamentals, shared responsibility, CSPM family, SSO protocols and risks

Q46What is cloud security? Why is it a different discipline from traditional security?4 marks

Cloud security protects cloud-hosted data, applications and infrastructure from threats and unauthorised access. Traditional security assumed a fixed perimeter ("inside" is trusted); the cloud dissolves the perimeter, with three shifts:

  • Shared control: the provider owns some layers, you own others, and the split changes across IaaS/PaaS/SaaS.
  • Speed and scale: Infrastructure as Code creates thousands of resources in seconds, so a mistake spreads fast.
  • API-driven everything: a leaked key or over-permissioned identity does as much damage as a stolen server key. Identity becomes the new perimeter.

Q48List and explain the six categories of cloud security threats.6 marks

  1. Misconfiguration: default or overly permissive settings (public bucket, database open to the internet, no MFA). Needs no hacking skill, hence the leading cause of breaches.
  2. Weak identity: over-permissioned identities and weak access control.
  3. Insecure APIs: everything is managed by API, so a leaked key lets an attacker act on the account.
  4. Data exposure: public buckets and over-shared links.
  5. Account hijacking: increasingly via session tokens, which can bypass login and MFA.
  6. Availability attacks: DDoS, accidental deletion by automation, regional outages.

Q49Explain the Shared Responsibility Model for IaaS, PaaS and SaaS. Cite the Capital One breach.7 marks

The provider secures the cloud itself (security of the cloud: data centres, host hardware, virtualisation layer, underlying network); the customer secures what they put in it (security in the cloud: identity and access, data, application and network configuration).

Moving IaaS → SaaS the provider takes more, but data and identity always stay with the customer. On EC2 you patch the OS; on Lambda AWS does, but you still own what the code does with data.

Capital One (2019): over 100 million records exposed. A misconfigured, over-permissioned WAF set up by the customer was tricked into fetching temporary credentials from the instance metadata service, which were used to read S3 buckets. It was a customer-side misconfiguration, not an AWS infrastructure flaw.

Q50Name the five pillars of a cloud security programme.5 marks

  1. IAM: who can do what, by least privilege (RBAC, MFA).
  2. Data protection: encryption at rest and in transit, tokenization, data classification (KMS for keys).
  3. Network security: VPCs, security groups / firewall rules, segmentation, WAF.
  4. Compliance & governance: ISO 27001, PCI-DSS, RBI IT framework, DPDP Act.
  5. Monitoring, detection & response: logging, alerting, continuous posture checking.

Q51What is CSPM? Explain its working and the five-stage cycle with a diagram.7 marks

Cloud Security Posture Management continuously and automatically discovers cloud resources, evaluates their configuration against best practices and compliance frameworks, and surfaces or fixes misconfigurations across every cloud account. It is agentless: it connects with read-only API credentials, builds a live inventory, checks it against a policy library and pushes prioritised findings to teams.

Limitations: focuses on configuration, not live runtime threats; false positives without tuning; auto-remediation can disrupt services; needs broad read access that must itself be secured.

Q52Why is CSPM needed? (volume, velocity, drift)3 marks

Misconfiguration is the largest root cause of cloud breaches, and manual review cannot keep up:

  • Volume: tens of thousands of resources across accounts, regions and providers.
  • Velocity: IaC and CI/CD change resources continuously.
  • Drift: a correct configuration is quietly changed later (a Friday "quick fix") and nobody re-reviews it.

Q54Define CIEM, KSPM and CNAPP and place them in the CSPM family.4 marks

  • CIEM (Cloud Infrastructure Entitlement Management): "does this identity have more access than it needs?"; finds and reduces over-privileged identities.
  • KSPM (Kubernetes Security Posture Management): the CSPM question for clusters, pods and RBAC (API server not public, no over-privileged pods).
  • CNAPP (Cloud-Native Application Protection Platform): umbrella product bundling CSPM, CWPP, CIEM and more.
  • CSPM = configuration; CWPP = running workloads.

Q55What is Single Sign-On? Explain its actors, benefits and risks.6 marks

SSO lets a user log in once with one set of credentials and access multiple independent applications without logging in again. It cures password fatigue (reuse, constant resets).

Userbrowser
↔
Identity Providerverifies user, MFA, issues signed assertion/token (Okta, Entra ID, Google)
↔
Service Providertrusts the IdP, never sees the password
  • Flow: user opens app → SP redirects to IdP → user authenticates (+MFA) → IdP issues signed token → browser presents it → SP verifies the signature and grants access; later apps reuse the IdP session.
  • Benefits: better UX, fewer weak/reused passwords, lower help-desk cost, central policy and quick de-provisioning, easy MFA.
  • Risks: IdP is a single point of failure and of compromise; legacy apps may not support SSO; misconfigured trust.

Q58Explain the OAuth 2.0 Authorization Code flow. Why is the back-channel step important? What is PKCE?7 marks

  1. User taps "Continue with Google" in the app (client).
  2. App redirects the browser to Google's authorization endpoint (/authorize).
  3. User authenticates and approves the requested permissions (scopes).
  4. Google redirects back with a short-lived single-use authorization code.
  5. Back channel: the app exchanges the code for an access token server-to-server, including its client secret.
  6. Google returns the access token (often with a refresh token).
  7. App calls Google's API; Google returns the data and the app creates the user's session.

The back-channel exchange keeps the client secret out of the browser and stops the code being intercepted and reused. Mobile and single-page apps cannot store a secret, so they use PKCE (Proof Key for Code Exchange) for the same protection.

Q60Write short notes on JWT, MFA with SSO and step-up authentication.4 marks

  • JWT: three Base64Url parts header.payload.signature (algorithm; claims such as sub, email, expiry; signature proving the IdP issued it). The app verifies it locally using the IdP's public key. OIDC ID tokens are JWTs.
  • SSO + MFA: SSO reduces the number of passwords; MFA makes each login harder to defeat (something you have / are). Enforcing MFA at the IdP protects every connected app; adaptive authentication asks for a second factor only on unusual logins.
  • Step-up authentication: SSO proves identity once, but sensitive actions (UPI payment) demand extra proof such as OTP, UPI PIN or biometric.
