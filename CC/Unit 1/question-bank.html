Overview of Cloud Computing

Q1–Q15 · cloud basics, architecture layers, IaaS / PaaS / SaaS, deployment models

Q1Define cloud computing (NIST definition).2 marks

A model for enabling ubiquitous, convenient, on-demand network access to a shared pool of configurable computing resources (networks, servers, storage, applications, services) that can be rapidly provisioned and released with minimal management effort or provider interaction.

The definition is built from 5 essential characteristics, 3 service models (IaaS, PaaS, SaaS) and 4 deployment models (public, private, hybrid, community).

Q2List and explain the five essential characteristics of cloud computing.5 marks

  • On-demand self-service: the user provisions servers/storage without human interaction with the provider (launch an EC2 VM in minutes).
  • Broad network access: services reachable over the internet from any device (Google Workspace on laptop/phone).
  • Resource pooling: resources are shared by many tenants (multi-tenant) and allocated dynamically with logical isolation (Azure).
  • Rapid elasticity: resources scale up or down automatically with the workload (Netflix on AWS Auto Scaling).
  • Measured service: usage is metered and billed pay-as-you-go (BigQuery bills by data processed).

Q3Trace the origins and evolution of cloud computing.5 marks

Cloud is the third stage of how computing is shared: client-server (central server, single point of failure, poor scaling) → distributed computing (networked computers share resources, but coordination and management limits) → cloud computing (centralised, elastic, on-demand pooling over the internet).

Year / eraMilestone
1960sTime-sharing: many users on one mainframe
1961John McCarthy: computing can be sold as a utility like water and electricity
1970sVirtualization: one machine runs several virtual systems
1990sInternet adoption enables web-based applications
1999Salesforce.com implements the utility idea commercially
2002 / 2006AWS launched / EC2 opened to everybody
2009Google Cloud and Microsoft Azure launch; IBM, Oracle, Alibaba follow

Q4Draw and explain the layered architecture of cloud computing.7 marks

Four-layer cloud architecture (top = closest to user)

Application layer (SaaS)email, docs, CRM, streaming: Gmail, Netflix, Salesforce
Platform layer (PaaS)frameworks, APIs, CI/CD: App Engine, Elastic Beanstalk, Heroku
Infrastructure layer (IaaS)virtualized compute, storage, network: EC2, Azure VMs
Datacenter layerservers, power, cooling, physical security

Each layer abstracts the one below it.

  • Application: end-user interface, on-demand pay-as-you-go delivery, multi-tenant, scales dynamically, highly available through distributed architecture.
  • Platform: pre-configured development environments, hides servers/network/storage, integrated databases, middleware and CI/CD, many languages, covers the full lifecycle code → test → deploy → scale.
  • Infrastructure: virtualization (many VMs on one machine), elastic provisioning and billing, failover across data centres, multi-tenant isolation.
  • Datacenter: physical hardware with redundant power/cooling/networking, scales horizontally (add servers) or vertically (upgrade), biometric and surveillance security.

Q7Explain SaaS with features, advantages, disadvantages and examples.5 marks

Fully functional software delivered over the internet, used through a browser with no install; the provider handles maintenance and updates.

  • Features: subscription model, no download/upgrade, scales with requirements, accessible from any connected device, provider responsible for everything.
  • Advantages: no hardware/setup cost, automated upgrades, cross-device, pay-as-you-go, easy customization and scalability.
  • Disadvantages: loss of control, limited range of solutions, connectivity is mandatory.
  • Examples: Google Workspace, Salesforce CRM, Microsoft 365.

Q8Explain PaaS with features, advantages, disadvantages and examples.5 marks

A development and runtime environment to build, test, deploy and manage applications without touching servers.

  • Features: develop, test and host in the same environment; scales with business needs; multiple users can work on the same app; integrated web services and databases; user has no full infrastructure control.
  • Advantages: highly scalable and multi-tenant, faster simpler development, less coding, automated policy, easy hybrid-cloud migration.
  • Disadvantages: data security concerns, not everything is cloud-enabled / compatibility with existing infrastructure, dependent on vendor reliability.
  • Examples: Google App Engine, Azure App Services, AWS Elastic Beanstalk, Heroku, Red Hat OpenShift.

Q9Explain IaaS with features, advantages, disadvantages and examples.5 marks

Virtualized compute, storage and networking rented instead of owned. It differs from ordinary hosting in scalability and virtualization; virtualization lets providers use up to about 90% of compute resources instead of leaving servers idle.

  • Features: highly scalable resources, enterprise-grade infrastructure, cost depends on consumption, multitenant (one hardware serves many users), client has complete control over the infrastructure.
  • Advantages: most flexible and dynamic model, pay-as-you-go, automated hardware deployment, frees staff from physical work.
  • Disadvantages: multi-tenant security issues, vendor outages block access, teams need training.
  • Examples: AWS EC2/EBS/VPC, Azure VMs, GCP Compute Engine, IBM Cloud Bare Metal.

Q12Explain the components of cloud architecture (frontend and backend).6 marks

Four core pieces: a frontend platform, a backend platform, a cloud-based delivery model and a network connecting them.

Frontendclient device / browser, UI, client-side apps
↔
Internetnetwork medium
↔
Backendapplication, service, runtime cloud, storage, infrastructure, management, security
  • Application: fulfils client requests. Service: manages access to storage, development environments, web apps.
  • Runtime cloud: OS-like layer running services via hypervisors. Storage: HDD/SSD/persistent disks. Infrastructure: CPU, GPU, network hardware.
  • Management: middleware coordinating frontend, backend and resources. Security: firewalls, backups, redundancy.

Q15What is resource pooling / multi-tenancy? Why is it both a benefit and a security concern?4 marks

Resource pooling: physical resources are shared among many users (tenants) and dynamically assigned by demand, with logical isolation (Azure hosts many organizations on shared hardware).

  • Benefit: high utilization, lower cost, elasticity.
  • Concern: a flaw or misconfiguration in isolation can expose one tenant's data to another; also performance degradation from noisy neighbours. This is why IaaS and PaaS list multi-tenant security among their disadvantages.
