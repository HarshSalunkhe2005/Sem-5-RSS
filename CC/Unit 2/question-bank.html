Virtualization

Q16–Q30 · hypervisors, implementation levels, Xen, full vs para-virtualization, binary translation, open-source cloud

Q16Define virtualization. What are its benefits?4 marks

Virtualization is the creation of a virtual (rather than actual) version of a server, desktop, storage device, OS or network resource. A single physical resource is shared among multiple customers by giving it a logical name and a pointer to the physical resource on demand. A VM runs logically separated from the hardware: the machine hosting it is the host, the VM is the guest.

  • Efficient resource use: a virtual server pool on shared hardware means fewer physical servers, less space, power and cooling.
  • Automated IT management: virtual machines are managed and duplicated with software tools, avoiding manual configuration errors.
  • Faster disaster recovery: restoring a VM takes minutes instead of the hours/days to replace a physical server.

Q18What is a hypervisor? Compare Type-1 and Type-2 hypervisors.6 marks

A hypervisor is firmware/low-level software acting as the Virtual Machine Manager: a layer between the VMs and the hardware/host OS. When a VM needs compute power the request goes to the hypervisor first, which passes it to the hardware, so all VMs get their share of physical resources.

Q19Explain the five implementation levels of virtualization.7 marks

Running a different OS on the same hardware is not trivial; the hypervisor bridges hardware and virtual OS. Five commonly used levels (bottom to top):

  1. ISA level: emulates an instruction set to run legacy code built for different hardware; an interpreter converts the code into a form the hardware can read; makes the VM hardware-agnostic.
  2. Hardware Abstraction Level (HAL): a hypervisor virtualizes I/O devices, memory and processor; mostly used in cloud infrastructure.
  3. Operating-system level: an abstract layer between OS and applications gives each user an isolated container with no hardware-sharing conflicts.
  4. Library level: applications use documented user-level library APIs; API hooks control the link between application and system.
  5. Application level: virtualizes only one application, not the whole environment; the app sits above the virtualization layer so high-level-language programs run seamlessly.

Q20List the eight types of virtualization and describe any four.5 marks

Types: hardware, operating system, server, storage, desktop, network, data, application.

  • Server: divides one physical server into several virtual servers to use its capacity fully (web hosting, dev/test, private cloud simulation).
  • Storage: pools all storage devices, even across vendors, into one virtual storage unit masking the SAN; eases replication and disaster recovery.
  • Network: combines switches, routers, firewalls to control them virtually; SDN controls traffic routing, NFV virtualizes firewalls and load balancers.
  • Data: a software layer between scattered data sources and applications that returns results in a suitable format.
  • Application: runs an application on an OS it was not designed for (Windows app on Linux), via streaming or server-based access.

Q21Explain hardware virtualization and its three types.6 marks

When the VMM/hypervisor is installed directly on the hardware it is hardware virtualization; its main job is to control and monitor the processor, memory and other hardware. Mostly done on server platforms.

  • Full virtualization: hardware is completely simulated; guest software runs unmodified; uses binary translation + direct execution; the guest is fully isolated. Introduced by IBM in 1966. Examples: VMware ESXi, Hyper-V, VirtualBox, Parallels. Hardware assist via Intel VT-x / AMD-V.
  • Emulation virtualization: the VM simulates the hardware and so becomes independent of it; guest OS needs no modification.
  • Para-virtualization: hardware is not simulated; guest runs in its own isolated domain; hardware-related instructions replaced by hypercalls; guest only partially isolated. Examples: Xen, VMware.

Q23Explain binary translation with full virtualization. Why are only critical instructions trapped?7 marks

Full virtualization needs no host-OS modification; it relies on binary translation to trap and virtualize sensitive, non-virtualizable instructions. Full virtualization = binary translation + direct execution.

Ring layout (lower ring = higher privilege)

ApplicationsRing 3, direct execution
→
Guest OSRing 1
→
VMMRing 0, scans and translates
→
Hardware
  1. Noncritical instructions run directly on the hardware.
  2. The VMM scans the instruction stream, identifies privileged, control- and behaviour-sensitive instructions, traps them into the VMM and emulates their behaviour; this emulation is binary translation.
  3. The guest OS is decoupled from the hardware and unaware of virtualization.

Only critical instructions are trapped because binary translation is time-consuming; running noncritical instructions natively promotes efficiency and security.

Performance: a code cache stores translated hot instructions (costs memory); about 80–97% of native on x86; I/O-intensive workloads suffer most. Advantages: best isolation, multiple guests run truly isolated, no hardware/OS assist needed. Disadvantages: runtime overhead, large performance cost, code-cache memory.

Q24What is host-based virtualization? State its pros and cons.4 marks

An alternative VM architecture: a virtualization layer is installed on top of the host OS, which still manages the hardware; guest OSes run on this layer.

  • Pros: install without modifying the host OS; the host supplies device drivers and low-level services, simplifying design and deployment; suits many host configurations.
  • Cons: hardware access passes through 4 layers of mapping, so performance is lower than the hypervisor architecture; if the guest ISA differs from the hardware ISA, binary translation is still needed and performance may be too low to be practical.

Q25Explain para-virtualization with compiler support. State its advantages and disadvantages.6 marks

Unlike full virtualization (privileged instructions intercepted and emulated at runtime), para-virtualization handles them at compile time: the guest OS kernel is modified to replace privileged/sensitive instructions with hypercalls to the hypervisor/VMM. Xen uses this: the guest OS runs at Ring 1 instead of Ring 0, so it cannot execute some privileged instructions directly and uses hypercalls instead. The virtualization layer sits between hardware and OS at Ring 0.

  • Advantages: relatively easy and practical; avoids the low performance of binary translation, which is hard to speed up; Xen is the standard example, and KVM and VMware ESX use paravirtual drivers for I/O.
  • Disadvantages: compatibility/portability doubts (must still support unmodified OSes for some uses); high maintenance cost for deep kernel changes; performance gain varies greatly with workload.

Q26Explain Xen hypervisor architecture with a diagram.7 marks

Xen is an open-source microkernel hypervisor from Cambridge University that separates policy from mechanism. It runs directly on hardware (Type 1, para-virtualization), turning it into a pool of logical resources allocated to guest OSes.

Xen architecture

Dom0privileged domain, device drivers, backend drivers  |  DomU 1 … DomU n guest VMs, frontend drivers, user applications
Xen hypervisorchecks page tables, schedules domains, allocates resources, boots machine to start Dom0
HardwareCPU, memory, disks, network
  • Dom0: first domain started at boot; can start new domains and access hardware directly; runs all device drivers; its backend driver multiplexes requests from each DomU's frontend driver. Only Linux has the tools/patches to run as Dom0.
  • DomU: unprivileged guest VM, no direct hardware access; must run a frontend driver; started by xend in Dom0 and accessed with the xm tool.
  • The hypervisor presents each domain a virtual machine similar but not identical to native hardware. Hypervisor + Dom0 + DomUs form the virtual machine environment running several OSes at once.

Q27Write short notes on KVM and VMware ESX Server.6 marks

KVM (Kernel-based Virtual Machine)

  • Full native virtualization for Linux on x86 hardware with Intel VT / AMD-V; limited para-virtualization (paravirtual network driver).
  • Loadable kernel module; part of kernel 2.6.20; memory management and scheduling are done by the Linux kernel.
  • Each VM (each vCPU) is a regular Linux process scheduled by the standard Linux scheduler. Supports unmodified Linux, Windows, Solaris, BSD guests.

VMware ESX Server

  • Bare-metal hypervisor for x86 SMP servers with direct I/O access and full resource control.
  • Components: virtualization layer (VMM virtualizing CPU, memory, network, disk), resource manager (allocates CPU, memory, disk, network bandwidth), hardware interface (drivers) and service console (boots the system, starts VMM and resource manager, then hands over, aids administration).
  • The unit notes describe it as a para-virtualization-style architecture: the VM kernel talks directly to hardware, bypassing the host OS. Many books list ESX/ESXi as full virtualization (binary translation, as in Q22), so in the exam follow the wording of your unit notes.
