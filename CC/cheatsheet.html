TopicRuleRemember
NIST essential characteristicsOn-demand self-service, broad network access, resource pooling, rapid elasticity, measured service5 characteristics
Service modelsIaaS (you manage OS and up), PaaS (you manage app and data), SaaS (you manage nothing)Control falls, convenience rises
Deployment modelsPublic, private, hybrid, communityHybrid = private + public, bursting
Hypervisor typesType 1 on bare metal (Xen, ESXi, Hyper-V, KVM); Type 2 on a host OS (VirtualBox, Workstation)Type 1 is faster and used in clouds
Virtualization techniquesFull (binary translation), para (hypercalls, modified guest), hardware-assisted (Intel VT-x, AMD-V)Hardware-assisted removes the translation cost
Virtualization levelsISA, hardware (HAL), OS, library, applicationHardware level = hypervisors
XenDom0 privileged (drivers, tools), DomU guests with frontend drivers, hypercalls and event channelsPolicy separated from mechanism
SOA rolesProvider, requester, registry: publish, find, bindLoose coupling through a contract
Load balancing algorithmsRound robin, weighted round robin, least connections, least response time, IP hashWeighted when servers differ in capacity
Layer 4 vs Layer 7 balancerL4 uses IP and port (fast, blind to content); L7 reads HTTP (path, cookies, headers)L7 can route by URL and terminate TLS
Target-tracking autoscalingdesired = ceil( current × metric / target )Cooldown prevents flapping
Jain's fairness indexJ = (Σxᵢ)² / ( n · Σxᵢ² )1 = perfectly even, 1/n = one server takes all
Shared responsibilityProvider secures the cloud; customer secures what they put in itCustomer always owns data, identity and access
CSPMContinuous: discover, assess, detect drift, prioritise, remediate, reportFinds misconfiguration, not malware
SSOUser logs in once at the identity provider, which issues a signed token to each applicationFewer passwords, one place to enforce MFA
