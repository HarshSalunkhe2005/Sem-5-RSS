Q32What is a cloud service provider? State the benefits of using one.3 marks

A third-party company offering a cloud-based platform, infrastructure, application or storage service; you pay only for what you use, like electricity or gas.

  • Scalability and flexibility (no physical-server limits); reliability (multiple redundant data centres); customisation; responsive load balancing.
  • Trade-off: the business must still evaluate security, access controls and compliance configuration for data in someone else's cloud.

Q33Explain the six principles of cloud architecture design.7 marks

  1. Reasonable deployment: public cloud = VMs on high-performance hosts; private = packaged software for a select user base; hybrid = unified management across public and private platforms (VMware, OpenStack, physical servers).
  2. Business continuity: high availability (redundancy), continuous operations (fault-free uptime), disaster recovery (restore apps/data in a different environment).
  3. Elastic expansion: decouple components; stay stateless (state in Redis), load balancing, message queues / API gateway, global load balancing across hybrid/multi-cloud.
  4. Performance efficiency: compute (bigger hosts, clusters), storage/caching (Redis hot-data, in-memory), network (optimal data centre per region).
  5. Security compliance: separate master/sub-accounts and key pairs, least privilege, ACLs and security groups, VPC isolation, protect against DDoS/SQL injection/XSS, keep access and operation logs.
  6. Continuous operation: monitor resources, services and events; alert by phone/SMS/email; auto-handle through callback functions; auto-scale on CPU; track cost and set balance alarms.

Q37Explain Service-Oriented Architecture (SOA) for cloud applications with a diagram.7 marks

SOA structures an application as loosely coupled, independently deployable services, each implementing one business capability and communicating over a network.

SOA components

Service consumerweb / mobile app or another service
↔
Enterprise Service Busrouting, transformation, load balancing, security, protocol conversion
↔
Cloud servicesAuthentication, Inventory, Payment, Shipping, Notification
Service registryUDDI, Eureka, Consul: directory for discovery
↑
Service providercreates the service and publishes its details
↓
Cloud infrastructurecompute, storage, network, virtualization (EC2, Azure, GCP)
  • Consumer requests (customer placing an order); provider publishes (Payment Service); registry enables dynamic discovery; ESB is the communication middleware.
  • Each service scales independently and can be swapped or upgraded without touching the rest, which gives elasticity and interoperability.

Q38What is the role of the service registry and the Enterprise Service Bus in SOA?4 marks

  • Service registry: a directory of available services so consumers discover them dynamically instead of hard-coding locations. Examples: UDDI, Eureka Server, Consul.
  • ESB: middleware for inter-service communication: message routing, data transformation, load balancing, security enforcement and protocol conversion.

Q39Why is SOA a good fit for cloud applications?3 marks

  • Loose coupling: each service is deployed independently.
  • Each service scales independently (elasticity) and runs on the shared cloud infrastructure.
  • Standard network interfaces give interoperability; a service can be upgraded or replaced without touching the rest.

Q40What is parallelization within cloud applications? Why parallelize in the cloud?4 marks

Dividing a large computational task into smaller tasks executed simultaneously across multiple processors, VMs, containers or cloud resources. The cloud's near-unlimited resources make parallel execution efficient and scalable.

  • Reduces execution time, improves performance, handles large-scale data, enables real-time analytics.
  • Example: processing millions of customer transactions on an e-commerce platform at once instead of one by one.

Q42Explain multi-tier application architecture with a diagram. Why is it suited to the cloud?7 marks

Multi-tier (N-tier) architecture physically separates presentation, processing and data logic into independent tiers, each developed, deployed, scaled and secured separately.

Three-tier web application (AWS mapping)

Presentation tierweb/mobile UI (HTML/CSS/JS), CloudFront / CDN
→
Application tierbusiness logic, APIs, microservices: load balancer + EC2 app servers
→
Data tierSQL/NoSQL, object storage, caches: RDS / DynamoDB
  • Independent scaling: scale only the busy tier.
  • Better security: data tier sits in a private subnet, reachable only by the app tier.
  • Independent maintenance: redeploy one tier without touching others.
  • Reusability: one backend serves both web and mobile frontends.

Each tier auto-scales and fails over independently, which fits elastic cloud infrastructure.

Q45Write short notes on OpenStack, Docker, Kubernetes, Terraform and Ansible.6 marks

  • OpenStack: open-source IaaS for private/public clouds; Nova (compute), Swift/Cinder (storage), Neutron (networking), Keystone (identity).
  • Docker: packages an app and dependencies into a lightweight portable container image.
  • Kubernetes: orchestrates, auto-scales and self-heals containers across a cluster.
  • Terraform: declarative, cloud-agnostic infrastructure provisioning; the same code applies on AWS/Azure/GCP.
  • Ansible / Chef / Puppet: configuration management automating server setup, deployment and drift correction.
  • Hypervisors Xen/KVM/VMware create the VMs under every IaaS; Eucalyptus / OpenNebula are earlier open-source private-cloud platforms.
