Load balancing and auto-scaling with AWS services (the Q7 scenario)

Seen in: Dec 24 Q7, Dec 25 Q7, May 25 Q7, May 26 Q7

This is the last question in every paper. The wording changes (poor utilization, time-of-day load, fluctuating traffic, multi-tier) but the answer skeleton is the same: problem, strategy, AWS services, steps, result. Learn the skeleton in the first answer and reuse it.

P1A cloud application has fluctuating user traffic. Analyze how load balancing and efficient resource utilization can maintain performance and minimise cost. Suggest strategies and outline the steps to implement them using AWS services.5 marks

Problem. Fixed capacity is either too small at peak (slow, errors) or too large off-peak (idle servers you still pay for). The fix is to spread requests evenly (load balancing) and to add or remove servers automatically (auto-scaling).

Strategy.

  • Put an Application Load Balancer in front of identical, stateless servers in two or more Availability Zones.
  • Use an Auto Scaling group with a target-tracking policy (for example keep average CPU at 50 %).
  • Add scheduled scaling for known patterns (office hours, sale days) and a minimum of 2 instances for availability.
  • Use cheaper capacity for the base (Reserved or Savings Plan) and Spot or on-demand for peaks.

Steps on AWS.

  1. Create a VPC with public subnets (ALB) and private subnets (servers) in 2 AZs.
  2. Build an AMI or launch template of the application (stateless: sessions in ElastiCache/DynamoDB, files in S3).
  3. Create a target group with a health check such as GET /healthz every 10 s, unhealthy threshold 3.
  4. Create the ALB, listener on 443, forward to the target group (set the deregistration delay, i.e. connection draining).
  5. Create the Auto Scaling group (min 2, desired 2, max 10) attached to the target group, spread over both AZs.
  6. Attach a target tracking policy: CPU 50 %, plus an instance warm-up time.
  7. Use CloudWatch alarms and dashboards (CPU, request count per target, latency) and a billing alarm.
  8. Load-test: scale-out and scale-in should happen, and killing one instance should not stop the app.

Worked number. 4 instances at 80 % CPU with target 50 %: desired = ceil(4 × 80 / 50) = ceil(6.4) = 7 instances; load per instance becomes about 46 %.

Result. Performance holds at peak, idle cost disappears off-peak, and a failed server is replaced automatically.

P2Describe a scenario where ineffective load balancing leads to poor resource utilization, and the strategies to fix it.5 marks

Scenario. A shop uses round robin over 3 servers. Server A is a 2-core machine, server B and C are 8-core. Every server gets one third of the requests, so A is at 95 % CPU and slow, while B and C sit at 30 %. Some requests are long (report generation) and stick to one server, which makes the imbalance worse. Customers see timeouts although most capacity is idle.

CauseFix
Servers of unequal size treated equallyWeighted round robin (weights 1 : 4 : 4) or least-connections
Sticky sessions pin users to one serverStateless servers, sessions in a shared store (Redis/DynamoDB)
Dead server still receives trafficHealth checks and connection draining
Fixed number of serversAuto-scaling on CPU or requests per target
Single balancer or single zoneRedundant balancer across Availability Zones

Measure it. Imbalance factor = max load / mean load (1.0 is perfect). Loads 95, 30, 30: mean 51.7, factor = 1.84. Jain's index = (Σx)² / (n·Σx²) = 155² / (3 × 10825) = 0.74 (1 is perfect). After weighted balancing the loads become about 55, 50, 50 and the index rises to about 1.00.

P3Outline how load balancing and auto-scaling maintain performance and scalability in a multi-tier cloud application. Identify suitable cloud services and the key steps to implement them.5 marks

A multi-tier application has a web tier, an application tier and a data tier. Each tier scales on its own.

TierBalancingScalingAWS service
PresentationApplication Load Balancer (public)ASG on request count per targetALB, EC2 or containers, CloudFront for static content
ApplicationInternal ALB between web and app tiersASG on CPU 50 %EC2 / ECS / Lambda
DataRead replicas share readsStorage auto-grows, replicas addedRDS Multi-AZ, Aurora, DynamoDB auto scaling

Steps.

  1. Make each tier stateless and put it in private subnets across 2 AZs.
  2. Create one target group and ALB for the web tier, another (internal) for the app tier.
  3. Create an Auto Scaling group per tier from a launch template, with health checks tied to the target group.
  4. Add target-tracking policies and scheduled scaling; set min 2 and a sensible max for cost control.
  5. Use RDS Multi-AZ for the database with read replicas; put a cache (ElastiCache) in front.
  6. Monitor with CloudWatch alarms, test with a load test, and review the bill.

Why it works. Load balancing removes the single bottleneck, auto-scaling follows demand, and multi-AZ placement keeps the app available when one zone fails.

P4A cloud environment has inconsistent workload at different times of the day. Construct a load balancing strategy to optimise resource utilization.5 marks

Idea. Combine a balancer that shares work fairly with scaling that follows the daily curve.

  1. Measure the pattern. CloudWatch shows peaks (for example 10:00 to 12:00 and 20:00 to 22:00) and a quiet night.
  2. Balance. Application Load Balancer using the least outstanding requests (or round robin) algorithm, health checks every 10 s, deregistration delay (connection draining).
  3. Scheduled scaling. Raise the minimum before the known peaks (for example 8 instances at 09:45, back to 2 at 23:00).
  4. Dynamic scaling. Target tracking at CPU 50 % handles surprise spikes; an instance warm-up time stops it over-scaling.
  5. Right-size and mix purchasing. Reserved capacity for the baseline of 2 instances, on-demand or Spot for peaks.
  6. Cache and offload. CloudFront and ElastiCache reduce load on the servers.

Outcome. Utilisation stays near the 50 to 70 % target all day, response time stays stable at peaks, and cost drops at night.

P6Illustrate how scalability, cost-efficiency and reduced management overhead are achieved differently in SaaS, PaaS and IaaS. Justify with real-world use cases.6 marks

The three models differ in how much the customer manages: IaaS (OS and up), PaaS (application and data only), SaaS (nothing).

AspectIaaSPaaSSaaS

ControlHighestMediumLowest

Conclusion. Choose IaaS for control, PaaS for developer speed, SaaS for ready-made software. Moving from IaaS to SaaS trades control for lower management effort.

P8Discuss the significance of each layer in cloud architecture (IaaS, PaaS, SaaS) in enabling cloud service delivery.3 to 4 marks

Each layer abstracts the one below it:

  • Datacenter layer: servers, power, cooling, physical security.
  • Infrastructure layer (IaaS): virtualised compute, storage and network, elastic provisioning (EC2, Azure VMs).
  • Platform layer (PaaS): development and runtime environment, databases, middleware, CI/CD (App Engine, Elastic Beanstalk).
  • Application layer (SaaS): the finished software used through a browser (Gmail, Salesforce).

Together they let a customer pick the level of control and effort they want.

P9How does the pay-as-you-go model in IaaS benefit organizations compared to owning physical infrastructure?3 marks

  • No upfront CapEx: no servers to buy; costs become OpEx.
  • Pay for use: billed per hour or per GB, so idle capacity is not paid for once instances are stopped.
  • Elasticity: capacity can grow for a peak and shrink after it, whereas owned hardware is sized for the peak and sits idle.
  • No maintenance: power, cooling, hardware replacement and datacenter staff are the provider's job.
  • Speed: a server is ready in minutes, not weeks of procurement.

Caveat: a continuously running, steady workload can be cheaper on owned hardware or reserved pricing.

P10Justify why multi-tenancy is a key feature of SaaS.3 marks

Multi-tenancy means one running copy of the application and one shared infrastructure serve many customers (tenants), whose data is logically isolated.

  • Lower cost: the infrastructure and operations cost is shared, so the subscription is cheap.
  • Higher utilisation: tenants peak at different times, so resources are used well.
  • One upgrade for all: the vendor patches or upgrades once, everybody gets it.
  • Easy scaling: a new customer is a configuration, not a new installation.

Risk to mention: a flaw in tenant isolation can expose data, so isolation, encryption and access control are essential. Example: Salesforce serves thousands of companies from the same code base.

Full virtualization vs para-virtualization and binary translation

Seen in: Dec 24 Q3, Dec 25 Q3, May 25 Q3, May 26 Q3

Always Part B Q3. The marking points are: guest OS modified or not, how privileged instructions are handled, performance, portability, and a recommendation.

P11Compare full virtualization (with binary translation) with para-virtualization in terms of efficiency, OS modification, performance and overhead. Which is more suitable for cloud providers and why?6 marks

A guest OS expects to run privileged instructions on real hardware. The hypervisor must stop that and handle it safely. The two techniques do it differently.

AspectFull virtualization (binary translation)Para-virtualization
Guest OSUnmodifiedModified kernel
Privileged instructionsTrapped and rewritten (translated) by the VMM at run time; non-critical instructions run directlyReplaced at compile time by hypercalls to the hypervisor
Guest awarenessUnaware it is virtualisedAware, uses the hypervisor API
Performance and overheadTranslation overhead (about 80 to 97 % of native on x86), code cache uses memoryClose to native, little overhead
IsolationComplete, best isolationPartial
Ease of deploymentAny OS runs, easy to deployOnly OSes with a ported kernel, high maintenance
ExamplesVMware ESXi, Hyper-V, VirtualBoxXen

Which suits cloud providers? Providers must run customers' unmodified operating systems (Windows, any Linux), so full virtualization, now helped by hardware assist (Intel VT-x, AMD-V), is the default in public clouds. Para-virtualization (or paravirtual drivers for network and disk) is used where the provider controls the guest, to gain speed.

P12Explain the process of binary translation in full virtualization and para-virtualization and how each handles guest OS instructions.6 marks

Full virtualization. The guest runs at a lower privilege ring (ring 1), the VMM at ring 0, applications at ring 3.

  1. The VMM scans the guest instruction stream.
  2. Ordinary (non-critical) instructions run directly on the CPU.
  3. Privileged, control- or behaviour-sensitive instructions are trapped.
  4. The VMM translates them into safe sequences that emulate the effect on the virtual hardware.
  5. Translated blocks are stored in a code cache so hot code is not translated again.

Para-virtualization. No run-time scanning. The guest kernel source is changed so every sensitive operation is a hypercall into Xen. This is done at compile time, which removes the translation cost.

Comparison in one line. Full: unmodified guest, translation at run time, slower. Para: modified guest, hypercalls at compile time, faster.

P13Describe the virtualization structure with key tools and mechanisms such as the hypervisor.3 to 4 marks

Virtualization creates virtual versions of servers, storage and networks on shared hardware.

  • Hypervisor (VMM): the layer between hardware and virtual machines that shares CPU, memory and I/O. Type 1 runs on bare metal (Xen, ESXi, Hyper-V, KVM); Type 2 runs on a host OS (VirtualBox, VMware Workstation).
  • Techniques: full (binary translation), para (hypercalls), hardware-assisted (VT-x, AMD-V).
  • Levels: ISA, hardware (HAL), OS (containers), library, application.
  • Tools: Xen, KVM, VMware ESXi, Docker for containers, Kubernetes for orchestration.

Hypervisor and the Xen architecture

Seen in: Dec 24 Q1b, Dec 25 Q1b, May 25 Q1b, May 26 Q1b

P14Explain why the hypervisor is the core component of virtualization and illustrate with the Xen architecture. Evaluate its role in resource management.3 marks

Role. The hypervisor sits between the hardware and the virtual machines. Every request for CPU, memory or I/O goes to it first, so it shares physical resources fairly, isolates one VM from another and lets many guest OSes run at once.

+----------+  +-----------+  +-----------+
| Dom0     |  | DomU 1    |  | DomU 2    |
| drivers  |  | guest OS  |  | guest OS  |
| backend  |<-| frontend  |  | frontend  |
+----------+  +-----------+  +-----------+
+---------------- Xen hypervisor -----------+
|  CPU scheduling, memory, hypercalls, events|
+--------------------------------------------+
+---------------- Hardware ------------------+

Sketch three boxes (Dom0, DomU 1, DomU n) over a Xen bar over a hardware bar.

  • Xen is a small Type 1 microkernel hypervisor from Cambridge; it separates policy from mechanism (scheduling and memory are mechanisms, management is left to Dom0).
  • Dom0 is the privileged first domain: holds the device drivers (backend) and management tools.
  • DomU are unprivileged guests with frontend drivers; they reach devices through Dom0.
  • Guests use hypercalls to ask Xen for services; Xen uses event channels to notify them.

Single Sign-On (SSO)

Seen in: Dec 24 Q6, Dec 25 Q1d, May 25 Q1e, May 26 Q1d

P16Elaborate Single Sign-On authentication in detail. Discuss its advantages for user experience and security with examples.6 marks

SSO lets a user log in once with one set of credentials and then use many independent applications without logging in again.

Actors. User (browser), Identity Provider (IdP: Okta, Entra ID, Google) and Service Provider (the application, which trusts the IdP and never sees the password).

Flow.

  1. User opens an application.
  2. The application redirects the browser to the IdP.
  3. User authenticates at the IdP (password plus MFA).
  4. The IdP issues a signed token (assertion) and sends the user back.
  5. The application verifies the signature and grants access.
  6. A second application reuses the IdP session, so no new login.
User experienceSecurity and administration
One login, no password fatigueFewer weak or reused passwords
Faster access to all appsMFA and policy enforced in one place
Fewer password resetsJoiner, mover, leaver: disable one account to remove all access; lower help-desk cost

Protocols: SAML 2.0 (enterprise), OAuth 2.0 (delegated authorization), OpenID Connect (login on top of OAuth). Risk: the IdP is a single point of failure and of compromise, so protect it with MFA and high availability. Example: one Google login opens Gmail, Drive and YouTube.

P17Evaluate the benefits of SSO for both users and administrators in cloud systems. / Illustrate how SSO improves efficiency and security.3 to 4 marks

Users: one login, fewer passwords to remember, quicker access, fewer lockouts.

Administrators: central user management, one place for MFA and password policy, instant de-provisioning when someone leaves, a single audit log, lower help-desk load.

Security: fewer passwords means less reuse and phishing surface. Keep the IdP highly available because it is a single point of failure.

Cloud Security Posture Management (CSPM)

Seen in: Dec 24 Q1e, Dec 25 Q1e, May 25 Q6, May 26 Q6

P18Evaluate the role of CSPM in maintaining compliance and security. Discuss how CSPM tools detect, prioritise and remediate misconfigurations or vulnerabilities.6 marks

CSPM continuously and automatically checks cloud accounts for misconfiguration and compliance gaps. Misconfiguration (public bucket, open database port, no MFA) is a leading cause of cloud breaches, and manual review cannot keep up with the volume, velocity and drift of change.

How it works (agentless, read-only API access):

  1. Discover a live inventory of accounts and resources, including shadow resources.
  2. Assess configuration against benchmarks (CIS, PCI-DSS, ISO 27001, custom rules).
  3. Detect misconfiguration and drift from the secure baseline.
  4. Prioritise by exploitability and business impact (a public database with customer data first).
  5. Remediate by auto-fix, ticket or infrastructure-as-code pull request.
  6. Monitor new resources and report compliance; the loop repeats.

Role in compliance: dashboards and audit evidence for each framework. Limits: looks at configuration, not live attacks (that is CWPP); false positives without tuning; auto-fix can break services. Example: an S3 bucket turned public on Friday is flagged and closed within minutes.

P19Describe the purpose / primary role of CSPM in cloud security.3 marks

CSPM answers one question: is my cloud configured securely? It inventories resources, compares them with best practice and compliance frameworks, finds misconfigurations and drift, ranks them by risk, and alerts or fixes them. Its main benefit is preventing breaches caused by misconfiguration and proving compliance.

Seen in: Dec 24 Q1f, Dec 25 Q1f, May 25 Q1f, May 26 Q1f

P20Discuss the advantages of HPC on the cloud compared with traditional on-premises HPC; mention a challenge.3 marks

HPC aggregates many nodes (compute, fast network, fast storage) to solve large problems in parallel.

Cloud HPCOn-premises HPC
Pay per use, no upfront equipment costLarge CapEx, fixed capacity
Scale to thousands of cores on demand, results in hours instead of weeksQueue waits when the cluster is full

Challenges: network latency and bandwidth between nodes, cost of data transfer, security and compliance, and high electricity use. Example: a film studio renders 1000 frames at 6 min each: one node needs 100 h, 50 nodes need 2 h.

P21Explain how cloud platforms support high performance computing for complex computational tasks.3 marks

Clouds offer large clusters of compute nodes with high-speed, low-latency networking and fast shared storage, scheduled by batch services. Users start a cluster, run a loosely coupled job (rendering, parameter sweeps) or a tightly coupled job with MPI (weather simulation), then shut it down and pay only for the time used. Google Cloud example: Compute Engine VMs, Cloud Storage, Batch scheduler, GKE.

P22Illustrate the components of a multi-tier application architecture and explain how it supports scalability, fault tolerance and efficiency in the cloud.5 to 6 marks

Multi-tier (N-tier) separates an application into independent tiers that are developed, deployed, scaled and secured separately.

User -> [Load balancer] -> Presentation tier (web servers)
                          -> Application tier (business logic, APIs)
                          -> Data tier (database, cache, object storage)
TierRoleExample (AWS)
PresentationUser interface, static contentCloudFront, EC2 web servers
ApplicationBusiness logicEC2, ECS, Lambda behind a load balancer
DataStorage and retrievalRDS, DynamoDB, S3
  • Scalability: scale only the busy tier with its own Auto Scaling group.
  • Fault tolerance: each tier runs on several servers in several zones; a failed server is replaced without stopping other tiers.
  • Security: the database sits in a private subnet reachable only from the application tier.
  • Efficiency: a tier can be upgraded or redeployed alone, one backend serves web and mobile.

P23Evaluate the role of Service-Oriented Architecture (SOA) in designing cloud applications. How does it improve reusability and interoperability?6 marks

SOA builds an application from loosely coupled services, each doing one business job and talking over a network through a standard interface.

Roles: service provider (publishes the service), service registry (directory: UDDI, Eureka, Consul), service consumer (finds and calls it). An Enterprise Service Bus can route messages, transform data and enforce security.

  1. Provider publishes its contract to the registry.
  2. Consumer finds it in the registry.
  3. Consumer binds and invokes it directly (SOAP or REST).
  • Reusability: a payment service written once is used by the web shop, mobile app and billing.
  • Interoperability: standard interfaces let services on different platforms or clouds work together.
  • Scalability: each service scales on its own; services can be upgraded or replaced without touching the rest.

Drawback: network calls add latency and a bus can become a bottleneck.

P26Explain the importance of parallelization in cloud applications for handling large-scale tasks.5 marks

Parallelization divides a large task into smaller tasks that run at the same time on many processors, VMs or containers. The cloud has near-unlimited resources, so it makes the speed-up affordable.

PatternHowExample
Data parallelismSame operation on chunks of data, merge resultsMapReduce or Spark over a large log file
Task parallelismDifferent independent sub-tasks togetherVideo transcoding: audio, thumbnails, compression
Pipeline parallelismSequential stages, different items in each stageETL pipeline

Benefits: shorter execution time, higher throughput, big-data handling, real-time analytics. Example: 1000 independent frames, 6 min each, on 50 nodes: 20 frames per node = 120 min instead of 6000 min, a 50× speed-up (ideal).

Cloud security: threats, safeguards and shared responsibility

Seen in: Dec 24 Q1d, Dec 25 Q6, May 25 Q1d, May 26 Q1e

P27Analyze the key challenges in securing cloud environments and how organizations can ensure confidentiality, integrity and availability.6 marks

GoalChallenge in cloudMeasure
ConfidentialityPublic buckets, shared tenancy, leaked keysEncryption at rest and in transit (KMS), least-privilege IAM, MFA, private subnets
IntegrityUnauthorised changes, tampered images or codeHashing and signatures, versioning, audit logs (CloudTrail), controlled infrastructure-as-code changes

P28Illustrate one common threat to cloud security and a measure to mitigate it.3 to 4 marks

Threat: misconfiguration, for example an S3 bucket left public or a database open to the internet. It needs no hacking skill, so it is one of the leading causes of breaches (Capital One, 2019: a misconfigured web application firewall let an attacker obtain the credentials of an over-permissioned role and read S3 buckets).

Mitigation: block public access by default, least-privilege IAM roles, MFA, infrastructure-as-code reviews, and a CSPM tool that flags and fixes drift automatically.

P29Describe the role of cloud security in safeguarding cloud environments; list the essential aspects.3 to 4 marks

Cloud security protects data, applications and infrastructure from threats and unauthorised access. Essential aspects: identity and access management (least privilege, MFA, SSO), data protection (encryption, key management), network security (VPC, security groups, WAF), compliance and governance (ISO 27001, PCI-DSS), and monitoring, detection and response (logs, alerts, CSPM).

P31Explain any two AWS tools offered for developing and deploying cloud applications.4 to 5 marks

1. AWS Elastic Beanstalk (PaaS). You upload application code (Java, Python, Node, .NET and others). Beanstalk provisions EC2 instances, a load balancer, an Auto Scaling group and CloudWatch monitoring, and handles patching and rolling deployments. You keep control of the underlying resources if you want. Example: a student portal deployed in minutes without configuring servers. Benefit: faster delivery, less management. Limit: less flexibility than building on EC2 yourself.

2. AWS Lambda (serverless compute). You upload a function; AWS runs it when an event arrives (S3 upload, API call, schedule) and scales it automatically. You pay only for run time in milliseconds. Example: a Lambda behind API Gateway returns a JSON response for a mobile app. Benefit: no servers, automatic scaling. Limit: time limit per run (15 minutes) and cold starts.

Other good choices: CodePipeline (CI/CD), CloudFormation (infrastructure as code), ECS/Fargate (containers).
