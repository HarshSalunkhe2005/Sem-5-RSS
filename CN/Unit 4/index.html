01 · Two ways to move packets

Virtual-Circuit & Datagram Networks

The Network Layer is the 3rd OSI layer. Its job is to move packets from the source host to the destination host across many networks and routers. A packet-switched network can offer this service in two ways: as a virtual-circuit network (connection-oriented) or as a datagram network (connectionless).

Virtual-circuit (VC) network

A VC network is a category of packet-switching network in which a virtual path is established between the source and destination before data flows. The path appears dedicated to the user, but it is really a logical circuit allocated from a managed pool of circuit resources according to traffic needs. The resources on the path can still be shared with other communications, which the user does not see.

Features

  • Switching is done at the network layer.
  • The path taken by the first packet is allocated; all later packets use the same path.
  • Buffers and bandwidth are reserved before transmission, and all packets consume the same resources.
  • All packets follow one path, so they share a common header and routing information.
  • Greater reliability and less complexity, owing to fixed paths and fixed resources.

Congestion control in a VC network (closed-loop)

  • No new connection: once congestion is detected, no new connections are set up (as a telephone exchange refuses new calls when overloaded).
  • Avoid the congested router: allow new connections, but route them so the congested router is not on the path.
  • Negotiation: at set-up time the host specifies the shape and volume of traffic, quality of service and other parameters.

Phases of VC transmission

  1. Set-up phase: a virtual circuit (route) is established from source to destination through a number of switches. Source and destination use global addresses, from which the switches make routing-table entries.
  2. Data-transfer phase: once the circuit exists, all packets follow the route set up earlier, according to the routing tables.
  3. Teardown phase: when data transfer is complete, the source sends a teardown request; the destination answers with a teardown confirmation; the switches flush their table entries, releasing the circuit.

Beyond the deck Each switch holds a VC table: (incoming interface, incoming VC number) → (outgoing interface, outgoing VC number). After set-up, packets carry only a short VC number (not the full destination address), and the number may change hop by hop.

Advantages of virtual circuit

  • Packets reach the receiver in the same order as sent.
  • A reliable network circuit.
  • No per-packet overhead for routing; a single global set-up overhead is used.

Disadvantages of virtual circuit

  • Costly to implement.
  • Provides only connection-oriented service.
  • A new connection set-up is always required before transmission.

Datagram network

In a connectionless system, a datagram is the smallest unit of data transmitted. Datagrams carry enough header information to be individually routed by every intermediate switching device. These networks exist within packet switching. (The deck adds that datagram communication is generally associated with UDP; in the Internet the datagram service of the network layer is provided by IP itself.)

Features of datagram networks

  • Switching is done at the network layer.
  • Each datagram is routed independently, even if it belongs to the same message; the network treats each as if it exists alone.
  • No dedicated path is fixed. Each datagram is routed using dynamically changing routing tables, so two successive packets from the source may follow completely different routes.
  • No prior resource allocation: buffers, processors and bandwidth are not reserved.
  • Resources are allocated on demand, first-come first-served (FCFS). A packet waits if other packets are being processed, whatever their source or destination.

Routing principle & example

Host H1 sends a message to host H2 through an ISP with five routers (numbered 1 to 5). H1 is attached to router 1 and H2 to router 5. The message is large enough to be broken into four packets A, B, C and D. Each router keeps a table with two columns: DEST (destination node) and NEXT (next node on the way). To reach DEST, the packet is forwarded to NEXT. These tables are dynamic and are refreshed from time to time depending on network conditions.

Because A, B, C and D are routed separately, they can take different routes and arrive out of order; it is the responsibility of H2 to reorder the packets and retrieve the original message.

02 · The glue of the Internet

Internet Protocol (IP), IP Packet & the Router

The Internet Protocol (IP) is a set of rules that allows computers and other devices to communicate over the Internet. It makes sure that information sent from one device reaches the correct destination by using a unique set of numbers called IP addresses. Whether browsing, e-mailing or streaming video, IP manages how the information travels.

Why IP is important

  • It is responsible for delivering packets from the source host to the destination host based on their IP addresses.
  • Every device is assigned an IP address, a "home address" which lets other devices locate it and send messages to it. IP provides the addressing and routing mechanisms the devices need.
  • IP works with ICMP to send error messages and operational information (e.g. destination unreachable, echo requests) so that senders learn about delivery problems.

Key terms

IP address

A "number sticker" given to every device that uses IP. It serves two purposes: host / network-interface identification and location addressing.

Packet

A parcel of data switched between origin and destination in a packet-switched network. It has a header and a payload.

Router

A network device that acts as a forwarding point for data packets between computer networks. Routers perform the traffic-routing functions of the Internet.

IPv4

Provides connectivity between hosts online; the version behind most Internet communication today.

IPv6

The latest iteration of IP, used to identify, locate and route computers so traffic can be transferred properly.

What is an IP packet?

The basic unit of data transmission in an IP network, consisting of:

  • Header: essential control information such as the source and destination IP addresses, which helps routers decide where to send the packet.
  • Payload: the actual data. On arrival, the payload is delivered to the appropriate application or protocol.

How IP routing works

IP routing moves information from the source to the recipient and on to its final destination. Data is broken into pieces, and each piece typically passes through several routers before reaching the destination. The path is determined by the routing algorithm, whose design considers factors such as packet size and header length to find the most suitable route. When a datagram arrives at a router, its source and destination address fields are used with the routing table to decide the address of the next hop.

MAC vs. IP vs. port address

When you open a website, three kinds of address are in play:

AddressLayerRole
Physical (MAC)Data linkIdentifies a network interface on the local network, for frame delivery.
Logical (IP)NetworkIdentifies the source and destination at the network layer, enabling routing between networks.

The router's two jobs Beyond the deck

  • Forwarding (data plane, per packet, nanoseconds): look up the destination address in the forwarding table and push the packet to the right output link.
  • Routing (control plane, slow time-scale): run routing algorithms / protocols to compute the paths and fill the forwarding table.
  • In the table the router uses longest-prefix matching: when several entries match the destination, the one with the longest prefix (most specific) wins. A worked example is on the Numericals page.

03 · 32-bit addresses

IPv4 & IPv4 Addressing

IPv4 (Internet Protocol version 4) is the most widely used system for identifying devices on a network. It uses a set of four numbers separated by periods (like 192.168.0.1) to give each device a unique address, which helps data find its way from one device to another.

Address format

  • An IPv4 address is 32 bits, grouped into four sections called octets (bytes) of 8 bits each, written in decimal and separated by dots: dotted-decimal notation.
  • An octet can represent 256 values, from 0 to 255. Example: 185.107.80.231 has four octets.

Advantages of IPv4 (from the deck)

  • IPv4 security permits encryption to keep privacy and security.
  • Easy to attach multiple devices across a large network (even without NAT, per the deck).
  • A model of communication that provides quality service and economical data transfer.
  • Routing is scalable and economical because addressing is aggregated more effectively.
  • Data communication becomes more specific in multicast organisations.

Limitations of IPv4

  • The world's supply of unique IPv4 addresses is dwindling and could run out.
  • If there are many hosts, the next class of addresses is needed.
  • Complex host and routing configuration, non-hierarchical addressing, difficult re-numbering, large routing tables.
  • Non-trivial to provide security, QoS, mobility, multi-homing, multicasting and so on. This is why IPv6 came into the picture.

04 · Network address & host ID

Subnet Masks, Network Address & Host ID

A subnet mask tells you which bits of an address are the network portion and which are the host portion: every 1 bit in the mask is a network bit and every 0 bit is a host bit. Writing /n (CIDR notation) means the first n bits are the network portion.

Q1: 172.16.5.120, mask 255.255.0.0 (/16)

First 16 bits = network, remaining 16 = host.

Network address = 172.16.0.0

Host ID = 5.120 (binary 00000101.01111000)

Q2: 10.20.30.45, mask 255.0.0.0 (/8)

First 8 bits = network, remaining 24 = host.

Network address = 10.0.0.0

Host ID = 20.30.45 (binary 00010100.00011110.00101101)

Formulas Beyond the deck

  • Network address = IP address AND subnet mask (bitwise).
  • Broadcast address = network address with all host bits set to 1.
  • Host ID = IP address AND (NOT mask).
  • Addresses in a block = 2(32 − n); usable hosts = 2(32 − n) − 2 (network and broadcast addresses are not assignable).
  • Subnetting into N equal subnets: borrow b = ⌈log2 N⌉ bits from the host part, so the new prefix is /(n + b). The block size in the changed octet is 256 − (mask value).
  • CIDR (classless inter-domain routing) drops the fixed A/B/C boundaries and allows any prefix length; VLSM lets different subnets of one network use different prefix lengths (allocate the largest subnet first).

Full worked examples (broadcast, usable hosts, equal subnets, VLSM, longest-prefix match, fragmentation) are on the Numericals page.

05 · 128-bit addresses

IPv6

The Internet Protocol version 6 (IPv6) is the latest version of IP, the system used for identifying and locating computers on the Internet. It was developed by the IETF. An IPv6 address is 128 bits long, giving an address space of 2128, far larger than IPv4's. It is written in hexadecimal separated by colons (:).

Address format

  • There are 8 groups, each representing 2 bytes (16 bits).
  • Each hex digit is 4 bits (one nibble); each group has 4 hex digits.
  • The delimiter is the colon.

Example: 2001:0db8:85a3:0000:0000:8a2e:0370:7334 Beyond the deck

Beyond the deck Shortening rules: (1) leading zeros in a group may be dropped; (2) one run of consecutive all-zero groups may be replaced by :: (only once per address). So 2001:0db8:0000:0000:0000:ff00:0042:8329 becomes 2001:db8::ff00:42:8329.

Need for IPv6 (features)

Large address space

128 bits versus 32 bits: an increase of 296 times in the address space.

Better header format

New header format; options are separated from the base header and inserted, when needed, between the base header and the upper-layer data. This simplifies and speeds up routing, since routers need not check most options.

New options

New options allow additional functionality.

Allowance for extension

Designed so the protocol can be extended for new technologies or applications.

Support for resource allocation

The type-of-service field is removed; two new fields, traffic class and flow label, let the source request special handling of a packet, e.g. real-time audio and video.

More security

Encryption and authentication options provide confidentiality and integrity of the packet.

Addressing methods

Unicast

Identifies a single network interface. A packet sent to a unicast address is delivered to that interface.

Multicast

Used by a group of hosts (not necessarily together geographically) that share a multicast destination address. One packet is delivered to all interfaces of the group.

Anycast

Assigned to a group of interfaces. A packet sent to an anycast address is delivered to only one member, mostly the nearest.

Migrating from IPv4 to IPv6 Beyond the deck

An IPv6 packet cannot be understood by an IPv4-only router, so the Internet moves gradually using three techniques: dual stack (hosts and routers run both IPv4 and IPv6), tunnelling (an IPv6 packet is carried as the payload inside an IPv4 packet across an IPv4-only region) and translation (NAT64 / header translation between the two).

06 · Error and control messages

Internet Control Message Protocol (ICMP)

ICMP is a network-layer protocol, used mostly on network equipment such as routers, for error handling at the network layer. IP has no built-in mechanism for sending error and control messages, so it depends on ICMP. It is a supporting protocol that routers and other devices use to send error messages and operational information, e.g. the requested service is not available, or a host or router could not be reached.

Uses of ICMP

Error reporting

If an error occurs between two devices, the router sends an ICMP error message to the source. E.g. if a message is too large for the receiver, it is dropped and an ICMP message is returned to the source.

Traceroute

Shows the route between two devices, hop by hop from one router to the next. Used to check network issues before data transfer.

Ping

A simple kind of traceroute that sends an echo-request message to measure the time for data to reach the destination and return; the replies are echo-reply messages.

Beyond the deck Traceroute works by sending probes with TTL = 1, 2, 3, …; each router that drops a packet because its TTL reached 0 returns an ICMP Time Exceeded (type 11), revealing that hop; the final host replies with a destination/port-unreachable or echo reply.

Working of ICMP

  • ICMP is connectionless, in contrast to TCP, which is connection-oriented and needs a handshake before sending.
  • ICMP packets are sent as datagrams containing an IP header with ICMP data; the ICMP header comes after the IPv4 or IPv6 packet header.

ICMP in DDoS attacks

ICMP lacks authentication and can be abused for DoS and DDoS attacks, where attackers overwhelm a target with unwanted traffic so it cannot serve its users. Ways ICMP is used:

  1. Ping of death: the attacker sends an IP packet larger than the maximum IP allows. It is fragmented on the way; when the recipient reassembles it, the size exceeds the limit, causing a buffer overflow and a freeze or crash.
  2. ICMP flood (ping flood): the target is overwhelmed with echo-request packets, each of which must be processed and answered with an echo reply, exhausting its resources.
  3. Smurf attack: the attacker sends an ICMP packet with a spoofed source IP; network equipment replies to it, sending the spoofed address a flood of packets.
  4. ICMP tunnelling: a command-and-control technique that hides malicious traffic inside benign-looking ICMP headers, bypassing firewalls and security measures.
  5. ICMP router-advertisement spoofing: false router advertisements mislead devices into using the attacker's machine as their default gateway, enabling man-in-the-middle attacks.

Advantages of ICMP

  • Devices use it to send error messages; administrators use ping and tracert to debug the network.
  • Alerts help identify connectivity issues, e.g. when a destination host or network becomes unavailable or a packet is lost.
  • Monitoring tools use ICMP to detect problems the network team must resolve.
  • A quick, simple method (queries and answers) to test connections and find the source of a fault.

Disadvantages of ICMP

  • If a router drops a packet because of an error, IP's design gives the sender no guaranteed way to be told.
  • If a packet's TTL reaches zero it is destroyed.
  • IP has no standard method for devices to check each other's "vital signs" (e.g. whether a destination is still operational) before sending data.

07 · Finding the best path

Routing & Routing Algorithms

A routing algorithm is a procedure that lays down the route or path used to transfer data packets from source to destination. It helps direct Internet traffic efficiently: after a packet leaves its source it can choose among many paths, and the routing algorithm mathematically computes the best path, i.e. the least-cost path.

1. Adaptive (dynamic)

Change routing decisions whenever the network topology or traffic load changes. They use dynamic information such as current topology, load and delay to select routes.

2. Non-adaptive (static)

Do not change decisions once selected. The route is computed in advance and downloaded to routers when they boot.

3. Hybrid

A combination of the two: the network is divided into regions and each region uses a different algorithm. The deck lists link-state and distance-vector under this heading.

Routing in the Internet Beyond the deck

The Internet is far too large for one flat routing algorithm, so it is split into autonomous systems (AS), each under one administrative control. Routing is therefore hierarchical:

  • Intra-AS routing (Interior Gateway Protocols, IGP): inside one AS, using RIP (distance vector) or OSPF (link state).
  • Inter-AS routing (Exterior Gateway Protocol): between ASes, using BGP, where policy matters as much as shortest path.

08 · Everyone knows the whole map

Link-State Routing Algorithm

A link-state algorithm determines the shortest path from one node to another. Each router shares its knowledge of its neighbourhood with every other router in the internetwork. Every router therefore learns the full network topology and builds its own routing table from it: it constructs a complete topological map (every node and link) and uses the map to compute shortest paths.

Important points

Complete topological map

A map of all nodes and links.

Dijkstra's algorithm

Often used to calculate shortest paths between nodes.

Link State Packets (LSPs)

Each router sends periodic LSPs, describing its local links, to all other routers.

Topology database

Routers keep information from received LSPs, which lets them build the network map.

Shortest-path calculation

After building the map, each router runs Dijkstra to every other node.

Link-state updates

When the topology changes, routers generate new LSPs so everyone stays up to date.

A link-state protocol maps the entire network (routers and links). The map is the link-state database (LSDB) or topology table: the data structure that stores the topology as known by a router. Routers exchange LSAs (Link State Advertisements), which describe the state of the links connected to each router and are used to build and maintain an up-to-date network map.

Two phases

1. Flooding phase

Each router floods its own LSA, containing the state of its own links and neighbours, to all other routers. Routers use the LSAs to build and update their LSDB.

2. Calculation phase

Once a router has the LSAs and has built its LSDB, it performs a shortest-path-first (SPF) calculation, considering link costs and router state. The result builds the forwarding table of best paths used to forward packets.

The two phases are continuous and simultaneous: routers keep flooding LSAs and updating the LSDB, and recompute SPF on the latest topology.

The algorithm, step by step

  1. Discovery: each router sends Hello packets to discover neighbours and establish adjacency; then routers exchange LSAs to learn the state of the network.
  2. LSA flooding: each router floods its own LSA (its links and neighbours) to all other routers, which build or update their LSDB.
  3. SPF calculation: with the LSDB complete, each router computes the best path to every destination (using link costs and router states) and builds the forwarding table.
  4. Updating LSAs: on a change (link failure, new router), the affected router floods a new LSA; this triggers a new SPF calculation and the forwarding table is updated.
  5. Aging LSAs: each LSA gets a time-to-live; when it expires the router removes it from the LSDB. The steps repeat continuously.

Dijkstra's shortest-path algorithm Beyond the deck

Let c(u,v) be the link cost, D(v) the current least cost from the source to v, and N' the set of nodes whose least cost is final.

  1. Initialise: N' = {source}. For each node v: D(v) = c(source, v) if v is a neighbour, else ∞.
  2. Loop: pick the node w not in N' with the smallest D(w) and add it to N'.
  3. Relax: for each neighbour v of w not in N': D(v) = min( D(v), D(w) + c(w,v) ), recording the predecessor.
  4. Repeat until every node is in N'. A worked iteration table is on the Numericals page.

Advantages of link-state routing

  • Each router has a complete map, so convergence is much faster than distance vector, which relies on periodic updates.
  • Updates are sent only when the topology changes, using less bandwidth than distance vector.
  • Better suited to large networks; handles many routers and links without routing loops.

Disadvantages of link-state routing

  • Needs more computational power and memory (for the LSDB and SPF), which can limit scalability.
  • More complex, so harder to configure and manage.
  • Generates more network traffic from frequent updates about topology changes (per the deck).
  • Vulnerable to routing attacks such as spoofed LSAs, which can make routers choose wrong routes.

09 · Routing by rumour

Distance-Vector Routing Algorithm

Distance Vector Routing (DVR) is a dynamic routing algorithm that routers use to find the best path from a source network to a destination network. Each router maintains a routing table with:

  • Destination: the destination network or router.
  • Distance (cost): the cost of reaching it.
  • Next hop: the neighbour through which packets should be forwarded.

Each router shares its routing information with its immediate neighbours only. Using what it hears, it updates its table until the network converges (the routes stabilise). The algorithm is based on the Bellman–Ford equation:

dx(y) = minv { c(x,v) + dv(y) }   where the minimum is over all neighbours v of x; c(x,v) is the cost of the link x–v and dv(y) is v's advertised distance to y. Beyond the deck (the deck shows the equation as a picture)

Working of the algorithm

  1. Initially each router knows the cost of reaching itself (0) and its directly connected neighbours.
  2. Each router shares its distance vector with its immediate neighbours periodically, or when a change occurs.
  3. Routers calculate the cost of reaching each destination through each neighbour.
  4. The router selects the minimum-cost route and updates its table.
  5. This continues until no routing table changes.

Example (from the deck)

Links: A–B = 1, B–C = 1, A–D = 4, D–C = 1. Router A wants the shortest path to router C.

  • Directly through B: cost = A–B + B–C = 1 + 1 = 2.
  • Through D: cost = A–D + D–C = 4 + 1 = 5.
  • So A chooses A → B → C with minimum cost 2.

The count-to-infinity problem

Routers keep increasing their estimated distance to an unreachable destination because each wrongly believes another router still has a valid path to it. This causes routing loops and slow convergence.

Example: three routers A, B, C in a line; network X is attached to A. Initial distances to X: A = 0 (directly connected), B = 1 (through A), C = 2 (through B). Now the A–X link fails.

  1. Link failure: A marks X unreachable (distance ∞).
  2. Incorrect information at B: before learning about the failure, B still advertises distance 1 to X. A hears this stale information and thinks B has a path to X.
  3. Distance increases: A computes 1 + 1 = 2 via B. B then hears A's new advertisement and computes 1 + 2 = 3.
  4. Repeated updates: A and B keep raising their distances, each believing the other has a route. Packets may loop between them.

Solutions to count-to-infinity

1. Split horizon

A router does not advertise a route back to the neighbour from which it learned it.

2. Route poisoning

A failed route is advertised with an infinite metric.

3. Poison reverse

A router explicitly advertises a route back to the neighbour it learned it from, but with an infinite metric.

4. Triggered updates

Routers send an update immediately after a significant change instead of waiting for the next periodic update.

5. Hold-down timers

After detecting a failure, routers temporarily suppress potentially incorrect routing information.

Beyond the deck Split horizon / poison reverse cure the two-node loop above but not every larger loop; that is why timers and a small "infinity" (16 in RIP) are also used. Link-state routing avoids the problem because every router has the full map.

10 · The simplest Internet routing protocol

Routing Information Protocol (RIP)

RIP is a distance-vector protocol that uses hop count as its primary metric. It defines how routers should share information when moving traffic among an interconnected group of LANs. It was originally designed for the Xerox PARC Universal Packet protocol suite (known as Gateway Information Protocol in Xerox Network Systems in 1981). RIP, defined in RFC 1058 (1988), is easy to configure and use in small networks.

How RIP works

  • Each RIP router keeps a routing table of all destinations it knows and sends it to its closest neighbours every 30 seconds. Neighbours are routers directly connected on the same network segments.
  • Neighbours pass the information on to their neighbours, and so on, until all RIP routers have the same knowledge of paths: this shared knowledge is convergence.
  • If an update gives a shorter path, the router updates the entry with the new length and next hop.
  • If the new path is longer, the router waits through a hold-down period to see whether later updates repeat the higher value; it changes the entry only if the longer path is stable.
  • If a router crashes or a link is cut, updates stop. A route not refreshed for six successive update cycles (180 s) is dropped, and the rest of the network is told through the router's own periodic updates.

Hop count

  • RIP supports at most 15 hops in a path. A destination network owned by a directly connected neighbour is one hop (a cost of one). If a packet cannot reach the destination in 15 hops, it is unreachable (16 = infinity).
  • RIP uses a modified hop count: engineers can assign a path a higher cost, as if it had extra hops, to discourage its use. E.g. a satellite backup link may be given a cost of 10 hops so traffic prefers other routes.

RIP has an Administrative Distance (AD) of 120 and uses port 520 (Beyond the deck over UDP, which is why UDP was listed among routing-update protocols in Unit 3).

11 · Link-state inside an AS

Open Shortest Path First (OSPF)

OSPF is a link-state routing protocol used to find the best path between routers within an Autonomous System (AS). OSPF routers establish neighbour relationships to exchange routing information, which leads to OSPF adjacencies. Hello packets are used for neighbour discovery and to set up communication. The neighbour states are key to forming adjacencies.

OSPF terms

Router ID

As the deck puts it, the highest active IP address on the router. The process first considers the highest loopback address; if none is configured, the highest active interface IP address is used.

Router priority

An 8-bit value used in the election of the DR and BDR on a broadcast network.

Designated Router (DR)

Elected to minimise the number of adjacencies. It distributes LSAs to the other routers and, on a broadcast network, handles Link State Requests and responds with updates.

Backup DR (BDR)

Backs up the DR; if the DR fails the BDR takes over its role.

DR and BDR election

Held on broadcast / multi-access networks, by these criteria:

  1. The router with the highest priority becomes the DR.
  2. On a tie, the router with the highest Router ID wins (highest loopback address, else highest active interface IP address).

OSPF neighbour states

StateWhat happens
DownNo Hello packets received on the interface. The initial state; adjacency process not started.
InitA Hello is received from another router, but the receiver is not yet listed in that neighbour's Hello. No bidirectional communication yet.
Two-WayBidirectional communication is confirmed: each router sees itself in the other's Hello. On broadcast / multi-access networks the DR and BDR election happens here.

How OSPF works: five steps

  1. Enable the local OSPF process and choose the RID: on start-up the process allocates a unique Router ID so it can send OSPF messages.
  2. Establish neighbour adjacencies: Hello messages are sent on all OSPF-enabled links; if other OSPF devices are on the same segment, the router tries to form adjacency with them.
  3. Exchange LSAs and build the topology table (LSDB): LSAs carry each directly connected link's cost and IP settings. Every router floods all LSAs until every device in the OSPF domain has them (LSA flooding). Since all LSAs reach every router in the area, all routers in an area hold the same LSDB.
  4. Execute the SPF algorithm: the LSDB is the input; the algorithm computes best paths from advertised link costs and creates the SPF tree from the local router's point of view.
  5. Update the routing table with the best paths from the SPF tree; forwarding decisions use the routing table.

Beyond the deck OSPF's default cost is derived from interface bandwidth (reference bandwidth ÷ interface bandwidth), and large networks are split into areas (a backbone Area 0 plus others) to keep the LSDB and SPF work manageable. OSPF runs directly over IP (protocol number 89).

12 · Routing between autonomous systems

Border Gateway Protocol (BGP)

BGP is the set of rules that determine the best network routes for data on the Internet. The Internet consists of thousands of private, public, corporate and government networks linked by standard protocols, so data crosses many networks before reaching its destination. BGP looks at all available paths and selects the best route.

Why BGP matters

The Internet is made of hundreds of thousands of autonomous systems (AS): smaller networks under the control of a single administrative entity, each uniquely identified by an AS number assigned by IANA. Data travels between ASes from source to destination. BGP lets each AS:

1. Find the best route

Each AS along the way decides where the packet goes next, based on factors such as geographical location, network congestion and data-transfer cost, so data takes the shortest route.

2. Discover network changes

The Internet is dynamic: ASes are constantly added and removed. BGP keeps each AS updated on new and obsolete routes.

3. Administer network policies

Administrators can set their own routing policies, e.g. distinguish routes internal and external to the AS, and decide whether data is routed internally or externally.

4. Add a layer of security

BGP can authenticate messages between routers using preconfigured passwords, verify messages from legitimate ASes and filter out unauthorised traffic.

How BGP works: peering

Administrators designate certain routers as BGP peers (BGP speakers). Peers perform three main functions:

  1. Route discovery: peers exchange routing information with neighbouring peers through NLRI (network-layer reachability information) and path attributes. NLRI carries connectivity information about neighbours; path attributes include latency, hop count and cost of transmission. Each peer can then build a graph of the connections around it.
  2. Route storage: every BGP router stores the route advertisements it collects in routing tables, used for path selection and updated frequently. E.g. keep-alive messages arrive from neighbours every 30 seconds (as per the deck) and the stored routes are updated accordingly.
  3. Path selection: routers use the stored information to route traffic optimally. The primary factor is the shortest path from the stored route graphs; when several paths exist, BGP picks the best by evaluating other path attributes in sequence.

Types of BGP

  • External BGP (EBGP): the session is between two neighbours in different autonomous systems.
  • Internal BGP (IBGP): the session is between two neighbours in the same AS.

Unit 4 — Summary

  • Network layer = host-to-host delivery across networks via logical addressing and routing. Datagram networks route every packet independently (no set-up, may reorder); virtual circuits set up a path and reserve resources first.
  • IPv4: 32-bit dotted-decimal addresses with network / host parts, classes A-E and subnetting; IPv6: 128-bit hex addresses, simpler header, flow label, no broadcast.
  • ICMP carries IP's error and diagnostic messages (ping = echo, traceroute = time exceeded).
  • Link-State: flood LSAs, build full map, run Dijkstra. Distance-Vector: Bellman-Ford with neighbours only, prone to count-to-infinity (split horizon, poison reverse, triggered updates, hold-down).
  • Internet routing: RIP (distance vector, hop count, max 15), OSPF (link state, inside an AS), BGP (path vector, between ASes, over TCP).
