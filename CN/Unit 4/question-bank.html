Q1Define network layer. L1 · 2 marks

The network layer is the 3rd layer of the OSI model. It is responsible for host-to-host delivery of packets across multiple networks, using logical (IP) addressing and routing to choose the path from source to destination. Its protocols include IP, ICMP, and routing protocols such as RIP, OSPF and BGP.

Q3Explain IPv4 addressing. L2 · 6 marks

An IPv4 address is a 32-bit logical address that identifies a device's connection to a network. It is written as four 8-bit octets in dotted-decimal notation (each 0 to 255), e.g. 185.107.80.231, which in binary is four groups of 8 bits.
  • Parts: a network part (identifies the network and its class), a host part (identifies the machine, unique within the network) and an optional subnet number (for dividing a large network into subnets).
  • Classful addressing: five classes. A starts with bit 0 (first byte 0-127), B with 10 (128-191), C with 110 (192-223), D with 1110 (224-239, multicast), E with 1111 (240-255, reserved).
  • Subnet mask / CIDR: a mask (or /n prefix) marks which bits are network bits, e.g. 172.16.5.120 with 255.255.0.0 (/16) has network address 172.16.0.0 and host ID 5.120.
Limitation: only 232 addresses, which is why IPv6 was introduced.

Q4Describe IPv6 features. L2 · 6 marks

IPv6 (developed by the IETF) is the latest version of IP, with a 128-bit address written as 8 groups of 16 bits in hexadecimal, separated by colons. Features:
  • Large address space: 128 bits, 296 times larger than IPv4's.
  • Better header format: options are moved out of the base header, so routing is simpler and faster.
  • New options and extensibility: the protocol can grow for new technologies and applications.
  • Resource allocation: the type-of-service field is replaced by traffic class and flow label, so real-time audio and video can get special handling.
  • Security: encryption and authentication give confidentiality and integrity.
  • Three address types: unicast (one interface), multicast (a group), anycast (one of a group, usually the nearest).

Q6Explain ICMP protocol. L2 · 6 marks

The Internet Control Message Protocol is a network-layer, connectionless protocol that supports IP. IP has no built-in mechanism for error and control messages, so routers and hosts use ICMP to report errors (destination unreachable, time exceeded, parameter problem) and for diagnostics.
  • Packet format: carried inside an IP datagram. Header: Type (8 bits), Code (8 bits), Checksum (16 bits), a 32-bit extended header (e.g. pointer to the error), then variable data (the offending IP header and part of its data).
  • Common types: 0 echo reply, 3 destination unreachable, 5 redirect, 8 echo request, 11 time exceeded, 12 parameter problem.
  • Tools: ping (echo request / reply, measures round-trip time) and traceroute (shows the route hop by hop).
  • Weakness: no authentication, so it can be abused: ping of death, ICMP/ping flood, smurf attack, ICMP tunnelling, router-advertisement spoofing.

Q7Discuss routing in computer networks. L2 · 6 marks

Routing is the process of selecting the path along which packets travel from source to destination; a routing algorithm computes the least-cost path and fills each router's routing / forwarding table. At each router the destination address is looked up in that table to find the next hop (forwarding).
  • Adaptive (dynamic) algorithms change routes as topology or load changes; non-adaptive (static) routes are computed in advance and loaded at boot; hybrid approaches combine both.
  • The main dynamic algorithms are Link-State (each router learns the whole map and runs Dijkstra) and Distance-Vector (routers share distance tables with neighbours; Bellman-Ford).
  • Routing in the Internet is hierarchical, split into autonomous systems: inside an AS, RIP (distance vector) or OSPF (link state); between ASes, BGP (path vector).

Q8Explain Link-State routing algorithm. L2 · 8 marks

In link-state routing every router learns the complete topology and independently computes shortest paths to all nodes (usually with Dijkstra's algorithm).
  1. Discovery: routers send Hello packets to find neighbours and form adjacencies.
  2. Flooding: each router floods Link State Advertisements / Packets (its links, their costs, its neighbours) to all routers; each stores them in the link-state database (LSDB), so all routers hold identical maps.
  3. SPF calculation: each router runs Shortest Path First (Dijkstra) on the LSDB to find the least-cost path to every destination and builds its forwarding table.
  4. Updates: on any change (link failure, new router) the affected router floods a new LSA and every router recomputes SPF.
  5. Aging: each LSA carries a time-to-live and is removed from the LSDB when it expires.
Dijkstra: start with the source in the set N'; repeatedly add the node with the smallest known cost and relax its neighbours using D(v) = min(D(v), D(w) + c(w,v)) until all nodes are included (worked example in the Numericals page).
Advantages: fast convergence, updates only on change, suits large networks. Disadvantages: more CPU and memory, more complex, vulnerable to spoofed LSAs. Example protocol: OSPF.

Q9Explain Distance Vector routing algorithm. L2 · 8 marks

In distance-vector routing each router keeps a table of destination, distance (cost), next hop and exchanges its distance vector only with its directly connected neighbours, periodically or on change. It rests on the Bellman-Ford equation: dx(y) = minv{c(x,v) + dv(y)}.
  1. Initially a router knows only cost 0 to itself and the costs to its direct neighbours.
  2. It sends its vector to its neighbours and receives theirs.
  3. For each destination it computes the cost through every neighbour and keeps the minimum, recording that neighbour as next hop.
  4. If its table changed, it sends the new vector; the process repeats until nothing changes (convergence).
Example: links A-B 1, B-C 1, A-D 4, D-C 1. A to C: via B = 1+1 = 2, via D = 4+1 = 5, so A uses B (cost 2).
Problem: count-to-infinity after a failure (routers keep raising each other's distance). Remedies: split horizon, route poisoning, poison reverse, triggered updates, hold-down timers, small infinity (RIP: 16). Example protocol: RIP.

Q11A large enterprise plans to migrate from IPv4 to IPv6 due to address exhaustion. Analyze the technical challenges involved and propose an effective migration strategy. L4 · 6 marks

Challenges:
  • Incompatibility: IPv4 and IPv6 hosts cannot talk directly; the header formats and address sizes differ.
  • Equipment and software: routers, firewalls, load balancers, monitoring tools and legacy applications may lack IPv6 support or hard-code IPv4 addresses.
  • Security: firewall and ACL rules must be rewritten for IPv6, ICMPv6 must be handled correctly, and running two stacks doubles the attack surface.
  • Addressing and routing: a new addressing plan, DNS (AAAA records), DHCPv6 / auto-configuration, and routing protocols that support IPv6 (OSPFv3, RIPng, BGP).
  • Cost and skills: hardware upgrades, staff training, testing and downtime risk.
Strategy (phased):
  1. Audit all devices and applications; upgrade or replace what cannot support IPv6.
  2. Obtain an IPv6 allocation and design a hierarchical addressing plan.
  3. Deploy dual stack first (IPv4 and IPv6 side by side), starting with the edge / internet-facing services.
  4. Use tunnelling to cross IPv4-only segments and translation (NAT64 / DNS64) for IPv6-only to IPv4-only communication.
  5. Update security policies, DNS and monitoring; pilot, then migrate departments gradually, and retire IPv4 only when no longer needed.

Q12A network administrator notices routing loops in a Distance Vector routing environment. Investigate the cause of the problem and recommend methods to avoid routing instability. L4 · 6 marks

Cause: distance-vector routers only know what their neighbours tell them. When a link fails, a router can accept a neighbour's stale advertisement that still shows a route through itself, then each router bases its distance on the other's. They keep increasing the metric (count-to-infinity); packets loop between them and convergence is very slow. Example: A loses its link to X; B still advertises distance 1 to X; A adopts 2 via B; B then adopts 3 via A; and so on (2, 3, 4, ... up to 16 in RIP).
Remedies:
  • Split horizon: do not advertise a route back out of the interface from which it was learned.
  • Route poisoning: advertise a failed route with an infinite metric.
  • Poison reverse: advertise the route back to the neighbour it came from, but with an infinite metric.
  • Triggered updates: send an update immediately after a significant change.
  • Hold-down timers: suppress possibly wrong information for a while after a failure.
  • Limit infinity (RIP: 16 hops) so the count stops; or move to a link-state protocol such as OSPF for large networks.

Q13During a cyberattack, routers in a network start receiving malformed packets. Explain how ICMP and routing protocols can help diagnose and mitigate the issue. L4 · 6 marks

ICMP for diagnosis:
  • Routers that drop a malformed packet can report it with ICMP Parameter Problem (type 12; pointer shows the bad byte, codes for missing option or bad length), Destination Unreachable (type 3) or Time Exceeded (type 11). Logging these shows the source, type and volume of the bad traffic.
  • Ping and traceroute locate which hop or path is affected or unreachable.
  • ICMP is itself abusable (ping of death, flood, smurf, tunnelling, router-advertisement spoofing), so unnecessary ICMP types should be filtered and rate-limited.
Routing protocols for mitigation:
  • Authenticate routing messages (RIPv2 authentication, OSPF authentication, BGP passwords) and filter routes so forged updates or spoofed LSAs cannot poison the tables.
  • Reroute: link-state / distance-vector protocols detect failed or overloaded links and recompute paths around the attacked segment; BGP policies can divert or drop traffic from the attacking AS.
  • Combine with access lists / firewalls dropping malformed packets and ingress filtering of spoofed source addresses (the TTL field also prevents endless looping).

Q14Analyze shortest path routing. L4 · 5 marks

Shortest-path routing models the network as a graph (routers = nodes, links = edges with a cost such as hop count, delay, bandwidth or money) and sends each packet along the least-cost path between source and destination.
  • Link-State: every router has the full graph and runs Dijkstra: grow a set of nodes with final least cost, always adding the closest remaining node and relaxing its neighbours (D(v) = min(D(v), D(w)+c(w,v))). Complexity O(n2), or O(E log n) with a heap.
  • Distance-Vector: routers use Bellman-Ford, dx(y) = min{c(x,v) + dv(y)}, without ever seeing the whole graph.
  • Analysis: gives optimal paths for the chosen metric and a loop-free tree; cost and metric choice decide behaviour. Weaknesses: needs accurate, up-to-date costs; load-based metrics can cause route oscillation; with distance-vector, count-to-infinity.
Example (Numericals page): from A, least costs B=2, C=3, D=1, E=2, F=4, with C reached via A-D-E-C rather than the direct cost-5 link.

Q15Evaluate routing algorithm performance. L5 · 5 marks

A routing algorithm is judged on these criteria:
  • Correctness and optimality: does it find the least-cost loop-free path? (Link-state: yes; distance-vector: yes once converged, but can loop while converging.)
  • Convergence speed: how fast all routers agree after a change. Link-state is fast; distance-vector is slow (count-to-infinity).
  • Stability and robustness: behaviour under failures, load changes, wrong or malicious information.
  • Overhead: control traffic, CPU and memory. Distance-vector is light but chatty (periodic updates); link-state needs a database and SPF computation but sends updates only on change.
  • Scalability: hierarchy (areas, autonomous systems) is needed for large networks; RIP is limited to 15 hops.
  • Simplicity and adaptivity: static routing is simple but cannot adapt; dynamic routing adapts at the price of complexity.
Verdict: link-state (OSPF) for large, fast-converging networks; distance-vector (RIP) for small, simple ones; path-vector (BGP) where policy between organisations matters.

Q16Illustrate subnetting with example. L3 · 8 marks

Subnetting divides one network into smaller subnetworks by borrowing bits from the host part and using them as a subnet number. It reduces broadcast traffic, improves security and management, and uses addresses efficiently. The subnet mask (1s = network + subnet bits, 0s = host bits) marks the split; network address = IP AND mask.
Example: divide 192.168.1.0/24 into 4 equal subnets.
  1. Need 4 subnets: 2b ≥ 4, so borrow b = 2 bits.
  2. New prefix /24 + 2 = /26, mask 255.255.255.192.
  3. Block size = 256 − 192 = 64; usable hosts per subnet = 26 − 2 = 62.

Q17Analyze packet forwarding process. L4 · 8 marks

Forwarding is the per-packet action of moving a packet from a router's input link to the correct output link. (Routing is the separate process that computes the tables.) In a datagram (IP) network:
  1. Sender host: creates the IP datagram with source and destination IP. If the destination is on the same subnet (checked with the mask) it is delivered directly (MAC found via ARP); otherwise it is sent to the default gateway router.
  2. Router receives the frame, verifies the header checksum, and strips the link-layer header.
  3. Decrements TTL; if it reaches 0 the packet is dropped and an ICMP Time Exceeded is sent to the source. The header checksum is recomputed.
  4. Table lookup: the destination address is matched against the forwarding table; when several prefixes match, the longest-prefix match wins (default route 0.0.0.0/0 if nothing else matches). The entry gives the next hop and output interface.
  5. Fragmentation: if the datagram is larger than the outgoing link's MTU it is fragmented (unless DF is set, then dropped and ICMP "fragmentation needed" returned).
  6. Output: the packet is queued on the output link (first-come first-served) and encapsulated in a new frame addressed to the next hop's MAC. Packets for unreachable destinations are dropped with ICMP Destination Unreachable.
  7. Repeats hop by hop until the destination router delivers it on the local network; the destination host reassembles fragments and passes the payload up (protocol field).
Each datagram is forwarded independently, so successive packets may take different routes if the tables change; a virtual-circuit network would instead use the VC table set up during connection set-up.

Q20Design a routing strategy for a smart city network that includes IoT devices, emergency services, and public Wi-Fi systems while ensuring scalability and reliability. L6 · 6 marks

  • Hierarchical, segmented addressing: use IPv6 (with IPv4 dual stack where needed) because of the vast number of IoT devices. Give each service its own prefix / VLAN / subnet: IoT sensors, emergency services, public Wi-Fi, city administration. Summarise prefixes at each level to keep routing tables small.
  • Routing protocol layout: a link-state IGP (OSPF with areas) in the city core and each district for fast convergence and scalability, one area per district / service; BGP towards ISPs and cloud / other agencies for policy-based, multi-homed Internet access.
  • Reliability: redundant links and routers (ring or mesh core, dual uplinks), fast failover (OSPF recalculates paths), second ISP for BGP multi-homing, redundant gateways.
  • Priority for emergency services: dedicated routes / separate VRF or VLAN, QoS (traffic class / flow label in IPv6) to give emergency traffic the highest priority, so congestion from public Wi-Fi or IoT never delays it.
  • Isolation and security: keep public Wi-Fi and IoT apart from emergency and administration networks with firewalls and ACLs; authenticate routing protocol messages; filter routes; rate-limit ICMP.
  • IoT specifics: low-power devices use gateways / aggregation, IPv6 auto-configuration and multicast to scale; use default routes towards the gateway to keep their tables tiny.
  • Operations: monitoring with ping / traceroute (ICMP) and plan capacity for growth.
