Numerical 1

Network address and Host ID (deck examples)

Rule: every 1 bit in the mask is a network bit, every 0 bit is a host bit. Network address = IP AND mask; Host ID = the remaining host bits.

(a) 172.16.5.120 with mask 255.255.0.0

IP = 172.16.5.120, mask = 255.255.0.0 (/16). Find the network address and Host ID.
  1. Count the mask bits255.255.0.0 = 11111111.11111111.00000000.00000000 → /16: first 16 bits network, last 16 bits host
  2. Network portion (keep the first 16 bits, zero the rest)172.16.|5.120 → 172.16.0.0
  3. Host portion5.120 = 00000101.01111000
Network address = 172.16.0.0; Host ID = 5.120

(b) 10.20.30.45 with mask 255.0.0.0

IP = 10.20.30.45, mask = 255.0.0.0 (/8). Find the network address and Host ID.
  1. Count the mask bits255.0.0.0 = 11111111.00000000.00000000.00000000 → /8: first 8 bits network, last 24 bits host
  2. Network portion10.|20.30.45 → 10.0.0.0
  3. Host portion20.30.45 = 00010100.00011110.00101101
Network address = 10.0.0.0; Host ID = 20.30.45

Numerical 2 Beyond the deck

Network address, broadcast address and usable hosts

(a) 192.168.10.77/26

IP = 192.168.10.77, prefix /26. Find mask, network, broadcast, first/last usable host, number of usable hosts.
  1. Mask for /2626 ones = 11111111.11111111.11111111.11000000 = 255.255.255.192
  2. Network address: AND the last octet77 = 01001101; 192 = 11000000; AND = 01000000 = 64 → 192.168.10.64
  3. Broadcast: set all 6 host bits to 101111111 = 127 → 192.168.10.127
  4. Usable range192.168.10.65 to 192.168.10.126
  5. Usable hosts2^(32−26) − 2 = 2^6 − 2 = 64 − 2 = 62
Network = 192.168.10.64; Broadcast = 192.168.10.127; Hosts = .65 – .126 (62 usable)

(b) 130.45.151.154/20 (mask not on an octet boundary)

IP = 130.45.151.154, prefix /20.
  1. Mask for /2011111111.11111111.11110000.00000000 = 255.255.240.0
  2. Third octet: 151 AND 240151 = 10010111; 240 = 11110000; AND = 10010000 = 144 → network 130.45.144.0
  3. Broadcast: host bits (4 in octet 3 + 8 in octet 4) all 1third octet 10011111 = 159, fourth 255 → 130.45.159.255
  4. Usable hosts2^12 − 2 = 4096 − 2 = 4094 (130.45.144.1 to 130.45.159.254)
Network = 130.45.144.0; Broadcast = 130.45.159.255; 4094 usable hosts

Link-state: Dijkstra's shortest path from A

Link costs: A–B 2, A–C 5, A–D 1, B–C 3, B–D 2, C–D 3, C–E 1, C–F 5, D–E 1, E–F 2. Notation: D(v) = least cost known to v, p(v) = predecessor. Compute least-cost paths from A.
  1. Initialisation, N' = {A}D(B)=2,p=A; D(C)=5,p=A; D(D)=1,p=A; D(E)=∞; D(F)=∞
  2. Add D (smallest = 1), N' = {A,D}. Relax D's neighboursB: min(2, 1+2=3) = 2; C: min(5, 1+3=4) = 4,p=D; E: 1+1 = 2,p=D
  3. Add B (2; tie with E, take B), N' = {A,D,B}. RelaxC: min(4, 2+3=5) = 4 (no change)

  5. Add C (3), N' = {A,D,B,E,C}. RelaxF: min(4, 3+5=8) = 4 (no change)

Numerical 7

Distance-vector: Bellman-Ford rounds (deck network)

Links (deck example): A–B = 1, B–C = 1, A–D = 4, D–C = 1. Each router starts knowing only itself (0) and its direct neighbours, then repeatedly applies dx(y) = min over neighbours v of { c(x,v) + dv(y) } using the neighbours' vectors from the previous round. Entries are cost (next hop).
  1. Round 0: initial vectors (∞ = not yet known)A: A=0, B=1, C=∞, D=4 | B: A=1, B=0, C=1, D=∞ | C: A=∞, B=1, C=0, D=1 | D: A=4, B=∞, C=1, D=0
  2. Round 1: example, A to Cvia B: c(A,B) + d_B(C) = 1 + 1 = 2; via D: c(A,D) + d_D(C) = 4 + 1 = 5 → min = 2 (next hop B)
  3. Round 1: the other new entriesB→D: via C = 1+1 = 2 (C); C→A: via B = 1+1 = 2 (B); D→B: via C = 1+1 = 2 (C). A→D stays 4: via B would be 1+∞.
  4. Round 2: example, D to Adirect: 4; via C: c(D,C) + d_C(A) = 1 + 2 = 3 → min = 3 (next hop C). Likewise A→D via B: 1 + d_B(D) = 1 + 2 = 3 (B)
  5. Round 3: recompute every entryno entry changes → the network has converged

Numerical 8

Count-to-infinity and poison reverse

Routers A, B, C in a line, A–B = 1, B–C = 1; network X hangs off A. Before failure: d_A(X) = 0, d_B(X) = 1 (via A), d_C(X) = 2 (via B). The A–X link then fails. RIP's infinity is 16.

Without any fix (deck table)

  1. A detects the failured_A(X) = ∞; B has not heard yet and still says d_B(X) = 1
  2. A hears B's stale vectord_A(X) = c(A,B) + d_B(X) = 1 + 1 = 2
  3. B hears A's new valued_B(X) = 1 + 2 = 3
  4. A againd_A(X) = 1 + 3 = 4; then B = 5, A = 6, B = 7, A = 8 …

The distances climb by 2 per exchange until they hit infinity (16 in RIP); packets for X loop between A and B meanwhile

With split horizon + poison reverse

  1. Normal advertisement from B to A (B reaches X through A)B tells A: d(X) = ∞ (poisoned), instead of 1
  2. A's link to X failsA has d_A(X) = ∞ and B's advertisement is also ∞ → A has no alternative route
  3. A advertises to BB hears X = ∞ from its next hop A → d_B(X) = ∞; on the next update C also learns d_C(X) = ∞
No counting: X becomes unreachable at A, B and C within a couple of updates (triggered updates make it immediate)

Poison reverse stops two-router loops like this one. Loops through three or more routers can still occur, which is why hold-down timers and a small "infinity" are used as well.
