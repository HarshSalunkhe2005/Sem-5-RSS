Q1. 172.16.0.0/16, 32 customers x 512 addresses

An ISP is granted the block 172.16.0.0/16 (65,536 addresses). It must give 32 customers 512 addresses each. Find the prefix for each customer, the address range of each, the total addresses allocated, and what is left.

Step by step

  1. 512 = 29, so each customer needs 9 host bits.
  2. Prefix = 32 - 9 = /23. Mask = 255.255.254.0 (the 23rd bit sits in the third octet, so third-octet mask = 254).
  3. Usable hosts per customer = 512 - 2 = 510 (network and broadcast addresses excluded).
  4. Block size in the third octet = 256 - 254 = 2, so each block moves the third octet by 2.
  5. Customer n: 172.16.(2n-2).0 to 172.16.(2n-1).255. First address is the network address, last is the broadcast address.
  6. Total allocated = 32 x 512 = 16,384 addresses, which is 172.16.0.0 to 172.16.63.255.
  7. Remaining = 65,536 - 16,384 = 49,152 addresses, from 172.16.64.0 to 172.16.255.255.
CustomerNetwork addressFirst usableLast usableBroadcast
Answer: /23 (255.255.254.0), 510 usable hosts each, 16,384 allocated, remaining 172.16.64.0 to 172.16.255.255 = 49,152 addresses.

Q2. 10.10.0.0/16, 16 organisations x 1,024 addresses

An ISP is granted 10.10.0.0/16. It must give 16 organisations 1,024 addresses each. Find the prefix, each organisation's range, the total allocated and the remaining addresses.

Step by step

  1. 1,024 = 210, so 10 host bits.
  2. Prefix = 32 - 10 = /22. Mask = 255.255.252.0.
  3. Usable hosts = 1,024 - 2 = 1,022.
  4. Block size in the third octet = 256 - 252 = 4.
  5. Organisation n: 10.10.(4n-4).0 to 10.10.(4n-1).255.
  6. Total allocated = 16 x 1,024 = 16,384, which is 10.10.0.0 to 10.10.63.255.
  7. Remaining = 65,536 - 16,384 = 49,152 addresses, from 10.10.64.0 to 10.10.255.255.

Answer: /22 (255.255.252.0), 1,022 usable hosts each, 16,384 allocated, remaining 10.10.64.0 to 10.10.255.255 = 49,152 addresses.

Q3. 190.100.0.0/16, 64 customers x 256 addresses

An ISP is granted 190.100.0.0/16. It must give 64 customers 256 addresses each. Find the prefix, each customer's range, the total allocated and the remaining addresses.

Step by step

  1. 256 = 28, so 8 host bits.
  2. Prefix = 32 - 8 = /24. Mask = 255.255.255.0.
  3. Usable hosts = 256 - 2 = 254.
  4. Block size in the third octet = 1 (each customer is one full third-octet value).
  5. Customer n: 190.100.(n-1).0 to 190.100.(n-1).255.
  6. Total allocated = 64 x 256 = 16,384, which is 190.100.0.0 to 190.100.63.255.
  7. Remaining = 65,536 - 16,384 = 49,152 addresses, from 190.100.64.0 to 190.100.255.255.
CustomerNetwork addressFirst usableLast usableBroadcast
Answer: /24 (255.255.255.0), 254 usable hosts each, 16,384 allocated, remaining 190.100.64.0 to 190.100.255.255 = 49,152 addresses.

Source: Moodle CN, numerical examples.

General method (5 steps)

  1. Host bits: addresses per customer A = 2h. Find h (for 512 it is 9, for 1,024 it is 10, for 256 it is 8).
  2. Prefix and mask: prefix = 32 - h. Write the mask (the octet holding the boundary = 256 - block size).
  3. Block size: block = A / 256 in the third octet (512 gives 2, 1,024 gives 4, 256 gives 1). Each customer starts one block after the previous.
  4. Range of customer n: network = start + (n-1) x block; broadcast = network + A - 1. Usable hosts = A - 2.
  5. Totals: allocated = customers x A. Remaining = size of the parent block (2(32 - parent prefix), 65,536 for a /16) minus allocated. Remaining starts right after the last customer's broadcast address.

Check: last broadcast + 1 = start of the remaining block. Here every question uses 16,384 of 65,536, so the remainder is 49,152 and starts at third octet 64.
