01 · The end-to-end layer

Overview & Responsibilities

The Transport Layer is the 4th OSI layer — an end-to-end layer (point-to-point between source and destination host, not hop-to-hop like the network layer). Its unit of data is the segment.

Sender side: receives a message from the Application layer, segments it, adds source/destination port numbers to the header, hands it to the Network layer. Receiver side: reassembles segments, reads the header, identifies the port, forwards the message to the correct application.

1. Process-to-Process Delivery

Not enough to reach the right computer — data must reach the right process on it (browser vs. email vs. YouTube).

2. Multiplexing / Demultiplexing

Sender-side multiplexer merges many processes' data into one outgoing stream. Receiver-side demultiplexer uses the port number to route incoming data to the right process.

3. End-to-End Connection

TCP (connection-oriented, handshake-based) vs. UDP (stateless, best-effort) — the two main ways to establish this.

4. Congestion Control

Prevents/removes overload when too many sources send data and router buffers overflow. TCP uses "leaky bucket"-style control.

5. Data Integrity / Error Correction

Checksums detect corruption; ACK/NACK tells the sender whether data arrived intact.

6. Flow Control

Prevents a fast sender from overwhelming a slow receiver — via the sliding window protocol.

02 · Fast, no guarantees

User Datagram Protocol (UDP)

UDP is unreliable and connectionless — no handshake, no ordering guarantee, no confirmation of delivery. That's precisely why it's fast: no waiting, no retransmission logic, minimal overhead.

UDP header — 8 bytes, fixed

Source Port (16 bit)Destination Port (16 bit)
Length (16 bit) — UDP header + data
Checksum (16 bit) — optional in UDP

Compare: TCP's header ranges 20–60 bytes. UDP's checksum is not mandatory (unlike TCP) — UDP leans on IP/ICMP for error reporting instead.

Where UDP is actually used

VoIP

Skype/WhatsApp calls — a delayed packet is worse than a dropped one.

DNS

Small queries, need a fast response — no need for TCP's overhead.

DHCP

Small messages, occasional loss isn't critical.

Routing updates

RIP uses UDP for periodic table updates.

UDP checksum: both sides use one's-complement arithmetic over the header + pseudo-header + data. The full worked example (the classic Forouzan-style calculation) is on the Numericals page.

03 · Building reliability on an unreliable network

Reliable Data Transfer (RDT)

The network layer (IP) makes no reliability promises — RDT is how the transport layer builds a trustworthy channel on top of that anyway.

Error detection

Checksums flag corrupted packets so they can be retransmitted.

ACK / NAK

Receiver confirms success (ACK) or flags an error (NAK), prompting retransmission.

Sequence numbers

Keep data in the correct order and let duplicates be detected.

Retransmission

If no ACK arrives before a timer expires, the sender assumes loss and resends.

Flow control

Regulates transmission rate so the receiver isn't overwhelmed.

Congestion control

Adjusts transmission rate based on network conditions, not just the receiver's.

TCP bundles all of this in. ARQ (Automatic Repeat reQuest) protocols — Stop-and-Wait, Go-Back-N, Selective Repeat — are the specific retransmission strategies that implement it.

04 · Three ways to guarantee delivery

Stop-and-Wait, Go-Back-N & Selective Repeat

Stop-and-Wait ARQ

Sender sends one frame, then waits for its ACK before sending the next. Simple and reliable, but low throughput — the link sits idle while waiting.

TermFormula
Propagation DelayDistance between routers ÷ velocity of propagation
Round Trip Time (RTT)Time to reach receiver + time for ACK to return
Timeout (TO)2 × RTT
Time To Live (TTL)2 × Timeout (max 255 seconds)

Three classic problems: lost data (sender never gets an ACK, stalls), lost ACK (same stall, different cause), delayed ACK (a late ACK might be misread as acknowledging a different, more recent packet).

Sliding Window: Go-Back-N (GBN)

Sender can transmit up to N (window size) packets without waiting for individual ACKs — much better throughput than Stop-and-Wait (which is just GBN with N=1).

How loss is handled

If one packet is lost, the sender must resend that packet and every packet after it in the window — even if the later ones were received fine. Receiver window size is always 1 (out-of-order packets are discarded).

Key formulas

Efficiency = N / (1 + 2a), where a = Tp/Tt (propagation ÷ transmission delay). Sequence-number constraint: Ws + WR ≤ ASN; with WR=1, minimum sequence numbers = N+1, requiring ⌈log₂(N+1)⌉ bits.

Selective Repeat (SR)

Like GBN, the sender can transmit a full window without waiting — but on loss, only the specific lost/corrupted frame is retransmitted (receiver buffers out-of-order frames instead of discarding them). More efficient, but more complex — the receiver must sort buffered frames, and needs individual (not cumulative) ACKs.

05 · When the network itself is overloaded

TCP Congestion Control

TCP's congestion window (cwnd) controls how much data can be in flight before an ACK is needed. Three phases:

1. Slow Start

Exponential growth: cwnd doubles every RTT (1→2→4→8→…) until it hits the threshold (ssthresh).

2. Congestion Avoidance

Additive growth: past the threshold, cwnd increases by just 1 segment per RTT — much more cautious.

3. Congestion Detection

Multiplicative decrease: a needed retransmission signals congestion happened — cwnd is slashed, and TCP falls back to Slow Start or Congestion Avoidance.

A worked congestion-window growth sequence (Slow Start doubling, then Congestion Avoidance's +1 per RTT) is on the Numericals page.

Unit 3 — Summary

  • Transport = end-to-end (point-to-point host to host); Network = hop-to-hop
  • UDP trades reliability for speed; TCP builds full reliability via ACKs, sequence numbers, retransmission, and flow/congestion control
  • Stop-and-Wait is simple but slow (N=1); Go-Back-N and Selective Repeat pipeline multiple packets for much better throughput
  • TCP congestion control alternates exponential growth (Slow Start), cautious linear growth (Congestion Avoidance), and sharp cuts (on detected loss)
