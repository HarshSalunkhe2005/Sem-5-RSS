Unit 3: Transport Layer

Question Bank — CO3

All 20 questions, as given in the official question bank

Q1Define transport layer. L1 · 2 marks

The 4th OSI layer, providing end-to-end (point-to-point host-to-host) delivery of data between application processes, using segments as its unit of data.

Q2List responsibilities of transport layer. L1 · 4 marks

Process-to-process delivery, multiplexing/demultiplexing, end-to-end connection management, congestion control, data integrity/error correction, and flow control.

Q3Differentiate transport layer and network layer. L2 · 6 marks

Transport = end-to-end delivery between applications (TCP/UDP); Network = logical addressing and routing between networks (IP/ICMP). See the comparison table on the Unit 3 notes page.

Q4Explain UDP protocol. L2 · 6 marks

A connectionless, unreliable transport protocol with an 8-byte fixed header — no handshake, no guaranteed order or delivery, optional checksum. Trades reliability for speed and low overhead; ideal where occasional loss is acceptable (streaming, gaming, DNS).

Q5Describe UDP checksum process. L2 · 6 marks

Sender treats the segment as 16-bit words, sums them with one's-complement arithmetic, then complements the sum to get the checksum. Receiver repeats the sum including the checksum field itself — if the complemented result is all zeros, the data is accepted; any 1-bit means an error. Full worked example on the Numericals page.

Q6Evaluate congestion avoidance techniques. L2 · 6 marks

TCP's Congestion Avoidance phase grows cwnd additively (+1 segment per RTT) once past the slow-start threshold — much more cautious than Slow Start's exponential growth, aiming to probe for more bandwidth without triggering renewed congestion.

Q7Explain Stop-and-Wait protocol. L2 · 6 marks

Sender transmits one frame, then waits for its ACK before sending the next — simple and reliable, but the link sits idle during each wait, giving low throughput (equivalent to GBN with window size N=1).

Q8Discuss Go-Back-N ARQ. L2 · 4 marks

Sender can transmit up to N packets without waiting for individual ACKs. On any loss, it must resend the lost packet and every packet sent after it in the window, even ones the receiver already got correctly — receiver window is always 1, so out-of-order packets are simply discarded.

Q9Explain Selective Repeat ARQ. L2 · 5 marks

Like GBN, sender transmits a full window without waiting — but only the specific lost/corrupted frame is retransmitted, since the receiver buffers out-of-order frames instead of discarding them. Needs individual ACKs and receiver-side sorting, making it more complex but far more bandwidth-efficient under loss.

Q10Compare Go-Back-N and Selective Repeat. L4 · 5 marks

See the comparison table on the Unit 3 notes page — key differences: what gets retransmitted on loss, receiver window size (1 vs. N), cumulative vs. individual ACKs, and whether out-of-order packets are discarded or buffered.

Q11Wireless file transfer with frequent retransmissions — compare GBN vs. SR performance. L4 · 6 marks

On a lossy wireless link, GBN wastes significant bandwidth (resending every packet after the lost one, even correctly-received ones), while Selective Repeat only resends the actual lost packet — SR performs noticeably better here, at the cost of needing more receiver buffering and per-packet ACK tracking.

Q12Discuss TCP congestion control. L2 · 4 marks

Three phases: Slow Start (exponential cwnd growth until ssthresh), Congestion Avoidance (linear +1/RTT growth past ssthresh), and Congestion Detection (multiplicative decrease — a needed retransmission signals congestion, so cwnd is cut and the sender falls back to an earlier phase).

Q13Analyze slow start algorithm. L4 · 5 marks

cwnd starts small (often 1 segment) and doubles every RTT that all segments are acknowledged — reaching a usable sending rate very quickly. This aggressive growth is deliberately capped at ssthresh, after which TCP switches to the far more cautious Congestion Avoidance phase. Worked growth sequence on the Numericals page.

Q14Online exam server congestion scenario — analyze TCP congestion control's stabilizing role. L4 · 6 marks

As retransmissions spike, TCP's congestion-detection phase kicks in for every affected connection: cwnd is multiplicatively cut, backing off the sending rate network-wide, which reduces router buffer pressure. Combined with each connection's Congestion Avoidance phase re-probing cautiously afterward, this self-stabilizes the network rather than letting congestion snowball.

Q15Illustrate TCP three-way handshake. L3 · 6 marks

SYN (client → server, "let's connect", proposes an initial sequence number) → SYN-ACK (server → client, acknowledges and proposes its own sequence number) → ACK (client → server, acknowledges the server's number) — after which both sides can exchange data reliably.

Q16Ultra-low-latency stock trading — TCP or UDP? L5 · 6 marks

Depends on the requirement: if even one dropped price update is unacceptable (correctness over speed), TCP's reliability is worth the latency cost. If the system can tolerate an occasional stale/dropped update in exchange for the lowest possible latency (treating each update as disposable once a newer one exists), UDP wins — many real trading systems actually use UDP with application-level sequencing for this reason.

Q17Fixed window size in a highly dynamic network — evaluate impact. L5 · 6 marks

A fixed window can't adapt: too small for the network's actual capacity wastes available bandwidth (link sits underutilized); too large risks overwhelming a receiver or congesting the network when conditions worsen. This is exactly why real TCP uses a dynamically adjusted window (via flow control's receive-window advertisement and congestion control's cwnd) rather than one fixed value.

Q18Compare TCP and UDP protocols. L4 · 8 marks

TCP: connection-oriented (handshake), reliable (ACKs, retransmission), ordered, flow/congestion-controlled, 20–60 byte header, higher overhead. UDP: connectionless, unreliable (best-effort), no ordering guarantee, no flow/congestion control, fixed 8-byte header, minimal overhead. TCP for correctness-critical apps (email, file transfer); UDP for latency-critical apps (streaming, gaming, VoIP).

Q19Design a reliable data transfer scenario. L6 · 5 marks

Combine sequence numbers (ordering + duplicate detection), checksums (error detection), ACK/NAK (confirm receipt), timers + retransmission (recover from loss), and a sliding-window protocol (GBN or SR, per throughput needs) — this is essentially what TCP implements as a complete package.

Q20Sender overwhelming receivers — design a TCP flow-control solution. L6 · 6 marks

Use TCP's built-in flow control: the receiver advertises its Receive Window (rwnd) — the spare room in its receive buffer — with every ACK. The sender must keep its unacknowledged data within that advertised window, so it naturally throttles down whenever the receiver's buffer starts filling up, preventing overwhelm without any application-level changes.
