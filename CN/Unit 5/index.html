01 · Moving frames across one link

Link Layer Basics

The Data Link Layer is the second layer of the OSI model. It is responsible for converting the data stream into signals bit by bit and sending that over the underlying hardware. At the receiving end it picks up the electrical signals from the hardware, assembles them into a recognisable frame format and hands it to the upper layer.

Two sub-layers

Logical Link Control (LLC)

Deals with protocols, flow control and error control.

Media Access Control (MAC)

Deals with the actual control of the media — who may transmit on a shared link and when.

Functions of the data-link layer

1. Framing

Takes packets from the Network layer and encapsulates them into frames, then sends each frame bit by bit on the hardware. The receiver assembles signals back into frames.

2. Addressing

Provides layer-2 hardware addressing. The hardware address is assumed to be unique on the link and is encoded into the hardware at manufacturing time.

3. Synchronization

When frames are sent on the link, both machines must be synchronized for the transfer to take place.

4. Error control

Signals may meet problems in transit and bits get flipped. These errors are detected and an attempt is made to recover the actual data bits. It also provides an error-reporting mechanism to the sender.

5. Flow control

Stations on the same link may have different speed or capacity. The layer ensures flow control so that both machines can exchange data at the same speed.

6. Multi-access

When hosts on a shared link transmit, collisions are very likely. The layer provides mechanisms such as CSMA/CD to access a shared medium among multiple systems.

Framing: how a receiver finds frame boundaries Beyond the deck

A frame is header | payload (the packet) | trailer. The receiver needs a way to know where one frame ends and the next begins. Standard methods:

  • Character (byte) count — a header field says how many bytes follow. Simple, but one corrupted count desynchronises everything after it.
  • Flag bytes with byte stuffing — frames start/end with a flag byte; if the flag (or the escape byte) appears in the data, an ESC byte is inserted before it.
  • Flag bits with bit stuffing — frames start/end with the flag 01111110; the sender inserts a 0 after every run of five consecutive 1s in the data, and the receiver removes it.

Bit-stuffing example: data 0110111110111111 becomes 011011111001111101 on the wire (a 0 is inserted after each run of five 1s). The receiver deletes a 0 that follows five 1s, so the data can never be mistaken for the flag 01111110.

Where it lives Beyond the deck: the link layer is implemented in the network adaptor (NIC); a MAC address is 48 bits (written as six hex bytes) and ARP maps an IP address to the MAC address on the same LAN. Typical link-layer services: framing, link access, reliable delivery on error-prone links (e.g. wireless), error detection/correction and flow control.

02 · Catching corrupted bits

Error Detection and Correction

Error detection ensures data is transmitted accurately without corruption. It works by adding extra (redundant) bits to the data so the receiver can verify its correctness. If errors are found, the receiver discards the frame and requests retransmission.

  • Detects errors caused by noise or interference.
  • Uses redundant bits for consistency checking.
  • Common methods: Parity check, Checksum, CRC.
  • Ensures data integrity and reliable communication.

Types of errors

1. Single-bit error

Only one bit of the transmitted data unit is altered (a 0 becomes 1 or vice versa), giving a corrupted data unit.

2. Multiple-bit error

More than one bit is affected. Rarer than single-bit errors, but can occur in high-noise or high-interference environments.

3. Burst error

Several consecutive bits are flipped, producing a sequence of consecutive incorrect values.

Error-detection methods in this unit

  1. Simple parity check
  2. Two-dimensional parity check
  3. Checksum
  4. Cyclic Redundancy Check (CRC)

Detection vs. correction Beyond the deck

Detection only tells the receiver that something is wrong (it then discards the frame and relies on retransmission/ARQ). Correction (forward error correction, FEC) lets the receiver also work out which bits are wrong and repair them without a resend, at the cost of more redundant bits. Two-dimensional parity is the simplest correcting scheme; Hamming codes are the classic one.

A code with minimum Hamming distance d can detect up to d − 1 bit errors and correct up to ⌊(d − 1)/2⌋ bit errors. No detection scheme is 100% reliable — an error pattern can occasionally slip through undetected.

03 · The cheapest check

Parity Checking

1. Simple parity check

Simple bit parity adds one extra bit to the data. In even parity: a 1 is added to the block if it contains an odd number of 1s, and a 0 if it contains an even number of 1s. This makes the total number of 1s even, which is why it is called even-parity checking. (Odd parity does the opposite — the total number of 1s is made odd.)

Example: data 1011001 has four 1s → parity bit 0 → codeword 10110010.

Advantages

Detects all single-bit errors and any odd number of bit errors.

Easy to implement in hardware and software; only one extra bit per data unit (e.g. per byte).

Fast to calculate and check, so errors are caught without significant delay.

Disadvantages

Cannot detect an even number of bit errors.

Deck example: data 101010 is sent as 1010101 (even parity). If two bits flip, giving 1111101, the receiver still counts an even number of 1s and wrongly concludes there is no error.

2. Two-dimensional parity check

Parity bits are calculated for each row (equivalent to a simple parity bit) and also for all columns; both sets are sent along with the data. At the receiving end the parity bits are recomputed on the received data and compared. A failing row plus a failing column pinpoints the bad bit, which can then be flipped back.

Advantages

Can detect and correct all single-bit errors.

Can detect two- or three-bit errors occurring anywhere in the matrix.

Disadvantages

Cannot correct two- or three-bit errors — it can only detect them.

If the error is in a parity bit itself the scheme does not work as intended.

Worked examples with a single-bit error located by row and column are on the Numericals page.

04 · Add, then complement

Checksum

The checksum method divides the data into equally sized segments and uses 1's complement arithmetic to calculate the sum of these segments. The calculated checksum is sent along with the data. At the receiver the same process is repeated; if the result is all zeros the data is correct.

At the sender

  1. Divide the data into k segments of m bits each.
  2. Add the segments using 1's complement arithmetic to get the sum.
  3. Complement the sum — that is the checksum.
  4. Send the checksum segment along with the data segments.

At the receiver

  1. Add all received segments (data + checksum) using 1's complement arithmetic.
  2. Complement the sum.
  3. If the result is zero, accept the data; otherwise discard it.

1's-complement addition: add normally; if there is a carry out of the leftmost bit, add that carry back into the least-significant bit (end-around carry). The Internet checksum used by IP, TCP and UDP does this on 16-bit words. Worked 8-bit and 16-bit examples are on the Numericals page.

Strengths and weaknesses Beyond the deck

  • Very cheap to compute in software, which is why transport and network layers use it.
  • Weaker than CRC: the sum does not depend on word order, so swapping two words, or two compensating bit flips in the same column, can go unnoticed.
  • Link layers prefer CRC because it is computed in hardware and detects burst errors much better.

05 · Division, not addition

Cyclic Redundancy Check (CRC)

Unlike the checksum scheme, which is based on addition, CRC is based on binary division. A sequence of redundant bits — the CRC bits — is appended to the end of the data unit so that the resulting data unit becomes exactly divisible by a second, predetermined binary number (the generator / divisor).

At the destination the incoming data unit is divided by the same number. If there is no remainder, the data unit is assumed correct and is accepted. A remainder means the data unit was damaged in transit and must be rejected.

CRC working

Given a dataword of length n and a divisor of length k:

  1. Step 1: append k − 1 zeros to the original message.
  2. Step 2: perform modulo-2 division (XOR, no borrows or carries).
  3. Step 3: the remainder of the division is the CRC.
  4. Step 4: codeword = original data followed by the CRC (the data with the appended zeros replaced by the CRC).

Note: the CRC is exactly k − 1 bits long, and the codeword length is n + k − 1 bits.

The deck's example

Data to send = 1010000, divisor given as the polynomial x³ + 1 (binary 1001, so k = 4).

  • Append k − 1 = 3 zeros → 1010000000.
  • Modulo-2 divide by 1001 → remainder 011 (full steps on the Numericals page).
  • Codeword sent = 1010000 + 011 = 1010000011.
  • Receiver divides 1010000011 by 1001 → remainder 0 → accept.

Polynomial form: a bit string is read as a polynomial, one bit per power of x. So 1001 = x³ + 0x² + 0x + 1 = x³ + 1. The generator 10011 = x⁴ + x + 1.

Why CRC is strong Beyond the deck

  • With a generator of degree r (r check bits) it detects every burst error of length ≤ r.
  • A burst of length r + 1 is missed with probability 2−(r−1); longer bursts with probability 2−r.
  • A well-chosen generator catches all single-bit and all odd-numbered bit errors (when divisible by x + 1).
  • Ethernet's frame check sequence (FCS) is a 32-bit CRC (CRC-32), computed in hardware by the NIC.

06 · Sharing one channel

Multiple Access & Random Access Protocols

Multiple access protocols operate in the Medium Access Control (MAC) sub-layer and allow a number of nodes or users to access a shared network channel. Several data streams originating from several nodes are transferred through the multi-point channel. Their objectives are: optimisation of transmission time, minimisation of collisions and avoidance of crosstalk.

Three categories

Random access

No station has priority; any station sends depending on whether the medium is idle or busy. ALOHA, CSMA, CSMA/CD, CSMA/CA.

Controlled access

Stations take turns, so there are no collisions. See Taking-turns protocols.

Channelization

The channel is divided by frequency, time or code among stations Beyond the deck (FDMA / TDMA / CDMA).

1. Random access protocol

All stations have the same superiority — no station has more priority than another. Any station can send data depending on the medium's state (idle or busy). It has two features:

  • There is no fixed time for sending data.
  • There is no fixed sequence of stations sending data.

ALOHA

ALOHA was designed for wireless LANs but is applicable to any shared medium. Multiple stations can transmit at the same time, which can lead to collisions and garbled data.

Pure ALOHA

A station sends whenever it has data and then waits for an acknowledgement.

If the ACK does not arrive within the allotted time, the station waits a random back-off time (Tb) and resends. Because different stations wait different amounts of time, the probability of a further collision decreases.

Slotted ALOHA

Similar to pure ALOHA, except that time is divided into slots and sending is allowed only at the beginning of a slot.

A station that misses its slot must wait for the next one. This reduces the probability of collision.

CSMA — Carrier Sense Multiple Access

CSMA ensures fewer collisions because a station must first sense the medium (idle or busy) before transmitting. If idle it sends; otherwise it waits until the channel becomes idle. However, a collision is still possible because of propagation delay: station A senses the channel idle and starts sending, but before A's first bit reaches B, station B also senses the channel idle and sends — the two frames collide.

CSMA persistence modes Beyond the deck

  • 1-persistent — keep sensing; as soon as the channel is idle, send immediately (probability 1).
  • Non-persistent — if busy, wait a random time and sense again.
  • p-persistent — when idle, send with probability p, otherwise defer to the next slot.

07 · Listen while talking (wired)

CSMA/CD — with Collision Detection

Carrier sense multiple access with collision detection: stations can terminate transmission as soon as a collision is detected, instead of wasting time sending the rest of a corrupted frame.

How CSMA/CD works Beyond the deck

  1. Sense the channel; if it is idle, start transmitting (if busy, wait until idle).
  2. Keep listening while transmitting. If no other signal is heard for the whole frame, the frame is done.
  3. If another transmission is detected (a collision), stop at once and send a short jam signal so every station knows a collision occurred.
  4. Run binary exponential backoff: after the n-th collision pick K uniformly from {0, 1, …, 2m − 1} with m = min(n, 10), wait K × 512 bit times (51.2 µs on 10 Mbps Ethernet), then try again. After 16 failed attempts, give up and report an error.

Minimum frame size: a frame must last at least as long as the round-trip propagation time (Tt ≥ 2·Tp), otherwise a sender could finish transmitting before the collision signal returns. For 10 Mbps Ethernet, 2·Tp = 51.2 µs → 512 bits = 64 bytes. Beyond the deck

CSMA/CD suits wired, half-duplex shared media (classic Ethernet), where a node can transmit and receive at the same time. Fully switched, full-duplex Ethernet no longer needs it.

Numerical work (minimum frame size, backoff ranges and collision probabilities) is on the Numericals page.

08 · Avoid rather than detect (wireless)

CSMA/CA — with Collision Avoidance

What the deck says: carrier sense multiple access with collision avoidance. The process of collision detection involves the sender receiving acknowledgement signals: if there is just one signal (its own) the data was sent successfully, but if there are two signals (its own and the one it collided with) a collision has occurred. To distinguish these cases, a collision must have a large impact on the received signal.

Exam-safe version Beyond the deck: in a wireless LAN a node cannot reliably listen while it transmits (its own signal drowns out everything else, and hidden terminals cannot hear each other), so collisions cannot be detected — they must be avoided, and success is confirmed by a link-layer ACK.

IEEE 802.11 CSMA/CA procedure Beyond the deck

  1. If the channel is sensed idle for DIFS, transmit the whole frame (no collision detection).
  2. If the channel is busy, choose a random backoff counter and count it down only while the channel is idle (freeze it when busy). When it reaches 0, transmit.
  3. The receiver, after a short SIFS, returns an ACK.
  4. If no ACK arrives, assume a collision/loss, double the backoff window and retry.
  5. Optional RTS/CTS: the sender sends a short Request-To-Send, the receiver answers Clear-To-Send, and everyone who hears either one stays silent. This solves the hidden-terminal problem and means any collision only wastes a short RTS frame.

09 · No collisions, by design

Taking-Turns Protocols Beyond the deck

The deck lists controlled access protocols as a category but does not detail them. Taking-turns protocols avoid collisions by letting only one node transmit at a time, trying to combine the good points of channelization (no collisions) and random access (full channel for a lone sender).

Polling protocol

One node is the master (controller). It polls each other node in round-robin fashion: "you may send up to N frames". When a node has finished, the master polls the next one.

Pros: no collisions and no empty slots. Cons: polling overhead and delay (even when nobody has data), and the master is a single point of failure. Example: Bluetooth master/slave.

Token-passing protocol

No master. A small special frame, the token, circulates in a fixed order. A node may transmit only while it holds the token (for a limited time), then passes the token on.

Pros: decentralised and efficient. Cons: token overhead and latency, and the failure of one node (or a lost token) can bring the whole channel down until recovery. Examples: Token Ring, FDDI.

A third controlled-access method is reservation: time is divided into intervals and each interval starts with a short reservation period in which stations announce that they want to send.

10 · Internet over the cable-TV network

DOCSIS

Data Over Cable Service Interface Specifications (DOCSIS) is the technology used to communicate and transfer data across RF or coaxial cable at high speeds. It began with DOCSIS 1.0 in 1997 by CableLabs and was originally built on the pre-existing cable-TV infrastructure, which made roll-out possible. The standard is now in its third generation, with prospects for the future remaining bright.

Evolution of DOCSIS

VersionYearWhat the deck says
DOCSIS 1.01997Up to 40 Mbps downstream and 10 Mbps upstream; sufficient for the usage requirements of the time.
DOCSIS 1.1about two years laterSame bit rates (40 Mbps DS / 10 Mbps US) but allowed VoIP services for cable-TV subscribers.
DOCSIS 2.02002A wider band in the upstream channel and more effective modulation schemes → 40 Mbps download and 30 Mbps upload.
DOCSIS 3.02006Channel bonding — combining upstream and downstream channels; bonding 6 or 8 MHz channels gives higher speeds. Also enabled IP multicast, IPv6 and AES encryption.
DOCSIS 4.0published 2020Latest major version from CableLabs for very high-speed broadband over existing hybrid fibre-coaxial (HFC) networks; builds on 3.0/3.1 with much higher upstream capacity, better spectrum usage and near-symmetric multi-gigabit services.

Careful with the figures: the deck quotes DOCSIS 3.0 as "up to 340 Mb/s (440 Mb/s for EuroDOCSIS downstream and 120 Mbps upstream)". The wording is garbled in the slide, so quote it as "per the lecture deck" in exams; the key idea is that channel bonding multiplies the rate by combining several channels.

Architecture: how a cable access network works Beyond the deck

Homes connect through cable modems (CM) to the coax part of an HFC network; fibre carries the signal to a cable modem termination system (CMTS) at the cable headend, which acts like the ISP's access router.

  • FDM (frequency division multiplexing) divides the spectrum into several downstream and several upstream channels. In the textbook description each downstream channel is about 6 MHz wide (≈ 40 Mbps) and each upstream channel about 6.4 MHz (≈ 30 Mbps).
  • Downstream is a broadcast channel: the CMTS transmits to all modems on it, so there are no collisions; each modem picks out its own frames.
  • Upstream is shared by many modems, so it also needs a multiple-access protocol. Each upstream channel is divided into time slots (mini-slots).
  • The CMTS periodically sends a MAP message on the downstream channel saying which modem may transmit in which mini-slots. Because the CMTS decides, data transmission itself is collision-free.
  • To ask for upstream capacity, modems send request frames in dedicated contention mini-slots using random access with binary exponential backoff; requests can collide, but data cannot.

So DOCSIS is a hybrid: random access for reservation requests, then centrally scheduled (taking-turns / reservation style) transmission of the data.

11 · A network pretending to be a link

Link Virtualization Beyond the deck

The deck does not cover this topic; the following is the standard textbook idea. Virtualization means an abstract resource is created on top of a physical one. Link virtualization is the case where a whole network (made of switches, with its own protocols) is used by the layer above as if it were just a single link.

  • The network layer (IP) sends a datagram to the next hop over what it believes is a point-to-point link. In reality that "link" is a complete underlying network — historically ATM or frame relay, today MPLS/VPN services or a provider's Ethernet network.
  • Because IP only sees the virtual link, it treats the underlying network as a link-layer technology, and the provider can change the real network without changing IP.

Virtual LANs (VLANs) and overlays

VLAN (IEEE 802.1Q)

A switch is partitioned so ports belong to different logical LANs that share the same physical switches. Traffic between VLANs must pass a router (or Layer-3 switch). Frames on trunk links carry a 4-byte tag with a 12-bit VLAN ID (4094 usable VLANs).

Overlay (VXLAN, tunnels, VPNs)

Layer-2 frames of a tenant's logical network are encapsulated inside IP/UDP packets and carried over the shared physical network. VXLAN's 24-bit network identifier supports about 16 million logical networks — useful in data centres.

AdvantageWhy it helps
Isolation / securityDifferent clients or departments cannot see each other's broadcast traffic.
Resource sharingMany logical networks run over the same physical switches and cables, lowering cost.
FlexibilityMove a user or VM to another logical network by configuration, not by re-cabling.
Smaller broadcast domainsLess broadcast traffic and better performance.

12 · Forward by label, not by IP lookup

Multiprotocol Label Switching (MPLS) Beyond the deck

The deck does not cover MPLS; this is the standard textbook treatment. MPLS is a forwarding technique that uses a short fixed-length label, instead of the destination IP address, to forward packets. It was designed to speed up forwarding and, more importantly today, to enable traffic engineering and VPNs.

MPLS header (32 bits)

FieldSizePurpose
Label20 bitsIdentifies the forwarding path (FEC); used as the table index
TC (traffic class, formerly EXP)3 bitsQuality-of-service marking
S (bottom of stack)1 bit1 on the last label of the stack (labels can be stacked)
TTL8 bitsTime to live, like IP's

The MPLS header sits between the link-layer header and the IP header (so it is often called "layer 2.5").

How forwarding works

  1. The ingress label-edge router (LER) examines the IP packet, classifies it into a forwarding class (FEC) and pushes a label.
  2. Each label-switching router (LSR) on the path looks up only the incoming label in its table, swaps it for an outgoing label and sends the packet out the matching interface — no IP lookup.
  3. The egress LER pops the label and forwards the plain IP packet onward.

The path of labels is a label-switched path (LSP). Labels are distributed with a signalling protocol such as LDP or RSVP-TE; MPLS routers also use link-state routing (OSPF/IS-IS) with extensions.

Traffic engineering

Paths can be chosen by load, not just shortest path — traffic is steered around congested links.

Fast reroute

Pre-computed backup LSPs restore service within milliseconds after a link failure.

VPNs / QoS

Labels separate customers' traffic over a shared backbone and carry class-of-service information.

13 · Revise

Unit 5 — Summary

  • The link layer moves frames across one link; it has an LLC sub-layer (flow/error control) and a MAC sub-layer (media access).
  • Error detection adds redundant bits: parity (cheap; misses even-numbered errors), 2D parity (corrects single-bit errors), checksum (1's-complement sum, complemented) and CRC (modulo-2 division, strongest).
  • Random access: pure ALOHA (max 18.4%), slotted ALOHA (max 36.8%), CSMA, CSMA/CD (wired, detect and back off), CSMA/CA (wireless, avoid with backoff, ACK and RTS/CTS).
  • Taking-turns protocols (polling, token passing) avoid collisions entirely.
  • DOCSIS carries data over the cable-TV network using FDM channels, CMTS-scheduled mini-slots and channel bonding.
  • Link virtualization (VLANs, overlays) and MPLS (label switching) let one physical network behave as many logical ones.
