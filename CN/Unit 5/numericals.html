Numerical 1

Simple parity (even and odd) and its limit

(a) Even parity

Data = 1011001 (7 bits). Use even parity.
  1. Count the 1s1011001 → 1+0+1+1+0+0+1 = 4 ones
  2. Choose the parity bit so the total number of 1s is even4 is already even → parity bit = 0
  3. Codeword1011001 + 0 = 10110010
Even-parity codeword = 10110010 (four 1s)

(b) Odd parity

Data = 1010100 (7 bits). Use odd parity.
  1. Count the 1s1010100 → 3 ones
  2. Choose the parity bit so the total number of 1s is odd3 is already odd → parity bit = 0
  3. Codeword1010100 + 0 = 10101000 (three 1s)
Odd-parity codeword = 10101000

(c) Receiver check (even parity)

Sent 10110010. Case 1: received 10010010 (one bit flipped). Case 2: received 10011010 (two bits flipped).
  1. Case 1: count 1s in 100100101+0+0+1+0+0+1+0 = 3 → odd
  2. Case 1: decisionEven parity expected, got odd → error detected, frame discarded
  3. Case 2: count 1s in 100110101+0+0+1+1+0+1+0 = 4 → even
  4. Case 2: decisionParity looks fine → the 2-bit error is NOT detected (accepted wrongly)
An odd number of flipped bits is caught; an even number slips through

(d) The deck's own example

Data 101010, even parity. Codeword sent = 1010101. Two bits flip in transit → 1111101.
  1. Parity bit for 101010three 1s (odd) → parity bit = 1 → codeword 1010101
  2. Received 11111011+1+1+1+1+0+1 = 6 ones → even
  3. Receiver's conclusionEven count matches even parity → "no error", which is a wrong assumption (bits 2 and 4 were flipped)
Simple parity cannot detect an even number of bit errors

Numerical 3

Internet checksum (1's complement) — sender and receiver

(a) Sender side — 8-bit words

Four 8-bit words: 10011001, 11100010, 00100100, 10000100. Use 1's-complement addition (wrap any carry-out back into the LSB).
  1. Add word 1 (start from 0)00000000 + 10011001 = 10011001
  2. Add word 2 to the running sum10011001 + 11100010 = 101111011 → carry out: 01111011 + 1 = 01111100
  3. Add word 3 to the running sum01111100 + 00100100 = 10100000
  4. Add word 4 to the running sum10100000 + 10000100 = 100100100 → carry out: 00100100 + 1 = 00100101
  5. Checksum = one's complement of the sumcomplement(00100101) = 11011010
Checksum sent = 11011010

(b) Receiver side (no error)

Received words 10011001, 11100010, 00100100, 10000100 plus checksum 11011010.
  1. Add all five words (1's complement)sum of data words = 00100101; 00100101 + 11011010 = 11111111 (no carry)
  2. Complement the resultcomplement(11111111) = 00000000
  3. DecisionAll zeros → data accepted
Result = 00000000 → accepted

(c) Receiver side (one bit corrupted)

Word 2 arrives as 11100011 (last bit flipped from 0 to 1); everything else is unchanged.
  1. Add the four received data words (1's complement)sum = 00100110
  2. Add the received checksum00100110 + 11011010 → 00000001
  3. Complement the resultcomplement(00000001) = 11111110
  4. DecisionNot all zeros → error detected, segment discarded
Result = 11111110 → NOT zero → error detected

(d) The same method on 16-bit words (as in UDP/TCP/IP)

Three 16-bit words: 0110011001100110, 0101010101010101, 0000111100001111
  1. Word 1 + Word 20110011001100110 + 0101010101010101 = 1011101110111011 (no carry out)
  2. Add Word 31011101110111011 + 0000111100001111 = 1100101011001010 (no carry out)
  3. Checksum = complement of the sumcomplement(1100101011001010) = 0011010100110101
  4. Receiver adds all three words + checksum1100101011001010 + 0011010100110101 = 1111111111111111
  5. Complementcomplement(1111111111111111) = 0000000000000000 → accepted
  6. If the last bit of Word 1 flips to 1 in transitsum of words + checksum = 0000000000000001; complement = 1111111111111110 ≠ 0 → error detected
16-bit checksum = 0011010100110101; receiver gets all zeros when there is no error

Rule: sum all words with end-around carry; the sender transmits the complement. The receiver adds everything including the checksum — a sum of all 1s (complement = all 0s) means accept.

Numerical 4

CRC — polynomial division in GF(2) (modulo-2)

Example 1 — data 1101011011, generator 10011

Data = 1101011011, generator = 10011 (x⁴ + x + 1). Find the CRC and the codeword.
  1. Write the generator and count its lengthgenerator = 10011 → k = 5 bits (x⁴ + x + 1)
  2. Append k−1 zeros to the data1101011011 + 0000 = 11010110110000 (14 bits)
  3. Division step 1: leading 1 at bit 1 → align generator and XOR11010110110000 ⊕ 10011000000000 = 01001110110000
  4. Division step 2: leading 1 at bit 2 → align generator and XOR01001110110000 ⊕ 01001100000000 = 00000010110000
  5. Division step 3: leading 1 at bit 7 → align generator and XOR00000010110000 ⊕ 00000010011000 = 00000000101000
  6. Division step 4: leading 1 at bit 9 → align generator and XOR00000000101000 ⊕ 00000000100110 = 00000000001110
  7. Remainder = the last k−1 bits of the final line00000000001110 → remainder (CRC) = 1110
  8. Codeword = data + CRC1101011011 + 1110 = 11010110111110 (14 bits = n + k − 1)
CRC = 1110; transmitted codeword = 11010110111110

Example 1 — receiver verification

Received codeword = 11010110111110 (no error).
  1. Divide the received codeword by the same generator11010110111110 ÷ 10011 (mod 2)
  2. Step 1: XOR at bit 111010110111110 ⊕ 10011000000000 = 01001110111110
  3. Step 2: XOR at bit 201001110111110 ⊕ 01001100000000 = 00000010111110
  4. Step 3: XOR at bit 700000010111110 ⊕ 00000010011000 = 00000000100110
  5. Step 4: XOR at bit 900000000100110 ⊕ 00000000100110 = 00000000000000
  6. Read the remainderremainder = 0000 (all zeros) → codeword accepted
Remainder = 0000 → no error detected

Example 1 — receiver sees an error

Bit 4 is flipped in transit.
  1. Received codeword with bit 4 flipped11010110111110 → 11000110111110
  2. Step 1: XOR at bit 111000110111110 ⊕ 10011000000000 = 01011110111110
  3. Step 2: XOR at bit 201011110111110 ⊕ 01001100000000 = 00010010111110
  4. Step 3: XOR at bit 400010010111110 ⊕ 00010011000000 = 00000001111110
  5. Step 4: XOR at bit 800000001111110 ⊕ 00000001001100 = 00000000110010
  6. Step 5: XOR at bit 900000000110010 ⊕ 00000000100110 = 00000000010100
  7. Step 6: XOR at bit 1000000000010100 ⊕ 00000000010011 = 00000000000111
  8. Read the remainderremainder = 0111 ≠ 0 → corruption detected, frame discarded
Remainder = 0111 ≠ 0 → error detected

Subtraction in GF(2) is XOR (no borrows, no carries). A division step is only done when the leading bit of the working string is 1; if it is 0 just move on to the next bit.

CRC — the deck's example (x³ + 1)

Example 2 — the deck's example: data 1010000, generator x³ + 1

Data = 1010000, generator = 1001 (x³ + 1). Find the CRC and the codeword.
  1. Write the generator and count its lengthgenerator = 1001 → k = 4 bits (x³ + 1)
  2. Append k−1 zeros to the data1010000 + 000 = 1010000000 (10 bits)
  3. Division step 1: leading 1 at bit 1 → align generator and XOR1010000000 ⊕ 1001000000 = 0011000000
  4. Division step 2: leading 1 at bit 3 → align generator and XOR0011000000 ⊕ 0010010000 = 0001010000
  5. Division step 3: leading 1 at bit 4 → align generator and XOR0001010000 ⊕ 0001001000 = 0000011000
  6. Division step 4: leading 1 at bit 6 → align generator and XOR0000011000 ⊕ 0000010010 = 0000001010
  7. Division step 5: leading 1 at bit 7 → align generator and XOR0000001010 ⊕ 0000001001 = 0000000011
  8. Remainder = the last k−1 bits of the final line0000000011 → remainder (CRC) = 011
  9. Codeword = data + CRC1010000 + 011 = 1010000011 (10 bits = n + k − 1)
CRC = 011; transmitted codeword = 1010000011

Example 2 — receiver verification

Received codeword = 1010000011 (no error).
  1. Divide the received codeword by the same generator1010000011 ÷ 1001 (mod 2)
  2. Step 1: XOR at bit 11010000011 ⊕ 1001000000 = 0011000011
  3. Step 2: XOR at bit 30011000011 ⊕ 0010010000 = 0001010011
  4. Step 3: XOR at bit 40001010011 ⊕ 0001001000 = 0000011011
  5. Step 4: XOR at bit 60000011011 ⊕ 0000010010 = 0000001001
  6. Step 5: XOR at bit 70000001001 ⊕ 0000001001 = 0000000000
  7. Read the remainderremainder = 000 (all zeros) → codeword accepted
Remainder = 000 → no error detected

Cross-check with polynomials

Data 1010000 = x⁶ + x⁴; multiply by x³ → x⁹ + x⁷; divide by x³ + 1.
  1. Use x³ ≡ 1 (mod x³ + 1)x⁹ = (x³)³ ≡ 1, x⁷ = (x³)²·x ≡ x
  2. Add the residues (mod 2)x⁹ + x⁷ ≡ 1 + x
  3. Write as a 3-bit remainder (x² x¹ x⁰)1 + x → 0 1 1 → 011
Remainder 011 confirmed algebraically

Numerical 7

ALOHA — throughput of pure vs. slotted ALOHA Beyond the deck

(a) Throughput at given G

Frames are 200 bits on a 200 kbps shared channel. Frame time Tfr = 200 / 200,000 = 1 ms. Offered load: 1000, 500 and 250 frames/s (all stations together).
  1. Frame timeTfr = 200 bits / 200,000 bps = 0.001 s = 1 ms
  2. G = offered frames per frame time = (frames/s) × Tfr1000 → G = 1; 500 → G = 0.5; 250 → G = 0.25
  3. Pure ALOHA: S = G · e^(−2G)G=1: 1·e⁻² = 0.1353; G=0.5: 0.5·e⁻¹ = 0.1839; G=0.25: 0.25·e^(−0.5) = 0.1516
  4. Slotted ALOHA: S = G · e^(−G)G=1: 1·e⁻¹ = 0.3679; G=0.5: 0.5·e^(−0.5) = 0.3033; G=0.25: 0.25·e^(−0.25) = 0.1947
  5. Good frames per second = (frames/s offered) × e^(−2G) (pure) or × e^(−G) (slotted)pure: 135.3 / 183.9 / 151.6 frames/s; slotted: 367.9 / 303.3 / 194.7 frames/s
Pure S: 0.135, 0.184, 0.152. Slotted S: 0.368, 0.303, 0.195

(b) Maximum throughput

  1. Pure ALOHA: dS/dG = 0 → G = 1/2S_max = (1/2)·e⁻¹ = 1/(2e) = 0.1839 ≈ 18.4%
  2. Slotted ALOHA: dS/dG = 0 → G = 1S_max = 1·e⁻¹ = 1/e = 0.3679 ≈ 36.8%
  3. Compare0.3679 / 0.1839 = 2 → slotted ALOHA doubles the best-case throughput (vulnerable time halves: 2·Tfr → Tfr)
Pure max = 18.4% at G = 0.5; Slotted max = 36.8% at G = 1

(c) Slotted ALOHA with N stations

N = 10 stations, each transmits in a slot with probability p = 0.1.
  1. A slot succeeds only if exactly one station transmitsP(success) = N · p · (1−p)^(N−1)
  2. Substitute10 × 0.1 × 0.9⁹ = 1 × 0.387420… = 0.3874
  3. Interpretabout 38.7% of slots carry a good frame; with p = 1/N and N → ∞ this tends to 1/e ≈ 36.8% (the maximum)
P(success) = 0.3874 (≈ 38.7% of slots)

The deck explains how pure and slotted ALOHA behave but does not give the S = G·e^(−2G) and S = G·e^(−G) formulas; they are standard textbook results and are the usual exam numerical.

Numerical 8

CSMA/CD — minimum frame size and binary exponential backoff Beyond the deck

(a) Minimum frame size

Classic 10 Mbps Ethernet; worst-case one-way propagation delay Tp = 25.6 µs (so the round trip is 51.2 µs).
  1. Collision detection needs the sender to still be transmitting when the collision signal returnsTt ≥ 2·Tp
  2. Compute the round-trip time2·Tp = 2 × 25.6 µs = 51.2 µs
  3. Minimum frame = bandwidth × 2·Tp10×10⁶ bit/s × 51.2×10⁻⁶ s = 512 bits
  4. Convert to bytes512 / 8 = 64 bytes (the Ethernet minimum frame size)
Minimum frame size = 512 bits = 64 bytes

(b) Minimum frame size for a different LAN

Bus length 2 km, signal speed 2×10⁸ m/s, bandwidth 10 Mbps.
  1. Propagation delayTp = 2000 m / (2×10⁸ m/s) = 10 µs
  2. Round trip2·Tp = 20 µs
  3. Minimum frame size10×10⁶ × 20×10⁻⁶ = 200 bits (25 bytes)
Minimum frame size = 200 bits (theoretical, ignoring jam time)

(c) Binary exponential backoff after n collisions

Slot time = 512 bit times. At 10 Mbps one bit time = 0.1 µs, so one slot = 51.2 µs.
  1. Backoff slot (unit)512 bit times × 0.1 µs = 51.2 µs
  2. After the n-th collision pick K uniformly from {0, 1, …, 2^m − 1}, with m = min(n, 10)n = 1 → {0,1}; n = 2 → {0..3}; n = 3 → {0..7}; n = 4 → {0..15}
  3. Wait K × 51.2 µs, then sense the channel and retrylongest waits: n=1: 51.2 µs; n=2: 3×51.2 = 153.6 µs; n=3: 7×51.2 = 358.4 µs; n=4: 15×51.2 = 768 µs
  4. The range stops growing at n = 10max K = 1023 → max wait 1023 × 51.2 = 52,377.6 µs; attempts 11–15 reuse 0…1023
  5. After 16 failed attemptsthe NIC aborts and reports an error
Range doubles each collision: 0..1, 0..3, 0..7, 0..15 … capped at 0..1023, abort at 16

(d) Two stations collide: what happens next?

Stations A and B transmit together and collide (collision no. 1).
  1. Both choose K from {0, 1}4 equally likely pairs (K_A, K_B): (0,0), (0,1), (1,0), (1,1)
  2. They collide again only if K_A = K_BP = 2/4 = 1/2 (pairs (0,0) and (1,1))
  3. One station wins the next attempt if K_A ≠ K_BP = 2/4 = 1/2: the one with K = 0 sends immediately; the other waits 51.2 µs, senses the channel busy and defers
  4. If they collide a second time, K is drawn from {0..3}P(same K) = 4/16 = 1/4
  5. If a station draws K = 5 after its 3rd collisionit waits 5 × 51.2 µs = 256 µs
P(2nd collision) = 1/2, P(3rd | 2nd) = 1/4 — backoff spreads stations out quickly

The deck defines CSMA/CD in two lines; the frame-size rule and the backoff algorithm are the standard Ethernet details expected in numericals.
