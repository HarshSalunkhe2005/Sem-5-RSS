Unit 5: Link Layer

All 20 questions, as given in the official question bank

Q1Define link layer. L1 · 2 marks

The link layer (data link layer, OSI layer 2) is responsible for moving data across a single link between adjacent nodes: it converts the data stream into signals bit by bit, and at the receiver assembles the signals back into frames and hands them to the upper layer. It has two sub-layers: LLC (flow and error control) and MAC (control of the medium).

Q2Explain framing in data link layer. L2 · 4 marks

Framing: the data-link layer takes packets from the Network layer and encapsulates them into frames (header + payload + trailer), then sends each frame bit by bit on the hardware. At the receiver it picks up the signals and assembles them back into frames. The header carries the layer-2 (hardware) addresses and control information; the trailer carries the error-detection bits.

Beyond the deck To mark frame boundaries: (1) character count; (2) flag bytes with byte stuffing; (3) flag bits 01111110 with bit stuffing — a 0 is inserted after every five consecutive 1s in the data, e.g. 0110111110111111 is sent as 011011111001111101, and the receiver removes the stuffed 0.

Q3Describe parity checking. L2 · 4 marks

Parity adds one redundant bit so the receiver can check the data. Even parity: append 1 if the block has an odd number of 1s, 0 if it has an even number, so the total number of 1s is even (odd parity makes it odd). The receiver recounts the 1s; the wrong parity means an error.

Example: 1011001 has four 1s → parity bit 0 → 10110010.

  • Advantages: detects all single-bit errors and any odd number of errors; one extra bit per data unit; fast and easy.
  • Disadvantage: misses an even number of bit errors (deck example: 1010101 corrupted to 1111101 still shows even parity).

Two-dimensional parity adds parity per row and per column; it detects and corrects all single-bit errors and detects 2- and 3-bit errors.

Q4Explain checksum method. L2 · 6 marks

Checksum divides the data into equal segments and uses 1's-complement addition.

  • Sender: split the data into k segments of m bits; add them with 1's-complement arithmetic (carry out of the MSB is added back to the LSB); complement the sum to get the checksum; send the checksum with the data.
  • Receiver: add all received segments including the checksum, complement the result. All zeros means accept; otherwise discard.

Example (8-bit words): 10011001 + 11100010 + 00100100 + 10000100 = 00100101 (after end-around carries) → checksum = 11011010. Receiver: 00100101 + 11011010 = 11111111 → complement 00000000 → accepted. (Full steps on the Numericals page.)

It is cheap to compute in software, used by IP/TCP/UDP, but weaker than CRC.

Q5Discuss CRC error detection. L2 · 4 marks

CRC is based on binary (modulo-2) division, not addition. A sender-agreed generator (divisor) of k bits is used: append k−1 zeros to the data, divide modulo 2, and the remainder (k−1 bits) is the CRC; the codeword is the data followed by the CRC, so it is exactly divisible by the generator. The receiver divides the received codeword by the same generator: remainder 0 → accept, non-zero remainder → damaged, reject. Codeword length = n + k − 1.

Beyond the deck A generator with r check bits catches every burst error up to r bits long and all single-bit errors; Ethernet uses a 32-bit CRC computed in hardware.

Q6Apply CRC on a binary message. L3 · 4 marks

Message (data) = 1101011011, generator = 10011 (x⁴ + x + 1), so k = 5.

  1. Append k−1 = 4 zeros: 11010110110000.
  2. Modulo-2 division (XOR the generator at each leading 1):
    • 11010110110000 ⊕ 10011000000000 = 01001110110000
    • 01001110110000 ⊕ 01001100000000 = 00000010110000
    • 00000010110000 ⊕ 00000010011000 = 00000000101000
    • 00000000101000 ⊕ 00000000100110 = 00000000001110
  3. Remainder = last 4 bits = 1110.
  4. Transmitted codeword = 1101011011 + 1110 = 11010110111110.

Receiver check: dividing 11010110111110 by 10011 gives remainder 0000 → accepted. (A second example with the deck's data 1010000 and x³ + 1: CRC = 011, codeword 1010000011 — see the Numericals page.)

Q7Explain random access protocols. L2 · 6 marks

In random-access protocols all stations have equal priority; any station may send whenever the medium is idle or when it has data, with no fixed time and no fixed sequence of stations. Collisions can occur, so the protocol defines how to reduce them and recover.

  • Pure ALOHA: send at once, wait for an ACK; if none comes, wait a random back-off time Tb and resend.
  • Slotted ALOHA: time is divided into slots and a station may send only at the start of a slot, which reduces collisions. Beyond the deck Max throughput: pure 18.4% (1/2e), slotted 36.8% (1/e).
  • CSMA: sense the medium first; send if idle, wait if busy. Collisions are still possible because of propagation delay.
  • CSMA/CD: stop transmitting as soon as a collision is detected, then back off.
  • CSMA/CA: avoid collisions in advance (wireless).

Q8Discuss CSMA/CD protocol. L2 · 6 marks

Carrier Sense Multiple Access with Collision Detection: stations first sense the medium and can terminate transmission as soon as a collision is detected, instead of finishing a corrupted frame.

  1. Beyond the deck Sense the channel; send if idle, wait if busy.
  2. Listen while sending; if no collision, the frame completes.
  3. On collision, stop, send a short jam signal.
  4. Binary exponential backoff: after the n-th collision wait K × 512 bit times with K chosen from 0 … 2min(n,10) − 1; give up after 16 attempts.

Beyond the deck A frame must last at least 2·Tp so the sender is still transmitting when the collision signal returns (10 Mbps Ethernet: 512 bits = 64 bytes). It is used on wired, half-duplex Ethernet.

Q9Explain CSMA/CA protocol. L2 · 6 marks

Carrier Sense Multiple Access with Collision Avoidance. A wireless sender cannot reliably detect collisions while sending, so the protocol avoids them and uses acknowledgements to confirm success (the deck notes that the sender checks for acknowledgement signals; if only its own signal is seen the data was sent successfully).

Beyond the deck IEEE 802.11 procedure:

  1. If the channel is idle for DIFS, transmit the frame.
  2. If busy, choose a random backoff, count down only while idle, transmit at 0.
  3. Receiver sends an ACK after SIFS; no ACK means collision/loss, so double the backoff window and retry.
  4. Optional RTS/CTS handshake reserves the channel and solves the hidden-terminal problem.

Q11Explain taking-turns protocols. L2 · 6 marks

Beyond the deck Taking-turns (controlled-access) protocols let only one node transmit at a time, so there are no collisions.

  • Polling: a master node polls each other node in turn and lets it send up to a limited number of frames. Pros: no collisions or empty slots. Cons: polling overhead and delay, master is a single point of failure (e.g. Bluetooth).
  • Token passing: a small token frame circulates in a fixed order; only the holder may send, then it passes the token on. Pros: decentralised, efficient. Cons: token overhead and latency; one failed node or a lost token can stop the channel (Token Ring, FDDI).

Reservation is a third variant: stations announce in a reservation period which intervals they will use.

Q12Describe DOCSIS architecture. L2 · 6 marks

DOCSIS (Data Over Cable Service Interface Specifications) carries data over RF/coaxial cable using the existing cable-TV infrastructure; started with DOCSIS 1.0 in 1997 (CableLabs).

  • Evolution (deck): 1.0 – 40 Mbps down / 10 Mbps up; 1.1 – same rates plus VoIP; 2.0 (2002) – 40 down / 30 up; 3.0 (2006) – channel bonding, IP multicast, IPv6, AES encryption; 4.0 (published 2020) – near-symmetric multi-gigabit over HFC.
  • Beyond the deck Architecture: home cable modems connect over coax/HFC to a CMTS at the cable headend. FDM divides the spectrum into several downstream and upstream channels.
  • Downstream is a broadcast from the CMTS (no collisions). Upstream is divided into time mini-slots; the CMTS broadcasts MAP messages assigning mini-slots to modems, and modems request capacity in contention mini-slots using random access with binary backoff.

Q13A manufacturing plant using wireless communication experiences frequent collisions during data transmission. Analyze how CSMA/CA can improve network efficiency. L4 · 6 marks

Beyond the deck In a wireless plant, nodes cannot detect collisions while transmitting (radio cannot send and listen at once), and machines far apart may be hidden terminals. Collisions waste airtime and force retransmissions.

  • Carrier sensing plus IFS means a node transmits only when the channel is idle for DIFS.
  • Random backoff counted down only while idle spreads out nodes that were waiting, so they do not all start together when the channel frees up; the window doubles after each failure.
  • ACK after SIFS confirms delivery, so losses are recovered quickly.
  • RTS/CTS reserves the channel and silences hidden nodes; a collision then wastes only a short RTS frame instead of a long data frame.

Result: fewer and cheaper collisions and higher useful throughput, at the cost of some fixed overhead (IFS, ACK, RTS/CTS) which pays off when load is high or frames are long.

Q14A communication channel introduces burst errors in transmitted frames. Evaluate the effectiveness of parity, checksum, and CRC techniques for error detection. L4 · 6 marks

A burst error flips a run of consecutive bits.

MethodEffect on burst errors
Simple parityCatches the burst only if it flips an odd number of bits; a burst that flips an even number is missed, so about half of bursts slip through. Weak.
2D parityBetter, spreading bits over rows and columns, but some patterns are still missed. Moderate.
ChecksumDetects most bursts, but because it is a sum, compensating flips can cancel and word order is ignored. Moderate; good for software use.
CRCDetects every burst no longer than the CRC length r, and longer bursts with probability about 1 − 2−r. Strongest. Beyond the deck

Conclusion: CRC is the right choice for burst-prone channels; parity is the weakest. That is why link layers (Ethernet, Wi-Fi) use CRC.

Q15An Internet service provider wants to improve traffic engineering across its backbone network. Assess how MPLS can help optimize packet forwarding. L5 · 6 marks

Beyond the deck MPLS forwards packets by a short label in a 32-bit shim header (20-bit label, 3-bit TC, 1-bit S, 8-bit TTL) placed between the link-layer and IP headers.

  • Faster forwarding: label-switching routers do an exact-match label lookup and swap the label, instead of a longest-prefix IP lookup.
  • Traffic engineering: label-switched paths (set up with RSVP-TE/LDP) can be routed explicitly around congested links, so load is spread over several paths rather than all following the IP shortest path.
  • Fast reroute: pre-established backup LSPs restore service within milliseconds after a link failure.
  • QoS and VPNs: the TC bits mark class of service and label stacking isolates customer traffic on the shared backbone.

Assessment: MPLS gives the ISP control over paths and better link utilisation and resilience, at the cost of extra signalling and operational complexity.

Q17A cable Internet provider experiences unfair bandwidth allocation among users during peak hours. Explain how DOCSIS manages upstream and downstream communication to address this issue. L4 · 8 marks

Beyond the deck (DOCSIS basics are in the deck; the scheduling details are standard textbook material.)

  • Channels: frequency-division multiplexing splits the cable into several downstream and upstream channels, and DOCSIS 3.0 channel bonding lets a modem use several channels together for more capacity.
  • Downstream: the CMTS is the only transmitter, so it broadcasts to all modems with no collisions and can schedule and rate-limit each user.
  • Upstream: shared by many modems, so it is divided into time mini-slots. A modem requests mini-slots in contention slots (random access with binary backoff); the CMTS then publishes a MAP message on the downstream channel saying which modem may send in which mini-slots. Data transmission is therefore scheduled and collision-free.
  • Fairness: because the CMTS decides who gets mini-slots, it can enforce per-user rate limits and quality-of-service classes (DOCSIS 1.1 added QoS for services like VoIP), so a few heavy users cannot take all the capacity at peak time.

The provider can additionally add more bonded channels or split congested nodes (DOCSIS 3.x/4.0 give more spectrum).

Q18A data center wants to run multiple logical networks over the same physical infrastructure for different clients. Design a solution using link virtualization concepts and justify its advantages. L6 · 6 marks

Beyond the deck

  1. Per-client VLANs: assign each client its own VLAN ID (IEEE 802.1Q, 12-bit ID, 4094 usable). Switch ports for that client's servers are in that VLAN; the links between switches are trunks carrying tagged frames for all VLANs.
  2. Overlay for scale: where more than 4094 tenants or Layer-3 spanning is needed, use VXLAN: each tenant's Ethernet frames are encapsulated in UDP/IP with a 24-bit network ID (about 16 million networks).
  3. Inter-network traffic only through a router/firewall, so tenants stay isolated unless policy allows.
  4. Per-tenant rate limits / QoS on shared uplinks; optionally MPLS VPNs across sites.

Advantages: isolation and security (separate broadcast domains), efficient use of shared hardware and lower cost, flexibility (move a client or VM by configuration, no re-cabling), smaller broadcast domains and easier management.

Q19Design a frame delivery mechanism. L6 · 6 marks

Beyond the deck Design for delivering a packet over one link (Ethernet-style):

  1. Framing: encapsulate the network-layer packet into a frame: header (destination and source MAC addresses, type), payload, trailer (CRC). Mark boundaries with flag bits and bit stuffing.
  2. Addressing: use unique layer-2 hardware addresses; ARP finds the MAC address for the next-hop IP address.
  3. Medium access: on a shared medium sense the channel first (CSMA/CD for wired, CSMA/CA for wireless) and back off on collisions.
  4. Synchronization: a preamble lets receiver and sender clocks align.
  5. Error control: the sender computes a CRC over the frame; the receiver recomputes it, discards bad frames, and the sender retransmits when no ACK arrives (stop-and-wait or sliding window ARQ, mainly needed on error-prone links such as Wi-Fi).
  6. Flow control: the receiver tells the sender when to slow down (windowing or pause frames) so slower stations are not overwhelmed.
  7. Delivery: the receiver accepts the frame only if the destination MAC matches (or is broadcast), strips the header and trailer and passes the packet up.

Beyond the deck Example: one physical switch, two departments (Sales and Engineering) that need separate networks.

  1. Create the VLANs on the switch and put each port in its VLAN (access ports); hosts then see separate broadcast domains although they share the hardware.
  2. Configure a trunk to the router (router-on-a-stick) or a Layer-3 switch; frames carry a 12-bit VLAN ID in the 802.1Q tag.
  3. The router has one sub-interface per VLAN (192.168.10.1 and 192.168.20.1) and applies access rules; a Sales host cannot reach Engineering unless allowed.
  4. To extend the logical network over an IP network (another building or data centre), tunnel it with VXLAN or an MPLS VPN.

The result is two isolated logical networks over one physical infrastructure.
