Unit 2: Application Layer

Question Bank — CO2

All 20 questions, as given in the official question bank

Q1Define application layer. L1 · 2 marks

The topmost layer of the OSI model, where user-facing network applications (browsers, email clients, etc.) directly interact with the network — defining protocols like HTTP, SMTP, FTP, and DNS.

Q2Explain principles of network applications. L2 · 4 marks

Six core aspects govern application design: the application architecture, how processes communicate, the process-to-network interface, the transport services available to applications, the transport services actually provided by the Internet, and the application-layer protocols used.

Q3Describe HTTP protocol. L2 · 6 marks

HTTP (HyperText Transfer Protocol) is the application-layer protocol governing communication between web clients (browsers) and web servers, using a stateless request/response model over TCP. Released in 1991, evolved through five major versions (0.9 → 3).

Q4Explain HTTP request message format. L2 · 6 marks

A request has a start line (method + URI + version, e.g. GET /hello.htm HTTP/1.1), header fields (general/request/entity headers), and an optional body (e.g. form data on a POST).

Q5Explain HTTP response message format. L2 · 6 marks

A response has a status line (version + status code + message, e.g. HTTP/1.1 200 OK), header fields (general/response/entity headers), and a body carrying the actual content (HTML, JSON, files, etc.).

Q6Differentiate persistent and non-persistent HTTP. L4 · 5 marks

Non-persistent (HTTP/1.0 default): a new TCP connection is opened for every single request — high overhead. Persistent (HTTP/1.1's "keep-alive"): one TCP connection is reused across many requests, cutting connection-setup overhead significantly.

Q7Discuss web caching and its advantages. L2 · 6 marks

Web caching stores a copy of a response the first time it's fetched, serving that copy on later requests instead of re-fetching from the origin. Advantages: faster repeated page loads, reduced bandwidth cost, and less overall load on origin servers and the network.

Q8E-commerce slow-loading scenario — analyze HTTP/DNS/caching roles. L4 · 6 marks

Even with high bandwidth, slow loading can stem from: DNS resolution delay (uncached lookups), non-persistent HTTP connections (new TCP handshake per resource), or a cold cache (every asset re-fetched from origin). Fixes: enable HTTP/1.1+ persistent connections/multiplexing (HTTP/2), use a CDN with edge caching, and reduce DNS lookup chains.

Q9Explain SMTP protocol. L2 · 6 marks

SMTP is the application-layer protocol for exchanging email between mail servers — the client opens a TCP connection (port 25 traditionally, 587 for secure submission) and transfers the message; delivery can be end-to-end (between organizations) or store-and-forward (via intermediate MTAs within one).

Q10Describe DNS hierarchy. L2 · 6 marks

A tree: Root servers at the top → Top-Level Domain (TLD) servers (.com, .edu, .in) below them → Authoritative name servers at the bottom, which hold the actual IP address for a specific domain.

Q11Analyze DNS caching mechanism. L4 · 8 marks

Resolved records are cached locally (browser/OS/resolver) for a duration set by the record's TTL. This avoids repeated full-hierarchy lookups for the same domain, dramatically speeding up subsequent visits — but means DNS changes take up to one TTL period to propagate to clients holding a stale cached entry.

Q12Compare HTTP and FTP. L4 · 5 marks

HTTP is optimized for retrieving/displaying web content over a single connection per resource (historically) and is stateless. FTP is purpose-built for file transfer, using two separate connections (control on port 21, data on port 20), and maintains session state (logged-in user, current directory) across commands.

Q13Differentiate TCP and UDP sockets. L4 · 5 marks

A TCP socket (stream socket) gives reliable, connection-oriented, ordered delivery. A UDP socket (datagram socket) is connectionless, faster, but offers no delivery/order guarantees — the application must handle loss itself if it matters.

Q14Secure file-sharing for remote employees — FTP vs. P2P. L5 · 6 marks

FTP(S)/SFTP is more suitable here: centralized access control (usernames/passwords), audit-friendly (server logs every transfer), and encryption available (FTPS/SFTP) — important for corporate security policy. P2P lacks central control/audit and is better suited to open, decentralized sharing, not access-controlled corporate files.

Q15Video app using UDP with frame drops/jitter — would TCP help? L5 · 6 marks

Switching to TCP would likely make it worse for real-time video: TCP's retransmissions and in-order delivery introduce added delay (head-of-line blocking) when packets are lost — exactly wrong for real-time streaming, where a late frame is often worse than a dropped one. Better fixes: adaptive bitrate, forward error correction, or better congestion-aware UDP-based protocols (e.g. QUIC/HTTP-3 style).

Q16Design a socket-based multi-user chat application. L6 · 6 marks

A server socket listens on a fixed port; each connecting client gets a dedicated TCP socket (handled on its own thread/async task) for reliable, ordered message delivery; the server broadcasts each incoming message to all other connected client sockets. TCP guarantees messages arrive complete, in order, and without loss — essential so chat history stays consistent for every user.

Q17Analyze advantages of P2P over client-server. L4 · 8 marks

No single point of failure (no central server to crash), scales naturally as more peers add more capacity rather than overloading one server, and can be cheaper to operate (no dedicated server infrastructure needed) — traded off against harder security/access-control and content-discovery challenges.

Q18Banking app DNS resolution failures at peak — investigate & propose fault tolerance. L6 · 6 marks

Likely causes: authoritative server overload at peak query volume, or a single point of failure in the DNS setup. Fault-tolerant strategy: multiple redundant authoritative name servers (geographically distributed), appropriately tuned TTLs to balance caching vs. freshness, and a secondary/backup DNS provider.

Q19Design a simple client-server communication model. L6 · 6 marks

Client opens a TCP socket to the server's known IP:port → sends a request → server processes and sends a response on the same connection → connection closes (non-persistent) or stays open for further requests (persistent) — the same pattern HTTP itself follows.

Q20Create an application-layer architecture for email communication. L6 · 6 marks

Sender's User Agent → Mail Submission Agent → Client MTA → SMTP over TCP (port 587) → Server MTA (possibly via relays) → recipient's mailbox → recipient's User Agent retrieves via IMAP/POP3 — matching the SMTP flow on the Unit 2 notes page.
