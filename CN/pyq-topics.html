The OSI reference model Beyond the deck

OSI = Open Systems Interconnection, a 7-layer model by ISO. Each layer uses the services of the layer below and offers services to the layer above. The deck only mentions layers in passing (see Unit 1 protocols across layers, Unit 3 transport).

7

Framing, MAC addressing, error and flow control: Ethernet, PPP, HDLC
1

Bits on the medium: cables, hubs, Wi-Fi radio, RS-232

Mnemonic top to bottom: All People Seem To Need Data Processing. Data is called message / segment / packet / frame / bits as it goes down from layer 7 to 1.

Function of each layer

  1. Physical: sends raw bits as electrical, light or radio signals; defines connectors, voltage levels, bit rate and topology.
  2. Data link: turns bits into frames, adds hop-to-hop (MAC) addresses, detects errors, controls flow and access to the shared medium.
  3. Network: adds source and destination IP addresses and routes packets across networks.
  4. Transport: end-to-end delivery between processes using port numbers; segmentation, reliability (TCP), flow and congestion control.
  5. Session: opens, manages and closes the dialog between two applications.
  6. Presentation: makes the data understandable to both ends.
  7. Application: the interface to network services used by the user's programs.

Data link layer: framing, byte stuffing, bit stuffing Beyond the deck

Framing splits the stream of bits from the physical layer into frames so the receiver can tell where one frame ends and the next begins. A frame has header (addresses, control), payload and trailer (error-detection code). Methods: fixed-size frames, character (byte) count, flag with byte stuffing, flag with bit stuffing. Error control is in Unit 5 error detection and CRC; flow control is in the next section.

Why stuffing is needed

A flag pattern marks the frame boundary. If the payload happens to contain the same pattern, the receiver would wrongly end the frame early. Stuffing adds extra bits or bytes so the flag can never appear inside the data; the receiver removes them (destuffing).

Byte stuffing (character stuffing) example

Flag byte = F, escape byte = ESC. The sender inserts an ESC before any F or ESC found in the data.

Data: A F B ESC C
Stuffed: A ESC F B ESC ESC C
On the wire: F | A ESC F B ESC ESC C | F

Receiver: sees ESC, discards it and takes the next byte literally. Result: A F B ESC C, the original data.

Bit stuffing example

Flag = 01111110. Rule: after five consecutive 1s in the data, the sender always inserts a 0. Receiver: after five consecutive 1s, remove the following 0.

Data: 0 11111 1 0 11111 11 0 = 0111111011111110
Stuffed: 0 11111 0 1 0 11111 0 11 0 = 011111010111110110
On the wire: 01111110 | 011111010111110110 | 01111110

Check: the data has a run of six 1s (so a 0 is stuffed after the first five) and a run of seven 1s (a 0 is stuffed after the first five). 16 data bits become 18 stuffed bits, and the stuffed stream never contains six 1s in a row, so it cannot imitate the flag. Destuffing removes each 0 that follows five 1s and returns the original 16 bits.

Bit stuffing vs byte stuffing: why bit stuffing is better

  • It works on bits, so the frame can be any length; byte stuffing forces the frame to be a whole number of bytes.
  • It is independent of the character code (ASCII, Unicode or any binary data); byte stuffing is tied to 8-bit characters and a chosen flag and escape byte.
  • Lower overhead: each stuffing costs 1 bit instead of a whole extra byte (8 bits).
  • Simple to do in hardware; used by HDLC and PPP-style links.

Flow control and piggybacking Beyond the deck

Flow control stops a fast sender from overwhelming a slow receiver. At the data link layer the two classic schemes are below. The deck covers the same ARQ protocols at the transport layer: Unit 3 Stop-and-Wait, Go-Back-N, Selective Repeat, plus extra-topics scenario S8.

Stop-and-waitSliding window
IdeaSend one frame, wait for its ACK, then send the nextSend up to W frames before an ACK; window slides as ACKs arrive
UtilisationLow on long or fast links (link idle while waiting)High; pipelining keeps the link busy
ComplexityVery simple; 1-bit sequence numberNeeds sequence numbers and buffers
Best suitedShort links, low data rate, simple devicesLong-delay or high-bandwidth links

Where each sliding-window protocol is best suited (Paper 1 Q1b)

  • Go-Back-N: low error rate and a simple receiver with little buffer memory (receiver window = 1). A loss costs a whole window of retransmissions.
  • Selective Repeat: noisy or lossy, long-delay links (e.g. satellite) where resending only the lost frame saves bandwidth, and the receiver has the buffer space to hold out-of-order frames.

Piggybacking

In two-way (full-duplex) communication, instead of sending a separate ACK frame, the receiver delays the ACK and attaches it to the header of its own next data frame going the other way (the ACK field rides along with the data).

Without piggybacking:   A --data--> B,   B --ACK--> A,   B --data--> A,   A --ACK--> B   (4 frames)
With piggybacking:      A --data--> B,   B --data+ACK--> A,   A --data+ACK--> B            (3 frames)

Justification (Paper 3 Q1c): the ACK costs only a few header bits when carried inside a data frame, whereas a separate ACK frame uses its own header, trailer and channel access. So fewer frames are sent, header overhead falls, and bandwidth and processing are better used. Trade-off: the receiver must wait for outgoing data, and if none is ready within a timeout it sends a stand-alone ACK so the sender does not time out.

Common exam question: "Piggybacking is the better utilization of bandwidth. Justify" (Paper 3 Q1c, 3 marks). "How does ARQ work?" (Paper 2 Q1b). "Suitability of stop and wait ARQ in modern high-speed networks" (Paper 5 Q4b): simple, but the sender idles for a full round trip per frame, so utilisation is very low.

ARP: Address Resolution Protocol Beyond the deck

ARP finds the MAC (physical) address of a device on the same local network when only its IP address is known. A frame on the LAN needs a destination MAC, but applications and routing use IPs (see MAC vs IP vs port).

Why the request is a broadcast and the reply a unicast

  • Request = broadcast (destination MAC FF:FF:FF:FF:FF:FF): the sender does not know which device owns the target IP or its MAC (that is exactly what it is asking), so it cannot address anyone directly. Broadcasting reaches every host on the LAN; only the owner of the IP answers, the rest ignore it.
  • Reply = unicast straight to the requester: the request already carries the requester's IP and MAC, so the target knows exactly who asked. Sending the answer to everyone would waste bandwidth and interrupt every host for no reason.

Worked example

Host A: IP 192.168.1.10, MAC AA:AA:AA:AA:AA:01
Host B: IP 192.168.1.20, MAC BB:BB:BB:BB:BB:02 (A does not know it)
  1. A wants to send to 192.168.1.20 and finds no entry in its ARP cache.
  2. A broadcasts an ARP request (dest MAC FF:FF:FF:FF:FF:FF): "Who has 192.168.1.20? Tell 192.168.1.10 (AA:AA:AA:AA:AA:01)".
  3. Every host receives it. Only B matches the IP; others drop it. B also stores A's IP-to-MAC pair in its own cache.
  4. B sends a unicast ARP reply to AA:AA:AA:AA:AA:01: "192.168.1.20 is at BB:BB:BB:BB:BB:02".
  5. A saves the pair in its ARP cache and sends the data frame to BB:BB:BB:BB:BB:02.

ARP cache: a table of recent IP-to-MAC mappings kept by each host, so ARP is not repeated for every packet; entries expire after a short time because addresses can change. If the destination is on another network, the host ARPs for its default gateway's MAC instead and the router repeats ARP on the next network.

Common exam question: "Explain why an ARP request is sent as a broadcast and the reply as a unicast, using an example" (Paper 4 Q4, 6 marks).

SNMP: Simple Network Management Protocol Beyond the deck

SNMP is an application-layer protocol used to monitor and manage devices such as routers, switches, servers and printers from one central station.

ComponentRole
Manager (NMS)Management station run by the administrator; sends requests, receives responses and traps, shows alerts and reports
AgentSoftware on each managed device; collects local information and answers the manager
MIB (Management Information Base)The structured database of objects an agent exposes (interface status, traffic counters, CPU load, uptime), each identified by an object ID (OID) in a tree. SMI defines how objects are named and typed
 
  Manager (NMS)                                   Agent (router/switch/server) + MIB
      |---- GetRequest / GetNextRequest (UDP 161) ---->|   read a value
      |<--- GetResponse -------------------------------|
      |---- SetRequest (UDP 161) --------------------->|   change a value (configure)
      |<--- Trap (UDP 162): unsolicited alert ---------|   e.g. link down
  • GET (GetRequest, GetNextRequest): manager reads object values from the agent's MIB (polling).
  • SET: manager changes a value, e.g. disables an interface.
  • TRAP: agent sends an alert on its own when an event occurs, without being polled.
  • Runs over UDP (ports 161 and 162) to keep management traffic light.

Why it matters

Central monitoring of many devices; fault detection (traps tell you immediately); performance monitoring and capacity planning from traffic counters; remote configuration; accounting. Weakness: SNMPv1 and v2c send a plain-text "community string" as the only security; SNMPv3 adds authentication and encryption.

TELNET as a client/server application Beyond the deck

TELNET (TErminaL NETwork) lets a user log in to a remote machine and use it as if typing at its own keyboard. It is a client/server application over TCP, port 23.

  1. The user starts the TELNET client program and names the remote host (e.g. telnet host). The client opens a TCP connection to the TELNET server on port 23.
  2. The keystrokes typed by the user go to the local terminal driver, which passes them to the TELNET client. The client converts them into a universal format called the NVT (Network Virtual Terminal) character set, so every type of terminal and OS can interoperate without knowing the other's details.
  3. NVT data travels over TCP to the TELNET server on the remote host. The server converts NVT into the remote system's own format and hands it to a pseudo-terminal driver, which feeds the operating system as if the input came locally.
  4. The remote OS asks for a login name and password (sent through the same path), then runs the user's commands; the output goes back the same way: OS to server, NVT conversion, TCP, client, local terminal screen.
  5. Client and server can negotiate options (echo, terminal type) using control characters sent in-band. On logout, the TCP connection is closed.

Why TELNET is insecure: everything, including the username and password, travels as plain text, so anyone sniffing the path can read it. SSH (port 22) replaces it with encryption, server authentication and integrity protection, and is what is used today.

Common exam question: "Explain how TELNET functions as a client/server application, allowing a user to log on to a remote machine" (Paper 4 Q6, 6 marks). Sketch: terminal - client - TCP - server - pseudo-terminal - OS.

Email retrieval: POP3 vs IMAP Beyond the deck

SMTP, UA, MTA and MDA are covered in Unit 2 FTP and SMTP and extra-topics scenario S4. The gap is the last step: SMTP is a push protocol (sender to server, server to server); it cannot be used by the recipient to fetch mail. The recipient's UA pulls mail with POP3 or IMAP.

Steps to retrieve an email (Paper 4 Q6 OR)

  1. The sender's mail goes by SMTP through the MTAs to the recipient's mail server, where the MDA stores it in the recipient's mailbox.
  2. The recipient opens the mail client (UA), which opens a TCP connection to the mail server's retrieval service (POP3 port 110, IMAP port 143; 995 and 993 with TLS).
  3. The client authenticates with username and password.
  4. The client asks for the mailbox state/list of messages (POP3 STAT/LIST, IMAP folder list and headers).
  5. The client fetches the selected messages (POP3 RETR, IMAP FETCH) and the user reads them.
  6. The server marks or deletes messages as per the protocol (POP3 usually deletes after download; IMAP keeps them on the server), and the session is closed (QUIT/LOGOUT).

Reasons for transitioning to IPv6

  • Address exhaustion: 32 bits cannot cover the growing number of phones, IoT devices and servers; NAT only delays the problem and breaks end-to-end addressing.
  • Simpler, faster header processing in routers and extension headers for options.
  • Built-in support for multicast, anycast, auto-configuration, better QoS (traffic class, flow label) and IPsec.
  • Transition is gradual: dual stack, tunnelling and translation (see Unit 4).

P1Draw the OSI reference model and explain any three layers. Give protocol examples for each. (P1/P2 Q2)6 marks

Seven layers, top to bottom: Application, Presentation, Session, Transport, Network, Data link, Physical. Sender passes data down (each layer adds a header; the data link layer also adds a trailer); receiver passes it up, removing them.

  • Transport (4): process-to-process delivery using ports, segmentation, reliability, flow and congestion control. Protocols: TCP, UDP.
  • Network (3): logical (IP) addressing and routing of packets between networks. Protocols: IP, ICMP, OSPF, RIP.
  • Data link (2): framing, MAC addressing, error detection, flow and medium access control on each hop. Protocols: Ethernet, PPP, HDLC.

Others for reference: Application (HTTP, SMTP, DNS), Presentation (TLS, JPEG, encoding/compression/encryption), Session (NetBIOS, RPC; dialog control and checkpoints), Physical (cables, signals). Draw the 7 boxes as in the OSI section.

P2Explain the functions of the session and presentation layers. (P3 Q1b)3 marks

Session layer: establishes, maintains and terminates dialogs between applications; controls whose turn it is to send; inserts synchronisation checkpoints so a transfer can resume after failure.

Presentation layer: translates between data formats and character codes, encrypts and decrypts, and compresses and decompresses, so both ends understand the data.

P3Explain the requirement of stuffing at the data link layer and list the advantages of bit stuffing over byte stuffing. (P3 Q3)6 marks

Need: frames are delimited by a flag pattern (e.g. 01111110). If the data contains the same pattern, the receiver would end the frame early. Stuffing inserts extra bits or bytes so the flag never appears inside the data; the receiver removes them.

Byte stuffing: insert an ESC before any flag or ESC byte in the data. Example: A F B ESC C becomes A ESC F B ESC ESC C.

Bit stuffing: after five consecutive 1s insert a 0. Example: 0111111011111110 becomes 011111010111110110.

Advantages of bit stuffing: frames of any bit length; independent of character code; only 1 bit of overhead per stuffing instead of 8; easy hardware implementation.

P4What is bit stuffing? Give an example. (P4 Q1b)3 marks

Bit stuffing is a framing technique where the sender inserts an extra 0 after every run of five consecutive 1s in the data, so the flag 01111110 cannot appear in the payload. The receiver deletes the 0 that follows five 1s.

Example: data 01111110 (has six 1s) becomes 011111010 after stuffing (a 0 after the first five 1s), then is framed as 01111110 | 011111010 | 01111110. The receiver sees five 1s followed by 0, removes it, and gets 01111110 back.

P5Piggybacking is the better utilisation of bandwidth. Justify. (P3 Q1c)3 marks

In full-duplex communication the receiver, instead of sending a separate ACK frame, attaches the acknowledgment to its own next outgoing data frame. A data-plus-ACK frame costs only a few extra header bits, whereas a stand-alone ACK has its own header, trailer and channel access time.

So fewer frames are sent (3 instead of 4 in a data/data exchange), header overhead drops and the channel is used for useful data. If no data is ready, the receiver waits a short timeout and then sends a separate ACK.

P6Investigate the IPv4 header and explain all the fields with a diagram. (P3 Q5)7 marks

Draw the 32-bit-wide grid from the IPv4 header section: Row 1 Version (4), IHL (4), ToS/DSCP (8), Total length (16). Row 2 Identification (16), Flags (3), Fragment offset (13). Row 3 TTL (8), Protocol (8), Header checksum (16). Row 4 Source address (32). Row 5 Destination address (32). Then Options (variable) and data.

  • Version: 4. IHL: header length in 32-bit words (5 to 15, so 20 to 60 bytes).
  • ToS/DSCP: priority and QoS class. Total length: header + data, max 65,535 bytes.
  • Identification, Flags (DF, MF), Fragment offset: fragmentation and reassembly (offset in 8-byte units).
  • TTL: hop limit, decremented per router, discarded at 0. Protocol: 6 TCP, 17 UDP, 1 ICMP.
  • Header checksum: error check of the header only, recomputed at each hop.
  • Source and destination addresses: 32-bit IPs. Options: record route, source route, timestamp; padded.

P7Find the class of each IP address: (i) 227.12.15.89 (ii) 193.15.56.21. (P4 Q1d)2 marks

Look only at the first byte. Ranges: A 0-127, B 128-191, C 192-223, D 224-239, E 240-255.

  • (i) 227 is in 224-239, so Class D (multicast).
  • (ii) 193 is in 192-223, so Class C (default mask 255.255.255.0).

P8Explain why an ARP request is broadcast and the reply unicast, with an example. (P4 Q4)6 marks

ARP maps an IP address to a MAC address inside one LAN. The requester knows the target IP but not its MAC, so it cannot address a frame to it; the request is therefore broadcast to FF:FF:FF:FF:FF:FF so that whichever host owns the IP can answer. The reply is unicast because the request already carried the requester's IP and MAC; replying only to it avoids interrupting every other host and saves bandwidth.

Example: A (192.168.1.10, MAC AA..01) wants B (192.168.1.20). A broadcasts "Who has 192.168.1.20?". All hosts receive it, only B responds with a unicast "192.168.1.20 is at BB..02" to A. A stores the pair in its ARP cache and sends the data frame to BB..02. B also caches A's mapping.

P9What is unicast and multicast routing? (P1 Q1c)3 marks

Unicast routing: a packet goes from one source to exactly one destination; the router uses the destination address to find a single next hop in its forwarding table (e.g. web browsing).

Multicast routing: a packet goes from one source to a group of receivers identified by a group (Class D) address; routers build a distribution tree and copy the packet only where the path splits, so each link carries one copy. Hosts join groups with IGMP (e.g. live video, online lecture). Multicast saves bandwidth compared with sending a separate unicast copy to each receiver.

P10What is network topology? List the pros and cons of bus, star, ring and mesh. (P1 Q1a, P3 Q1a, P4 Q2)6 marks

Topology is the arrangement of the nodes and links of a network.

  • Bus: pro: cheap, little cable. Con: backbone fault stops everyone; collisions; hard to troubleshoot.
  • Star: pro: easy to add nodes, one link fault affects one node. Con: central hub or switch is a single point of failure.
  • Ring: pro: orderly access, predictable performance. Con: a break or one failed node can stop the ring; adding nodes is disruptive.
  • Mesh: pro: highest reliability, multiple paths, no bottleneck. Con: very costly; full mesh needs n(n-1)/2 links and n-1 ports per node.
  • Tree/hybrid: pro: scalable, faults isolated to a branch. Con: root failure splits the network, complex cabling.

P11Which is better for online multiplayer gaming, TCP or UDP, where responsiveness is critical and occasional loss is acceptable? (P4 Q1c)3 marks

UDP. Game state updates (positions, actions) are time-sensitive, and a late packet is useless because newer data replaces it. TCP would retransmit lost segments and deliver in order, so one lost packet stalls all later data behind it (head-of-line blocking) and adds delay. Its handshake, ACKs and congestion control add latency and jitter.

UDP is connectionless with an 8-byte header, no retransmission and no ordering delay, so latency is lowest. The game accepts occasional loss, or adds its own light reliability (sequence numbers, prediction) only for important events. TCP suits things that must arrive intact, such as login or chat. See extra-topics S6 and Unit 3 UDP.

P12Explain how TELNET works, and describe the steps to retrieve an email from the mail server. (P4 Q6 and OR)6 marks

TELNET

Client/server application over TCP port 23. The user's keystrokes go to the TELNET client, which converts them to the universal NVT format and sends them over TCP to the TELNET server on the remote host. The server converts NVT to the host's format and feeds the OS through a pseudo-terminal, as if typed locally; output returns the same way. The user logs in with username and password and runs commands remotely. It is insecure because all data, including passwords, is plain text; SSH (port 22) replaces it.

Email retrieval

SMTP delivers the mail into the recipient's mailbox on the mail server (push). The recipient's mail client then connects over TCP to the server using POP3 (port 110) or IMAP (port 143), authenticates, lists the mailbox, fetches the messages (RETR or FETCH) and closes the session. POP3 downloads and normally deletes the server copy; IMAP leaves mail on the server and keeps all devices in sync.
