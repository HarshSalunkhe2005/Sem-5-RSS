01 · The basics

What Is the Internet? What Is the Web?

The Internet is a global network of billions of computers and devices, all able to reach each other. The Web (World Wide Web) is not the same thing — it's a collection of websites you access through the Internet. Your browser isn't the Internet either; it's just an application that displays websites stored on it.

How a page actually loads

  1. Your device connects to a router/modem — the base connection to the Internet.
  2. You type a URL; your system sends a query to your ISP, which is linked to other servers that store/process data.
  3. The browser resolves that URL into a numeric IP address.
  4. The browser sends an HTTP request toward that address and requests a copy of the page.
  5. Data arrives as many small packets; the browser reassembles them (like a puzzle) into the page you see.

Protocols are the common language that lets wildly different hardware/software talk to each other — the same idea as two people using a shared third language despite different native tongues. Protocols are usually discussed in terms of which OSI layer they belong to.

Network-layer protocols

IP

Responsible for routing — the core network-layer protocol, but not the only one.

IPsec

A collection of protocols (ESP, AH, SA) that set up encrypted, authenticated IP connections over a VPN.

ICMP

Reports errors and status — e.g. tells the source when a router can't deliver a packet.

IGMP

Sets up one-to-many (multicast) connections, so many computers can receive packets aimed at one IP address.

Other well-known protocols

TCP

Transport-layer, reliable delivery. Referenced together with IP as "TCP/IP".

HTTP / HTTPS

Application-layer (layer 7) — HTTP is unencrypted; HTTPS fixes that using TLS/SSL for encryption.

UDP

Faster, less reliable transport alternative to TCP — used where speed beats reliability (streaming, gaming).

Routing protocols (what routers use)

ProtocolWhat it does
BGPBroadcasts which IP addresses a network controls, so routers decide which networks to route through.
EIGRPIdentifies distances between routers, auto-updates each router's routing table.
OSPFCalculates the most efficient route based on distance, bandwidth, etc.
RIPAn older, application-layer protocol that identifies distances between routers.

03 · The backbone

The Network Core

The Network Core is the central part of a network interconnecting sub-networks, moving huge volumes of data at very high speed across long distances (fiber optics, high-speed routers, optical links) — e.g. what carries a 4K YouTube stream without buffering.

Routing vs. Switching

Routing (by routers) determines the best path from source to destination. Switching (by switches) transfers packets between devices/interfaces within the network.

Protocol support

OSPF (Interior Gateway Protocol, within one organization/AS, uses Dijkstra's algorithm) vs. BGP (Exterior Gateway Protocol, connects different Autonomous Systems — how ISPs like Jio/Airtel exchange routing info).

Redundancy & reliability

Multiple paths between routers mean communication survives a single failure — e.g. a damaged fiber cable gets routed around automatically, often unnoticed by users.

Real examples

Internet backbone (submarine fiber cables), data-center interconnects (Google Cloud, Azure, AWS), and ISP core networks (Jio, Airtel, BSNL).

04 · Where users connect in

The Network Edge

The Network Edge is the boundary between your internal network and the wider Internet — where end-user devices actually connect in.

Three layers, one journey

1. Access Layer

Laptops, phones, IoT devices — connecting via Wi-Fi APs, Ethernet switches, routers.

2. Edge Layer

Edge routers/switches: connect local users to the Internet, forward packets to the core, run firewalls/NAT/VPN.

3. Core Layer

High-speed routers moving data between networks — fast, reliable packet forwarding.

Example path: Laptop → Wi-Fi Router (Access) → Edge Router (Network Edge) → Core Internet Network → destination server, and back the same way in reverse.

What the edge actually does

Security

Firewalls, IDS/IPS, VPN gateways, ACLs — blocks unauthorized access, filters malicious traffic.

Traffic management

QoS prioritizes important traffic (e.g. video call over file download); load balancing spreads requests across many servers.

Edge computing

Processing data close to where it's generated (not a distant cloud) — lower latency, faster response, less bandwidth used.

Delay (latency) — four components

Processing

Time for a router/switch to process the header, check errors, pick the next hop.

Queuing

Time a packet waits in a router's queue due to congestion.

Transmission

Time to push all the packet's bits onto the link — depends on packet size and link bandwidth.

Propagation

Time for the signal to physically travel the medium — depends on distance and propagation speed.

Total Delay = Processing + Queuing + Transmission + Propagation. Worked numericals — including this exact courier-delivery analogy turned into a calculation — are on the Numericals page.

Packet Loss

Packets fail to arrive due to congestion (routers/switches drop packets under overload), hardware failure (faulty routers/cables/NICs), or buffer overflow (a router's buffer fills up and any excess incoming packets are simply discarded).

Packet Loss vs. Delay

Packet LossDelay (Latency)
What happensPackets are completely lostPackets arrive, just late
Measured inPercentage (%)Milliseconds (ms)
CausesRetransmissions, missing dataSlow communication
Root causeCongestion, hardware failure, buffer overflowProcessing, queuing, transmission, propagation

Throughput

The actual data successfully transferred per unit time (bps/Kbps/Mbps/Gbps) — the real rate achieved, as opposed to bandwidth (the theoretical maximum). Four factors reduce it below bandwidth: bandwidth itself (the ceiling), latency (higher latency = lower effective throughput), packet loss (lost packets must be retransmitted, eating into effective throughput), and congestion (more users sharing a link = slower for everyone).
