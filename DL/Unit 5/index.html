01 · Why networks learned to see

Convolutional Neural Networks: Idea, Success & History

Definition. A Convolutional Neural Network (CNN) is a deep network whose early layers apply learned filters (kernels) that slide across the input (an image) and produce feature maps; later layers combine those maps into higher-level features and a classifier on top predicts the output. The key point from the deck: the filter weights are learned by backpropagation, not designed by hand.

How we arrived here — from fixed features to learned features

Raw pixels

Feed pixels straight to a classifier (car, bus, monument, flower). No useful structure extracted.

Hand-crafted features

Edge detector, SIFT / HOG: static feature extraction (no learning); only the classifier's weights are learned.

CNN

The kernel values themselves become parameters: learn these weights. Multiple kernels give multiple feature representations; multiple layers give a hierarchy of features, trained end to end by backpropagation.

How a CNN differs from a fully connected network

The deck poses the question: can we have a DNN that is complex (many non-linearities) but has fewer parameters, and is therefore less prone to overfitting? Answer: a CNN, because of two ideas.

Sparse connectivity

Each output unit looks at only a small local patch of the input (e.g. a 2×2 patch of a 4×4 image), not at every input as in a fully connected layer.

Weight sharing

The same kernel is reused at every position of the input, so the number of weights does not grow with image size. Multiple kernels on the same input give multiple feature maps.

Scale of the saving (worked, checked with Python). Connecting a 227×227×3 image (154,587 values) fully to a 55×55×96 layer (290,400 units) would need 154,587 × 290,400 ≈ 4.49 × 10¹⁰ weights. AlexNet's first conv layer produces the same 55×55×96 output with only 11×11×3×96 = 34,848 weights.

02 · The core operation

Convolution: Formulas, Padding, Stride & Output Size

1-D and 2-D convolution

1-D: s_t = Σ_{a=0}^{∞} x_{t−a} · w_{−a} = (x ∗ w)_t (slide a weight vector along a sequence and take a weighted sum at each position).

2-D: slide a kernel K over the image I; at each position multiply element by element and add: S_ij = (I ∗ K)_ij = Σ_a Σ_b I_{i+a, j+b} · K_{a,b}. With a 2×2 kernel [[w, x],[y, z]] on a 3×4 input [[a,b,c,d],[e,f,g,h],[i,j,k,l]] the first output is aw + bx + ey + fz, the next bw + cx + fy + gz, and so on.

Different kernels, different features

  • Blur: 3×3 kernel of all 1s (averaging) — blurs the image.
  • Edge detection: 3×3 kernel [[1,1,1],[1,−8,1],[1,1,1]] — detects edges.
  • Sharpening: 3×3 kernel [[0,−1,0],[−1,5,−1],[0,−1,0]] (the deck's padding example, p = 2, s = 1).
  • The deck also lists 16 directional edge/image kernels (W/Edge, NE/Edge, … ). In a CNN the kernel values are not chosen; they are learned.

3-D inputs and multiple filters (deck)

Important note. The input is 3-D (e.g. RGB) and the filter is also 3-D, yet the operation is still 2-D: the filter slides only vertically and horizontally, never along the depth, because the filter's depth equals the input's depth. Each filter gives one 2-D output; combining the outputs of K filters gives a 3-D output.

Terminology: input width/height/depth W_I, H_I, D_I; output W_O, H_O, D_O; filter spatial extent F; number of filters K; padding P; stride S.

Output-size formulas (deck)

CaseFormulaRemark
No padding, stride 1W_O = W_I − F + 1, H_O = H_I − F + 1The kernel cannot be placed at the borders, so output < input
With padding PW_O = W_I − F + 2P + 1Padding is used to keep output size equal to input; a bigger kernel needs more padding
Padding and strideW_O = ⌊(W_I − F + 2P) / S⌋ + 1, H_O likewiseHigher stride gives a smaller output
DepthD_O = KDepth of output = number of filters

The floor ⌊ ⌋ is needed when (W_I − F + 2P) is not divisible by S. For "same" output size with S = 1 use P = (F − 1)/2 (e.g. F = 3 → P = 1; F = 5 → P = 2).

Conclusion. Convolution = slide, multiply, add. Remember three levers: padding keeps size, stride shrinks it, and the number of filters sets the output depth.

Definition. Pooling slides a small window over each feature map (each depth slice separately) and replaces it with a single number: the maximum (max-pooling) or the mean (average-pooling).

Max-pooling, 2×2 filter, stride 2 (deck)

Input [[1,1,2,4],[5,6,7,8],[3,2,1,0],[1,2,3,4]] → output [[6,8],[3,4]]. Each output is the largest value in its 2×2 block.

Average-pooling, F = 2, S = 2 (deck)

Input [[2,2,7,3],[9,4,6,1],[8,5,2,4],[3,1,2,6]] → output [[4.25, 4.25],[4.25, 3.5]]. Top-left: (2+2+9+4)/4 = 4.25.

PropertyConvolution layerPooling layer
Learnable parametersYes: (F·F·D_I + 1)·KNone (0)
Output size⌊(W_I − F + 2P)/S⌋ + 1Same formula (typically F = 2, S = 2 halves the size)
Output depthK (number of filters)Unchanged (D_O = D_I)
PurposeExtract featuresReduce size / computation, small shift tolerance

The deck's other pooling example: max-pooling with S = 1, F = 3, P = 1. The output size is (W − 3 + 2)/1 + 1 = W, so the output has the same size as the input.

Beyond the deck: standard content, but asked in past papers Max-pooling keeps the strongest response in each region, which gives some translation invariance and is the usual choice in classification CNNs; average-pooling smooths and is used, for example, as the final global pooling in GoogLeNet (deck: 7×7×1024 average pooled).

Conclusion. Pooling has no weights; it only downsamples height and width (not depth), cutting computation for the next layers.

04 · The exam numerical

Counting Parameters and Computations

Rules. Conv layer: params = (F × F × D_I + 1) × K (the +1 is each filter's bias; the deck's slide counts only the weights F×F×D_I×K). Pooling and activation layers: 0. Fully connected: n_in × n_out + n_out. Multiplications in a conv layer: K × F × F × D_I × W_O × H_O.

Deck example: 12×12×3 input, 256 filters of 5×5×3, S = 1, P = 0

  • W_O = H_O = (12 − 5 + 0)/1 + 1 = 8; D_O = K = 256 → output 8 × 8 × 256.
  • Trainable parameters (deck, weights only): 5 × 5 × 3 × 256 = 19,200 (with biases: 19,456).
  • Computations: there are 256 kernels of 5×5×3 that move 8×8 times → 256 × 5 × 5 × 3 × 8 × 8 = 1,228,800 multiplications.

Why filters share weights: the saving

A 3×3 filter on a 64-channel input has 3×3×64 = 576 weights (+1 bias), whatever the image size. A fully connected layer on the same image would need a weight for every input–output pair.

Conclusion. For any CNN numerical: track the shape layer by layer with the output-size formula, then multiply F×F×(input depth)×K, add K biases, and remember pool/activation layers cost zero parameters.

05 · Putting the blocks together

CNN Network Design and Image Classification (Kaggle)

Typical pattern (deck figure). Input → [Convolution → Pooling] × N → fully connected layers → output. Deck hyperparameters: number of layers, number of filters in each layer, size of filters, and the max-pooling layers (plus stride and padding).

Input imageConv + ReLUPoolConv + ReLUPoolFlattenFCSoftmax

Design checklist

  1. Fix the input size (e.g. 32×32×3, 224×224×3, 227×227×3) and the number of classes.
  2. Choose the conv blocks: filter size F, number of filters K, stride S and padding P. Use the output-size formula to track every shape.
  3. Add pooling after some conv layers to shrink height and width as the number of filters grows.
  4. Flatten the last feature map and add one or more fully connected layers.
  5. Output layer: softmax with categorical cross-entropy for multi-class (Unit 3 pairing).
  6. Count parameters and check that the model is not larger than the data can support.

Beyond the deck: standard content, but asked in past papers Common rules of thumb: small 3×3 filters stacked deep, ReLU after every conv, double the filters after each pooling, dropout in FC layers, and data augmentation to fight overfitting.

Image-type classification (Kaggle style) Beyond the deck: standard content, but asked in past papers

Syllabus topic "Image Type Classification (Kaggle)": a Kaggle-style task gives labelled images (for example digits, cats vs dogs, CIFAR-10 object classes) and scores predictions on a hidden test set. The usual workflow:

  1. Load and resize every image to a fixed size; scale pixel values (÷255) or normalise per channel.
  2. Split the labelled data into train and validation sets; the validation score guards against overfitting.
  3. Augment the training images (flips, crops, small rotations) to enlarge the effective dataset.
  4. Build or reuse a model: a small CNN from scratch, or transfer learning — start from a network pre-trained on ImageNet (VGG, ResNet, …), replace the last layer with one for your classes, and fine-tune.
  5. Train with softmax + categorical cross-entropy (sigmoid + binary cross-entropy for two classes or multi-label), an adaptive optimiser such as Adam, and early stopping.
  6. Evaluate and submit: accuracy or log-loss on the validation set, then predict the test images and upload the file.

Conclusion. Design a CNN by stacking conv-pool blocks until the feature map is small, then classify; for real competitions, pre-trained networks plus augmentation usually beat a from-scratch model.

GoogLeNet and the Inception module (deck)

GoogLeNet has 22 layers (6.7% error). Instead of choosing one filter size, an Inception module applies 1×1, 3×3 and 5×5 convolutions and a 3×3 max-pooling in parallel on the same input and concatenates the results.

  • 1×1 convolutions reduce the depth (use D_O < D_I filters of size 1×1×D_I) and hence the number of computations; the resulting volume is smaller.
  • Deck example module: input 28×28×256 → branches of 96 (1×1), 128 (1×1) → 192 (3×3), 32 (1×1) → 96 (5×5), and 3×3 max-pool → 64 (1×1); concatenated output 28×28×448 (96 + 192 + 96 + 64 = 448).
  • The network has auxiliary loss branches during training and ends in average pooling of the 7×7×1024 volume.

ResNet

The deck chart lists ResNet with 152 layers and 3.57% top-5 error, the best of the series. Beyond the deck: standard content, but asked in past papers ResNet adds skip (shortcut) connections: a block computes y = F(x) + x, so it only has to learn the residual F(x). The identity path gives gradients a direct route backwards, which makes very deep networks trainable (very deep plain networks degrade because gradients vanish).

Conclusion. Progress came from depth plus smarter design: AlexNet (ReLU, dropout), VGG (uniform 3×3 blocks), GoogLeNet (inception, 1×1 reduction), ResNet (skip connections).

Why not the networks we have seen so far?

Feed-forward networks and CNNs share two limits (deck): outputs are independent of previous inputs and the input is of a fixed length. Sentences, speech, video and time series are sequences of variable length where order matters.

The sequence-learning problem

We need y_t = f̂(x_1, x_2, …, x_t). The deck's three requirements:

  • y_t must depend on the previous inputs as well;
  • the function must deal with a variable number of inputs;
  • the function executed at each time step must be the same — parameter sharing. Then y₁ = f(x₁), y₂ = f(x₁, x₂), y₃ = f(x₁, x₂, x₃), …

The recurrent neural network (deck)

s_i = σ(U·x_i + W·s_{i−1} + b), y_i = O(V·s_i + c). Here s_i is the hidden state (memory), U maps the input, W maps the previous state (the recurrence), V maps the state to the output; σ is the state activation (tanh or sigmoid) and O the output function (e.g. softmax). U, W, V, b, c are shared across every time step.

Data and tasks (deck)

Sequence classification

One label for the whole sequence: sentiment classification, video classification. Output taken at the last step: ŷ = O(V·s_T + c), T = sequence length.

Sequence labelling

One label per element: part-of-speech tagging, named-entity recognition. Output at every step: ŷ_i = O(V·s_i + c).

Sequence generation

Produce a new sequence: machine translation, transliteration.

Representing words as numbers (deck)

  1. Define special symbols <sos> (start), <eos> (end), <pad> (padding); prepend/append <sos>/<eos> to every sequence.
  2. Find the maximum sequence length (say 10) and add <pad> to shorter sequences so all have the same length.
  3. Lower-case all words, compute the number of unique words L across all sentences (L = 24 in the deck's example) and give each word a unique id from 1 to L (the dictionary / vocabulary).
  4. One-hot encode: represent each word by an L-dimensional binary vector with a 1 only at the position of its id.

The vanishing-gradient problem in RNNs and dealing with longer sequences

The deck's problem statement: at each new time step the old information gets morphed by the current input; after t steps the information from step t − k is completely morphed; and during backpropagation the information does not flow well. The RNN has only a finite-size state, so it cannot remember everything (the deck's "whiteboard" analogy: the board is finite, so we must selectively write, selectively read and selectively forget).

Beyond the deck: standard content, but asked in past papers Why the gradient vanishes. By the chain rule, the gradient reaching a step k steps back is a product of k Jacobians: ∂s_t/∂s_{t−k} = Π ∂s_j/∂s_{j−1}, and each factor contains W and the activation derivative σ′ (≤ 0.25 for sigmoid, ≤ 1 for tanh). If these factors are below 1 the product shrinks exponentially (0.25¹⁰ ≈ 10⁻⁶; 0.9⁵⁰ ≈ 0.005), so early inputs get almost no learning signal and the RNN cannot learn long-range dependencies. If the factors exceed 1 the product explodes (1.5⁵⁰ ≈ 6 × 10⁸), which is the exploding gradient problem; it is handled by gradient clipping. The vanishing case is solved architecturally by gated cells: LSTM (next section) and GRU.

08 · Selective read, write and forget

Long Short-Term Memory (LSTM)

Definition. An LSTM is an RNN cell with a state vector and three gates (values between 0 and 1) that control what is written to the state, what is read from the new input, and what is forgotten. Computing s_t from s_{t−1}, the goal (deck) is "selective write, selective read and selective forget so that only important information is retained in s_t".

Step-by-step, as built in the deck

  1. Selective write — output gate. Instead of passing s_{t−1} as it is, pass a fraction of it: h_{t−1} = o_{t−1} ⊙ σ(s_{t−1}), with o_{t−1} = σ(W_o·h_{t−2} + U_o·x_{t−1} + b_o). The gate o is learned from data (expressed through parameters), a value in (0,1) per component. o_t is the output gate.
  2. Temporary (candidate) state. Combine the previous output with the current input: s̃_t = σ(W·h_{t−1} + U·x_t + b). It captures all the new information, but we may not want to use all of it.
  3. Selective read — input gate. i_t = σ(W_i·h_{t−1} + U_i·x_t + b_i); the part of the new information actually used is i_t ⊙ s̃_t. i_t is the input gate.
  4. Selective forget — forget gate. f_t = σ(W_f·h_{t−1} + U_f·x_t + b_f); the part of the old state kept is f_t ⊙ s_{t−1}. f_t is the forget gate.
  5. New state. s_t = f_t ⊙ s_{t−1} + i_t ⊙ s̃_t (keep part of the old, add part of the new).
  6. Output / hidden state. h_t = o_t ⊙ σ(s_t); h_t is passed to the next time step (and to the output layer).

Full set of equations (deck). Gates: o_t = σ(W_o h_{t−1} + U_o x_t + b_o), i_t = σ(W_i h_{t−1} + U_i x_t + b_i), f_t = σ(W_f h_{t−1} + U_f x_t + b_f). States: s̃_t = σ(W h_{t−1} + U x_t + b), s_t = f_t ⊙ s_{t−1} + i_t ⊙ s̃_t, h_t = o_t ⊙ σ(s_t). (⊙ = element-wise product.) Beyond the deck: standard content, but asked in past papers Most textbooks write the cell state as c_t and use tanh for the candidate and for the output squashing; the structure is identical.

Roles of the three gates

Forget gate f_t

Decides how much of the old state to keep (1 = keep, 0 = erase). Example: forget stop-words, or a previous subject when a new one appears.

Input gate i_t

Decides how much of the new candidate information is written into the state. Example: store sentiment-bearing words like "awesome".

Output gate o_t

Decides how much of the state is exposed as the hidden state h_t / output at this step.

Tiny numeric walkthrough Beyond the deck: standard content, but asked in past papers

One scalar unit with gate outputs already computed: f = 0.8, i = 0.5, o = 0.9, candidate s̃ = 0.6, previous state s_{t−1} = 1.0. Then s_t = 0.8×1.0 + 0.5×0.6 = 1.1 and, with tanh squashing, h_t = 0.9 × tanh(1.1) = 0.9 × 0.8005 ≈ 0.72.

Parameters of one LSTM layer Beyond the deck: standard content, but asked in past papers (hidden size n, input size d): four weight blocks (three gates + candidate), each n·(n + d) + n, so 4·[n(n + d) + n]. For n = 3, d = 4: 4 × (3×7 + 3) = 96, which is four times the 24 parameters of a plain RNN's state block, n(n + d) + n.

Why LSTM fixes the vanishing gradient Beyond the deck: standard content, but asked in past papers

The state update is additive, s_t = f_t ⊙ s_{t−1} + …, so the derivative ∂s_t/∂s_{t−1} is essentially the forget gate f_t. When f_t ≈ 1 the gradient flows back through time almost unchanged, instead of being multiplied by W and σ′ at every step as in a plain RNN.

RNN vs LSTM

Plain RNNLSTM
State updates_i = σ(U x_i + W s_{i−1} + b): old state is overwritten (morphed) every steps_t = f_t ⊙ s_{t−1} + i_t ⊙ s̃_t: selective keep + selective write
GatesNoneForget, input, output
Long-range memoryPoor (vanishing gradient)Good (additive state path)
ParametersOne set (U, W, b)About 4× more
Speed / complexityCheaper, simplerSlower, more complex
UseShort sequencesLong sequences: translation, speech, text

Conclusion. LSTM = RNN + three learned gates. Forget controls the old memory, input controls the new, output controls what is revealed, so important information survives over long sequences.

09 · Learning to compress

Autoencoders Beyond the deck: standard content, but asked in past papers

Definition. An autoencoder is a neural network trained to reproduce its own input. Its two main components are the encoder, h = f(x), which maps the input to a hidden code, and the decoder, x̂ = g(h), which reconstructs the input from the code. It is trained without labels (unsupervised) by minimising the reconstruction loss L = ‖x − x̂‖² (mean squared error; cross-entropy for binary inputs).

UndercompleteOvercomplete
Code sizeSmaller than the input (h < n)Equal to or larger than the input (h ≥ n)
EffectThe bottleneck forces the network to learn the most important features (compression)Can copy the input (identity) and learn nothing useful
Remedy / variantNot neededAdd regularisation: sparse, denoising or contractive autoencoder
Typical useDimensionality reduction, feature learningDenoising, sparse representations

An undercomplete autoencoder with a linear encoder and decoder behaves like PCA; non-linear activations let it learn a more powerful non-linear compression.

Layer-wise pre-training

  1. Train a first autoencoder on the raw input x to reconstruct x; keep its hidden code h₁ and discard its decoder.
  2. Train a second autoencoder on h₁ (the codes of the first) to reconstruct h₁; keep its code h₂. Repeat for as many layers as wanted.
  3. Stack the trained encoders to form a deep network, add the output (classifier) layer on top.
  4. Fine-tune the whole stack with ordinary backpropagation on the labelled task.

Each layer starts from a sensible initialisation instead of random weights, which was important before modern activations and normalisation made deep networks easy to train directly.

Use in feature learning and applications

The hidden code is a compact, learned feature vector that can feed a classifier (needing fewer labelled examples), be used for visualisation, or support denoising (reconstruct clean data from corrupted input), anomaly detection (large reconstruction error flags unusual samples) and compression. Parameter example: a 784 → 32 → 784 autoencoder has (784×32 + 32) + (32×784 + 784) = 25,120 + 25,872 = 50,992 parameters.

Conclusion. An autoencoder learns features by reconstruction; undercomplete ones compress through a bottleneck, overcomplete ones need regularisation, and layer-wise pre-training stacks them into a deep, pre-initialised network.

Unit 5 — Summary

  • CNN = learned filters + sparse connectivity + weight sharing; output size is ⌊(W − F + 2P)/S⌋ + 1 and output depth is K
  • Conv params = (F·F·D_I + 1)·K; pooling and activations add none; the deck's example costs 1,228,800 multiplications
  • AlexNet: 5 conv + 3 FC, ReLU, dropout, ≈ 60 M parameters; VGG-16: 13 conv + 3 FC, all 3×3, ≈ 138 M parameters; GoogLeNet uses Inception with 1×1 reductions; ResNet uses skip connections
  • RNN: s_i = σ(U x_i + W s_{i−1} + b) with shared weights handles variable-length sequences, but gradients vanish over long ranges
  • LSTM adds forget, input and output gates around an additive state, so long-range information survives
  • Autoencoders learn compact features by reconstructing the input
