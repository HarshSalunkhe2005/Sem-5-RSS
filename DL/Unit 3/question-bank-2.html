Group A

Feed-forward networks: design and parameters

Question Bank Q159–170

Q159Define a feed-forward neural network.

A feed-forward neural network (FFNN) is a network whose connections only go forward — input layer → one or more hidden layers → output layer — with no cycles or feedback loops. Each neuron computes a = Σwᵢxᵢ + b and passes it through an activation h = f(a). Information flows in a single direction, so training uses backpropagation on a fixed computational graph.

Q160Draw a fully connected FFNN with 4 input, 5 hidden and 3 output neurons.

INPUT (4)         HIDDEN (5)        OUTPUT (3)
  x1  ○ ─┐
  x2  ○ ─┤  every input     h1 ○ ─┐
  x3  ○ ─┼─ connects to ──▶ h2 ○ ─┤  every hidden   ○ y1
  x4  ○ ─┘  every hidden    h3 ○ ─┼─ connects to ─▶ ○ y2
                            h4 ○ ─┤  every output   ○ y3
                            h5 ○ ─┘
  4×5 = 20 weights + 5 biases      5×3 = 15 weights + 3 biases
Every input neuron connects to every hidden neuron (20 links) and every hidden neuron to every output neuron (15 links). Each hidden and output neuron also has one bias. Total = 20 + 5 + 15 + 3 = 43 trainable parameters.

Q161Calculate the total number of trainable parameters in a fully connected network.

A layer with n_in inputs and n_out neurons has n_in × n_out weights + n_out biases. Worked on the network of Q160 (4→5→3): layer 1 = 4×5 + 5 = 25; layer 2 = 5×3 + 3 = 18; total = 25 + 18 = 43. (The question gives no sizes, so the Q160 architecture is used as the example; the general rule is in Q162.) The input layer has no parameters.

Q162Derive a general formula for the number of parameters in a fully connected network.

Let the layer sizes be n₀ (inputs), n₁, …, n_L (outputs). Layer l has a weight matrix W⁽ˡ⁾ of shape n_l × n_(l−1), giving n_(l−1)·n_l weights, and a bias vector of length n_l. So P = Σ from l=1 to L of (n_(l−1)·n_l + n_l) = Σ n_l(n_(l−1) + 1). Check with 4→5→3: 5(4+1) + 3(5+1) = 25 + 18 = 43.

Q163Explain why biases are trainable parameters.

The bias b shifts the neuron's pre-activation: a = w·x + b. Without it every decision boundary is forced through the origin (and f(0) is fixed), which limits what the neuron can represent. Because the best shift depends on the data, b is learned along with the weights; its gradient is simply ∂L/∂b = ∂L/∂a (the input is effectively a constant 1).

Q164Difference between parameters and hyperparameters?

Parameters (weights and biases) are learned from data by gradient descent during training. Hyperparameters (learning rate, number of layers/neurons, batch size, epochs, dropout rate, λ) are set by the designer before training and are tuned using the validation set — the optimizer never updates them.

Q165List important hyperparameters of a neural network.

Learning rate (and its schedule), batch size, number of epochs, number of hidden layers, neurons per layer, activation function, optimizer and its constants (β₁, β₂, momentum), weight initialization, regularization strength λ (L1/L2), dropout probability p, and the early-stopping patience.

Q166Explain batch size, epochs and iterations.

Batch size B = number of samples used for one gradient update. Epoch = one full pass over the whole training set. Iteration = one parameter update (one mini-batch). Relation: iterations per epoch = N / B. Example: N = 1000, B = 100 → 10 iterations per epoch; 20 epochs → 200 iterations.

Q167What is an epoch?

One complete pass of the entire training dataset through the network (forward and backward), so that every training sample has been used once to update the weights. Training normally runs for many epochs.

Q168What is a mini-batch?

A small random subset of the training set (typically 32–512 samples) used to compute one gradient estimate and one update. It balances the smooth but costly full-batch gradient against the noisy single-sample gradient, and maps well onto GPU matrix operations.

Q169Difference between training parameters and hyperparameters?

Same distinction as Q164: training parameters (weights, biases) are the quantities optimized on the training set by backpropagation; hyperparameters are external settings chosen beforehand (learning rate, depth, batch size, p, λ) that control how training happens and are tuned on the validation set, not by gradient descent.

Q170Parameter-Count Numerical Problem 1: 10 → 8 → 5 → 3, fully connected with biases. Total trainable parameters?

Layer 1 (10→8): 10×8 + 8 = 80 + 8 = 88.
Layer 2 (8→5): 8×5 + 5 = 40 + 5 = 45.
Layer 3 (5→3): 5×3 + 3 = 15 + 3 = 18.
Total = 88 + 45 + 18 = 151 (weights 135 + biases 16).

Computational cost

Question Bank Q171–178

Q171Parameter-Count Numerical Problem 2: architecture 20 → 50 → 100 → 10. Weights, biases, total?

Weights: 20×50 = 1000; 50×100 = 5000; 100×10 = 1000 → 7000.
Biases: 50 + 100 + 10 = 160.
Total trainable parameters = 7000 + 160 = 7160.

Q172Parameter-Count Numerical Problem 3: 10 classes, 784 inputs. Design a network with two hidden layers, count parameters, justify.

Choose 784 → 128 → 64 → 10 (values are my design choice). Layer 1: 784×128 + 128 = 100,352 + 128 = 100,480. Layer 2: 128×64 + 64 = 8,192 + 64 = 8,256. Layer 3: 64×10 + 10 = 650. Total = 100,480 + 8,256 + 650 = 109,386. Justification: 784 = 28×28 flattened pixels; widths shrink gradually (128 → 64) so the network compresses features progressively; ReLU in hidden layers for fast, non-saturating training; 10 softmax outputs with cross-entropy for 10 classes; ~109k parameters is enough capacity for such images without heavy overfitting (add dropout ~0.2–0.5 if needed).

Q173Explain the computational cost of a fully connected layer.

For one sample, a dense layer with n_in inputs and n_out outputs computes y = f(Wx + b): n_in × n_out multiply-accumulate operations (MACs) for Wx, n_out additions for b, and n_out activation evaluations. The matrix product dominates, so cost ≈ O(n_in·n_out) per sample and O(B·n_in·n_out) per mini-batch. Backward pass costs roughly 2× the forward pass (gradients w.r.t. weights and w.r.t. inputs).

Q174Derive the approximate number of multiplications for a dense layer.

Output neuron j: y_j = Σ over i=1..n_in of W_ji·x_i + b_j needs n_in multiplications. There are n_out such neurons, so multiplications = n_in × n_out for one sample, and B × n_in × n_out for a batch of B. Example: 784→128 gives 784×128 = 100,352 multiplications per sample (≈ 2× that in FLOPs, counting the additions).

Q175How does increasing the number of neurons affect computational cost?

Cost grows linearly with the width of a single layer, since cost ∝ n_in × n_out. But widening a hidden layer also enlarges the next layer's input, and if all layers are widened by k, the cost (and parameters) grow about k². Example: 784→128 costs 100,352 MACs; 784→256 costs 200,704 (doubled). More neurons also mean more memory and a higher overfitting risk.

Q176How does batch size affect computational cost?

Cost per iteration is proportional to B (B × n_in × n_out), but cost per epoch is the same total work (N samples processed). Example for 784→128: B = 32 → 3,211,264 MACs per iteration; B = 64 → 6,422,528. A larger B means fewer, more hardware-efficient iterations and a smoother gradient, but needs more memory; a smaller B gives more updates per epoch with noisier gradients.

Q177Explain why matrix multiplication is central to deep learning.

A whole layer for a whole batch is one matrix product: H = f(XW + b) with X of shape B × n_in and W of shape n_in × n_out. The backward pass is also matrix products (Xᵀδ for weight gradients, δWᵀ for input gradients). Since most of the compute is matmul, optimized libraries (BLAS, cuBLAS) and hardware focused on it make training fast.

Q178Explain why GPUs accelerate neural-network training.

Matrix multiplication consists of thousands of independent multiply-add operations, which suits the thousands of simple cores in a GPU running in parallel (CPUs have only a few strong cores). GPUs also have high memory bandwidth and specialised units (tensor cores) for dense matmul, giving 10–100× speed-up on large batches.

Group C

Classification and evaluation metrics

Question Bank Q179–189

Q179Differentiate binary and multiclass classification.

Binary: two classes (e.g. spam / not spam); one sigmoid output giving P(y=1), loss = binary cross-entropy. Multiclass: K > 2 mutually exclusive classes; K outputs with softmax giving a probability distribution over classes, loss = categorical cross-entropy.

Q180Explain multiclass classification using softmax.

The output layer produces K logits z₁..z_K. Softmax converts them to probabilities: p_k = e^(z_k) / Σⱼ e^(z_j), all positive and summing to 1. The predicted class is argmax p_k. Training minimizes cross-entropy L = −log p_(true class); the gradient w.r.t. the logits is simply p − y (one-hot).

Q181Explain one-vs-rest classification.

Train K separate binary classifiers, each separating one class (positive) from all the other K−1 classes (negative). At prediction time all K classifiers score the input and the class with the highest score wins. It lets binary-only models handle K classes, but the classes get imbalanced and the scores are not calibrated against each other.

Q182Explain the difference between classification and regression.

Classification predicts a discrete category (sigmoid/softmax output, cross-entropy loss, evaluated with accuracy/F1). Regression predicts a continuous value (linear output, MSE or MAE loss, evaluated with RMSE/R²). The model body is the same; the output layer, loss and metrics differ.

Q183Explain precision, recall, F1-score and accuracy.

From the confusion matrix (TP, FP, FN, TN): Accuracy = (TP+TN)/(TP+TN+FP+FN), the fraction of all predictions that are right. Precision = TP/(TP+FP): of those predicted positive, how many really are. Recall (sensitivity) = TP/(TP+FN): of the real positives, how many were found. F1 = 2·P·R/(P+R) = 2TP/(2TP+FP+FN), the harmonic mean, high only when both are high.

Q184When is accuracy a poor evaluation metric?

With imbalanced classes. If 95% of samples are class 0, a model that always predicts 0 scores 95% accuracy yet finds no positives (recall = 0). Accuracy also ignores unequal costs of errors (missing a disease vs a false alarm). Use precision, recall, F1, PR-AUC or ROC-AUC instead.

Q185Explain the confusion matrix.

A table of counts of actual vs predicted classes. For binary: TP (actual 1, predicted 1), FP (actual 0, predicted 1), FN (actual 1, predicted 0), TN (actual 0, predicted 0). Rows are the actual class and columns the predicted class; all metrics (accuracy, precision, recall, F1) are computed from these four numbers, and for K classes it is a K × K matrix.

Q186What is class imbalance?

A dataset in which one class has far more samples than another (e.g. 95% vs 5%, fraud detection, disease screening). The model is then biased toward the majority class because minimizing average loss rewards ignoring the rare class, which is often the one that matters.

Q187How can class imbalance be handled?

Data level: oversample the minority class (e.g. SMOTE) or undersample the majority. Algorithm level: class weights / weighted loss (weight ≈ 1/class frequency) or focal loss. Evaluation: use stratified splits, precision/recall/F1/PR-AUC rather than accuracy. Post-processing: tune the decision threshold below 0.5 for the rare class. Collecting more minority data also helps.

Q188Explain the ROC curve and AUC.

The ROC curve plots True Positive Rate (= recall = TP/(TP+FN)) against False Positive Rate (= FP/(FP+TN)) as the decision threshold sweeps from 1 to 0. A diagonal line is random guessing; the closer the curve is to the top-left corner, the better. AUC is the area under it: AUC = probability that a random positive is scored higher than a random negative; 0.5 = random, 1.0 = perfect. For very imbalanced data the precision-recall curve (PR-AUC) is more informative.

Q189Explain the difference between macro and micro averaging.

For multiclass metrics. Macro: compute the metric (e.g. precision) separately for each class and take the plain average — all classes count equally, so rare classes matter as much as common ones. Micro: pool the TP, FP, FN of all classes first, then compute once, e.g. micro precision = ΣTP/Σ(TP+FP) — dominated by frequent classes (for single-label multiclass, micro precision = micro recall = accuracy). Use macro when minority classes matter.

Group D

Application problems

Question Bank Q190–198

Q190Application Problem 1: predict whether a student will pass or fail. Design an ANN solution.

Inputs: attendance %, internal marks, previous GPA, study hours, assignments submitted etc. (numerical, scaled; categorical features one-hot encoded). Architecture: n → 16 → 8 → 1 (two hidden layers). Activations: ReLU in hidden layers, sigmoid at the output (P(pass)). Loss: binary cross-entropy. Optimizer: Adam, lr = 0.001. Regularization: dropout 0.2 and early stopping. Metrics: accuracy, precision, recall and F1 on a held-out test set (recall of the 'fail' class matters most, since the aim is to identify at-risk students). Use a stratified train/validation/test split (70/15/15).

Q191Application Problem 2: a Kaggle binary-classification dataset. Design a complete deep-learning pipeline.

1) Understand the data and the target; check missing values and class balance. 2) Clean: impute missing values, remove duplicates, handle outliers. 3) Encode categoricals, scale numericals (fit the scaler on train only). 4) Stratified split into train / validation / test (e.g. 70/15/15). 5) Build the model: dense layers with ReLU, sigmoid output, binary cross-entropy. 6) Train with Adam and mini-batches (e.g. 64), monitor validation loss, use dropout / L2 / early stopping. 7) Tune hyperparameters on the validation set. 8) Evaluate once on the test set with accuracy, precision, recall, F1, ROC-AUC, confusion matrix. 9) Diagnose errors, then save the model.

Q192Application Problem 3: 100,000 samples, 50 features. How to split into training, validation and test sets?

Shuffle, then split (stratified by class if classification): the common 80/10/10 gives 80,000 train / 10,000 validation / 10,000 test (70/15/15 gives 70,000 / 15,000 / 15,000 — also fine). Train is used to fit weights, validation to tune hyperparameters and early-stop, test only once at the end for an unbiased estimate. Fit preprocessing (scalers, imputers) on the training set only to avoid data leakage; for time-ordered data split chronologically.

Q193Application Problem 4: 95% class-0, 5% class-1. Why is accuracy misleading? Suggest metrics.

A model that predicts class 0 for everything gets 95% accuracy but finds no class-1 sample. Worked example (1000 samples: 950 class-0, 50 class-1, values assumed): TP = 30, FN = 20, FP = 40, TN = 910. Accuracy = (30+910)/1000 = 94% — looks great (yet it is even lower than the 95% of the useless always-0 model). Precision = 30/(30+40) = 0.429. Recall = 30/(30+20) = 0.60. F1 = 2·0.429·0.60/(0.429+0.60) = 0.50. The honest picture is a mediocre F1 of 0.50. Suitable metrics: precision, recall, F1, PR-AUC, ROC-AUC, confusion matrix, with stratified splits and class weights.

Q194Application Problem 5: training accuracy 99%, validation accuracy 72%. Problem and five solutions?

Large train–validation gap → overfitting (high variance): the network memorized the training data. Solutions: (1) get more data or use data augmentation; (2) add dropout; (3) add L2 regularization / weight decay; (4) early stopping on validation loss; (5) reduce model size (fewer layers/neurons); (6) batch normalization; (7) cross-validation and a proper hyperparameter search; (8) feature selection to remove noisy inputs.

Q195Application Problem 6: training and validation losses are both high. Reasons?

This is underfitting (high bias) or an optimization problem. Possible reasons: model too small or too simple; too few epochs; learning rate too low (slow) or too high (not converging); vanishing gradients or dead ReLUs; bad initialization; poorly scaled/unnormalized inputs; uninformative features or noisy/wrong labels; too much regularization (high λ or dropout); a bug in the data pipeline or loss. Fixes: bigger model, train longer, tune lr, normalize inputs, lower regularization, better features.

Q196Application Problem 7: training loss decreases; validation loss decreases then increases. Explain.

Initially the network learns real, general patterns, so both losses fall. After the turning point it starts to fit noise and quirks of the training set (memorization): training loss keeps decreasing but validation loss rises. This is overfitting; the minimum of the validation loss is the best stopping point. Remedy: early stopping (restore the best checkpoint), dropout, L2, more data/augmentation, a smaller model.

Q197Application Problem 8: great on training data, poor on unseen data. Problem and remedies?

The model has overfitted — it has high variance and poor generalization. Remedies: more training data or augmentation, L1/L2 regularization, dropout, early stopping, a simpler network, batch normalization, ensembling, and checking that no leakage or train/test distribution mismatch exists.

Q198Application Problem 9: a deep network learns very slowly in the early layers. Causes?

Classic vanishing gradient: backpropagation multiplies many local derivatives; with sigmoid/tanh (derivative ≤ 0.25 / ≤ 1) and small weights the product shrinks exponentially with depth, so early layers get near-zero gradients. Other causes: poor initialization (too small weights), saturated activations, too-small learning rate. Fixes: ReLU/Leaky ReLU, He/Xavier initialization, batch normalization, residual (skip) connections, gradient monitoring, shallower network.

Group E

Conceptual why-questions

Question Bank Q199–218

Q199Why can a network with nonlinear activations represent nonlinear decision boundaries?

Each nonlinear unit bends/clips its input (e.g. ReLU creates a kink), and composing many such functions yields piecewise-curved functions. By the universal approximation theorem, one hidden layer of enough nonlinear units can approximate any continuous function, so complicated boundaries such as XOR become learnable. With purely linear units the boundary is always a single hyperplane.

Q200Why does stacking linear layers without nonlinear activations not increase representational power?

Composition of linear maps is linear: W₂(W₁x + b₁) + b₂ = (W₂W₁)x + (W₂b₁ + b₂) = W′x + b′. The deep network collapses into a single linear layer, so it can only learn linear boundaries however many layers are used. Nonlinear activations between layers are what stop this collapse.

Q201Why does increasing depth sometimes make optimization more difficult?

Gradients are products of many layer Jacobians, so they can vanish (factors < 1) or explode (factors > 1) with depth; the loss surface becomes more non-convex with many saddle points; the early layers get weak, noisy signals; and degradation occurs — deeper plain nets can show higher training error. Remedies are ReLU, good initialization, normalization and skip connections.

Q202Explain vanishing gradients mathematically.

By the chain rule, for L layers: ∂L/∂W⁽¹⁾ = δ⁽ᴸ⁾ · Π over l of [W⁽ˡ⁺¹⁾ᵀ · diag(f′(a⁽ˡ⁾))] · (input). Every factor includes f′. For sigmoid f′(a) ≤ 0.25, so with 10 layers the activation-derivative part alone is ≤ 0.25¹⁰ ≈ 9.5×10⁻⁷. If ‖W‖·f′ < 1 the product decays exponentially with depth, and the early layers hardly learn (if it is > 1 the gradient explodes instead).

Q203Why does sigmoid suffer from saturation?

σ(a) = 1/(1+e⁻ᵃ) flattens toward 0 or 1 for large |a|. Its derivative σ′ = σ(1−σ) is at most 0.25 (at a = 0) and approaches 0 in the flat tails (e.g. σ′(5) ≈ 0.0066). A saturated neuron passes almost no gradient back, so learning stalls; sigmoid outputs are also not zero-centred.

Q204Explain why ReLU partially addresses the vanishing-gradient problem.

ReLU(a) = max(0, a) has derivative 1 for a > 0 (and 0 for a < 0). For active units the factor in the chain-rule product is exactly 1, so the gradient does not shrink with depth, unlike the ≤ 0.25 of sigmoid. It does not saturate for positive inputs and is cheap to compute. It is only 'partial' because inactive units (a < 0) pass zero gradient.

Q205Why can ReLU neurons die?

If a large update (e.g. a high learning rate) or a very negative bias pushes a neuron's pre-activation negative for all inputs, its output is 0 and its gradient is 0 everywhere. Since the weights then receive no gradient, they never change and the neuron stays permanently inactive ('dead ReLU'). Remedies: lower learning rate, good initialization (He), Leaky ReLU / ELU.

Q206Explain the relationship between initialization and gradient propagation.

Activations and gradients are repeatedly multiplied by weights. If initial weights are too small the signal and gradients shrink layer by layer (vanishing); if too large they blow up (exploding) or saturate sigmoid/tanh. Xavier/Glorot init (Var(w) = 2/(n_in+n_out)) for tanh/sigmoid and He init (Var(w) = 2/n_in) for ReLU keep the variance roughly constant across layers, allowing stable gradient flow.

Q207Why should weights generally not be initialized to the same value?

If all weights in a layer are equal, every neuron computes the same output and receives the same gradient, so they stay identical after every update — the layer behaves like a single neuron regardless of its width. Identical initialization therefore wastes the capacity of the layer.

Q208Explain symmetry breaking in neural networks.

Neurons in the same layer with identical weights are symmetric: same output, same gradient, same update, forever. Random initialization breaks this symmetry so that each neuron starts different, receives different gradients and learns a different feature. (Biases may be zero; it is the weights that must differ. Dropout noise also helps break co-adaptation.)

Q209Why is random initialization necessary?

To break symmetry (Q208) so neurons learn different features, and, when scaled properly (Xavier/He), to keep activations and gradients at a useful magnitude. Zero or constant initialization makes all neurons identical (and with zero weights the gradients to earlier layers are zero), so training cannot produce a diverse hidden representation.

Q210Explain the relationship between batch size and gradient noise.

The mini-batch gradient is an estimate of the true gradient with variance ≈ σ²/B. Small B → noisy gradient (cheap steps, more updates, tends to generalize well); large B → smoother, accurate gradient but costly steps and a tendency to converge to sharper minima, so lr is often scaled up with B. Full batch has no sampling noise.

Q211Why can noisy gradients sometimes help optimization?

The noise acts like random perturbation that helps the optimizer escape saddle points and shallow or sharp local minima and tends to settle in flat, wide minima that generalize better. It also acts as an implicit regularizer. Too much noise, however, prevents convergence (the loss bounces around), which is why learning rates are decayed.

Q212Explain the difference between optimization error and generalization error.

Optimization error = how far the training loss achieved is from the best possible training loss (the optimizer failed to reach a good minimum — slow, stuck, bad lr). Generalization error = the gap between performance on unseen data and on training data (the model fits training data but not the true distribution — overfitting). Fix optimization error with better optimizers/lr/init; fix generalization error with regularization, more data.

Q213Why can a larger network sometimes generalize better despite having more parameters?

Over-parameterized networks trained with SGD show 'double descent': beyond the interpolation threshold test error can fall again. Larger networks are easier to optimize (more good minima, fewer bad local minima), SGD has an implicit bias toward simple/flat solutions, and combined with regularization (weight decay, dropout, early stopping) and enough data the extra capacity is not used for memorization. So parameter count alone does not determine overfitting.

Q214Why does dropout approximately correspond to training an ensemble of subnetworks?

Each training step randomly drops units, so a different 'thinned' subnetwork (one of 2^M possible masks for M units) is trained, with weights shared among all of them. At test time the full network with scaled weights (or inverted dropout) approximates the geometric-mean prediction of the whole ensemble, giving the variance-reduction benefit of ensembling at the price of one model.

Q215Explain the relationship between regularization and model complexity.

Regularization limits the effective complexity of a model (smaller or sparser weights, fewer active units, fewer training steps) without changing the number of parameters. It trades a little more bias for much lower variance: too little regularization → overfitting, too much → underfitting. The strength (λ, p, patience) is a hyperparameter tuned on validation data.

Q216Why is cross-entropy particularly suitable for probabilistic classification?

Minimizing cross-entropy = maximizing the log-likelihood of the true labels under the model's predicted probabilities: L = −Σ y log p. It heavily penalizes confident wrong predictions (−log p → ∞ as p → 0). With sigmoid/softmax the gradient w.r.t. the logit is simply (p − y), with no σ′ factor, so learning does not stall on saturated outputs the way MSE does.

Q217Explain why softmax outputs can be interpreted as probabilities.

p_k = e^(z_k)/Σⱼ e^(z_j) satisfies p_k > 0 for all k and Σ p_k = 1, which are exactly the axioms of a discrete probability distribution. Exponentiation makes every score positive, normalization makes them sum to 1, and larger logits get larger probability. When trained with cross-entropy, they estimate P(class | x) (though not always well calibrated).

Q218Explain the relationship between logits and softmax probabilities.

Logits z are the raw, unbounded scores of the last linear layer. Softmax maps them monotonically to probabilities (a larger logit gives a larger probability) and is invariant to adding a constant to all logits; differences of logits are log-odds: log(p_i/p_j) = z_i − z_j. Example: z = [2, 1, 0] → e^z = [7.389, 2.718, 1] (sum 11.107) → p = [0.665, 0.245, 0.090]. A temperature T (z/T) makes the distribution sharper or flatter.

Q219Comprehensive Problem 1: sigmoid neuron with BCE, x=3, w=0.2, b=−0.1, y=1, η=0.1. One full training step.

Forward: z = wx + b = 0.2×3 − 0.1 = 0.5; ŷ = σ(0.5) = 1/(1+e⁻⁰·⁵) = 0.6225.
Loss: L = −[y ln ŷ + (1−y) ln(1−ŷ)] = −ln 0.6225 = 0.4741.
Gradients: for sigmoid + BCE, ∂L/∂z = ŷ − y = 0.6225 − 1 = −0.3775. ∂L/∂w = (ŷ−y)·x = −0.3775×3 = −1.1326; ∂L/∂b = −0.3775.
Update: w_new = 0.2 − 0.1×(−1.1326) = 0.3133; b_new = −0.1 − 0.1×(−0.3775) = −0.0622.
New prediction: z = 0.3133×3 − 0.0622 = 0.8775; ŷ = σ(0.8775) = 0.7063 (up from 0.6225), new loss = −ln 0.7063 = 0.3477 (down from 0.4741).

Q220Comprehensive Problem 2: h1=ReLU(w1x+b1), h2=ReLU(w2h1+b2), ŷ=w3h2+b3, L=½(ŷ−y)². Full forward/backward and one update.

Values assumed (question omits them): x = 2, y = 1, w1 = 0.5, b1 = 0.5, w2 = 0.8, b2 = 0.2, w3 = 1.5, b3 = −0.5, η = 0.1.
Computational graph: x → (×w1, +b1) → a1 → ReLU → h1 → (×w2, +b2) → a2 → ReLU → h2 → (×w3, +b3) → ŷ → ½(ŷ−y)² → L.
Forward: a1 = 0.5×2 + 0.5 = 1.5, h1 = 1.5; a2 = 0.8×1.5 + 0.2 = 1.4, h2 = 1.4; ŷ = 1.5×1.4 − 0.5 = 1.6; L = ½(0.6)² = 0.18.
Backward: ∂L/∂ŷ = ŷ−y = 0.6. ∂L/∂w3 = 0.6×h2 = 0.84; ∂L/∂b3 = 0.6. ∂L/∂h2 = 0.6×w3 = 0.9; ReLU′(a2)=1 so ∂L/∂a2 = 0.9 → ∂L/∂w2 = 0.9×h1 = 1.35; ∂L/∂b2 = 0.9. ∂L/∂h1 = 0.9×w2 = 0.72; ReLU′(a1)=1 so ∂L/∂a1 = 0.72 → ∂L/∂w1 = 0.72×x = 1.44; ∂L/∂b1 = 0.72.
Update (η=0.1): w1 = 0.5−0.144 = 0.356; b1 = 0.5−0.072 = 0.428; w2 = 0.8−0.135 = 0.665; b2 = 0.2−0.09 = 0.110; w3 = 1.5−0.084 = 1.416; b3 = −0.5−0.06 = −0.560.

Q222Comprehensive Problem 4: L(w)=w², start w=10. Compare SGD, Momentum, RMSProp, Adam.

Gradient g = 2w. Hyperparameters used (stated): lr = 0.1 for all; Momentum β = 0.9 (v ← βv + lr·g); RMSProp β = 0.9, ε = 1e-8; Adam β₁ = 0.9, β₂ = 0.999, bias-corrected.
SGD: w ← w − 0.1×2w = 0.8w → 8.0, 6.4, 5.12, 4.096, 3.277 (smooth geometric decay).
Momentum: v₁ = 2.0 → w = 8.0; v₂ = 0.9×2.0 + 0.1×16 = 3.4 → w = 4.6; v₃ = 3.98 → w = 0.62; v₄ = 3.706 → w = −3.086; v₅ = 2.718 → w = −5.804. It overshoots 0 and oscillates (inertia), then settles later.
RMSProp: s₁ = 0.1×20² = 40, step = 0.1×20/√40 = 0.316 → 9.684; then 9.458, 9.271, 9.105, 8.955. Step size is ≈ lr·sign(g), nearly independent of gradient magnitude, so progress is a slow, steady ≈0.2–0.3 per step.
Adam: m̂/√v̂ ≈ 1 at start, so each step ≈ lr = 0.1: 9.900, 9.800, 9.700, 9.600, 9.500 (almost linear descent).
Why different: SGD step ∝ gradient (large far away, shrinking near the minimum); Momentum accumulates past gradients, so it accelerates but overshoots; RMSProp and Adam normalize by √(running g²), making the step size ≈ lr regardless of gradient scale — here that is slow with lr = 0.1 from w = 10 (a larger lr or a decay schedule would be used), but it is robust to scale.

Q225Long-Answer Problem 1: for a two-layer network, perform a complete forward and backward pass with all gradients and one update.

No numbers are given, so the general procedure is shown (numerical versions: Q220 for ReLU/linear output, Q221 for sigmoid/BCE). Network: a¹ = W¹x + b¹, h = f(a¹), a² = W²h + b², ŷ = g(a²), loss L.
Forward: compute a¹, h, a², ŷ, then L.
Backward: δ² = ∂L/∂a² (e.g. ŷ − y for sigmoid+BCE or linear+MSE); ∂L/∂W² = δ² hᵀ; ∂L/∂b² = δ²; propagate back: ∂L/∂h = W²ᵀδ²; δ¹ = ∂L/∂h ⊙ f′(a¹); ∂L/∂W¹ = δ¹ xᵀ; ∂L/∂b¹ = δ¹.
Update: θ ← θ − η ∂L/∂θ for W¹, b¹, W², b². Repeat for every mini-batch. In Q221 (values assumed) this gave L: 0.4296 → 0.4029 after one step.

Q226Long-Answer Problem 2: compare SGD, Momentum, RMSProp and Adam mathematically; when is each useful?

SGD: θ ← θ − ηg. Simple, good generalization, but sensitive to lr and slow in ravines.
Momentum: v ← βv + ηg; θ ← θ − v (β≈0.9). Accumulates a velocity: faster along consistent directions, damps oscillation; can overshoot. Useful for ill-conditioned valleys and noisy gradients (often with SGD for CNNs).
RMSProp: s ← βs + (1−β)g²; θ ← θ − ηg/(√s+ε). Per-parameter step sizes; useful for non-stationary problems and RNNs.
Adam: m ← β₁m + (1−β₁)g; v ← β₂v + (1−β₂)g²; m̂ = m/(1−β₁ᵗ), v̂ = v/(1−β₂ᵗ); θ ← θ − η m̂/(√v̂+ε). Momentum + adaptivity + bias correction; the robust default (β₁=0.9, β₂=0.999), good for sparse/noisy gradients and little tuning, though SGD+momentum sometimes generalizes slightly better.

Q227Long-Answer Problem 3: given a computational graph with multiplication, addition, activation and loss, find the gradient of the loss w.r.t. every parameter.

Method: forward pass storing every node value, then traverse backward applying the chain rule: multiplication node z = ab: ∂z/∂a = b, ∂z/∂b = a; addition node: gradient passes unchanged to both inputs; activation node: multiply by f′; loss node: start from ∂L/∂ŷ. Where a value feeds several nodes, add the gradients.
Example (values assumed): ŷ = w·x + b, L = (ŷ − y)², with x = 2, w = 3, b = 1, y = 5. Forward: w·x = 6, ŷ = 7, L = (2)² = 4. Backward: ∂L/∂ŷ = 2(ŷ−y) = 4; addition node → ∂L/∂(wx) = 4 and ∂L/∂b = 4; multiplication node → ∂L/∂w = 4×x = 8, ∂L/∂x = 4×w = 12.

Q229Long-Answer Problem 5: diagnose underfitting, overfitting, good fit and optimization problems from loss curves.

Underfitting: training and validation loss both high and close together, plateau early → bigger model, train longer, better features, less regularization. Overfitting: training loss keeps falling, validation loss bottoms out then rises, large gap (as in Q223) → regularization, dropout, more data, early stopping. Good fit: both fall and converge to low values with a small gap. Optimization problem: loss does not decrease, oscillates wildly, jumps to NaN (lr too high), or decreases extremely slowly (lr too low, vanishing gradients, bad init) → tune lr, optimizer, initialization, normalization, gradient clipping.

Q230Long-Answer Problem 6: design an ANN for a binary-classification dataset and justify the choices.

Use the design of Q224 (30 features, imbalanced). Q231Long-Answer Problem 7: explain backpropagation from first principles using the chain rule and demonstrate on a two-layer network.

The loss is a composition of functions L(ŷ(a²(h(a¹(W¹))))). Gradients of every weight follow from the chain rule: ∂L/∂W¹ = ∂L/∂ŷ · ∂ŷ/∂a² · ∂a²/∂h · ∂h/∂a¹ · ∂a¹/∂W¹. Backpropagation computes this efficiently by one forward pass (store values) and one backward pass, reusing each δ = ∂L/∂a already computed for the layer above (dynamic programming), so cost is about 2× the forward pass rather than recomputing each path.
Numerical demo (Q221, values assumed: x=1, y=1, w1=0.5, w2=1, b=0, sigmoid, BCE): ŷ = 0.6508; δ² = ŷ−y = −0.3492; ∂L/∂w2 = δ²·h = −0.2174; ∂L/∂h = δ²·w2 = −0.3492; δ¹ = −0.3492×0.2350 = −0.0821; ∂L/∂w1 = δ¹·x = −0.0821. With η = 0.5, w2 → 1.1087 and w1 → 0.5410, and the loss decreases 0.4296 → 0.4029.

Q232Long-Answer Problem 8: compare sigmoid, tanh, ReLU and Leaky ReLU with derivatives, pros/cons and suitability.

Sigmoid: σ(x) = 1/(1+e⁻ˣ), range (0,1); σ′ = σ(1−σ) ≤ 0.25. Pros: probability interpretation. Cons: saturates (vanishing gradient), not zero-centred, exp is costly. Use: output layer of binary classification.
Tanh: (eˣ−e⁻ˣ)/(eˣ+e⁻ˣ), range (−1,1); tanh′ = 1 − tanh² ≤ 1. Pros: zero-centred. Cons: still saturates. Use: RNN/LSTM hidden states, shallow nets.
ReLU: max(0,x); derivative 1 for x > 0, 0 for x < 0. Pros: fast, no saturation for x > 0, sparse activations. Cons: dead neurons, not zero-centred. Use: default for hidden layers in deep nets (MLP, CNN).
Leaky ReLU: max(αx, x), α ≈ 0.01; derivative 1 for x > 0, α for x < 0. Pros: keeps a small gradient, so units do not die. Cons: α is an extra hyperparameter. Use: hidden layers when dying ReLUs are observed (GANs, deep nets).

Q233Long-Answer Problem 9: explain regularization comprehensively by comparing L1, L2, dropout, early stopping and data augmentation.

Regularization reduces overfitting by limiting effective model complexity.
L1: adds λΣ|w|; constant-magnitude gradient pushes weights to exactly 0, giving sparse models and feature selection.
L2: adds (λ/2)Σw²; gradient ∝ w shrinks all weights smoothly (weight decay), giving small, stable weights; the most common default.
Dropout: randomly zeroes units with probability p during training (scaling by 1/(1−p) in the inverted form); prevents co-adaptation and approximates an ensemble of subnetworks; off at inference.
Early stopping: stop when validation loss starts to rise and restore the best weights; free, needs a validation set.
Data augmentation: create modified copies (flips, crops, noise) so the model sees more variety; works on the data rather than the model, most effective for images/audio.
These are complementary and are often combined (e.g. L2 + dropout + early stopping).

Q234Long-Answer Problem 10: vanishing gradients and overfitting simultaneously. Propose a strategy.

Treat the two problems separately, and change one thing at a time while watching the curves.
Vanishing gradients: (1) replace sigmoid/tanh with ReLU or Leaky ReLU (derivative 1); (2) He initialization to keep variance stable; (3) batch normalization to keep pre-activations in a good range; (4) residual/skip connections to give gradients a direct path; (5) a gradient-friendly optimizer such as Adam, and check gradient norms per layer.
Overfitting: (1) dropout (0.2–0.5); (2) L2 weight decay; (3) early stopping; (4) data augmentation / more data; (5) reduce the network size if the gap persists.
Justification: the first set restores a learning signal in early layers (improves training loss), the second narrows the train–validation gap (improves validation loss). Because batch norm and dropout can interact, tune the dropout rate on validation data after the activation/initialization fixes.
