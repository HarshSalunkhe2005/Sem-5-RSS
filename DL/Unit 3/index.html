01 · The switchboard of a network

Activation Functions, In Depth

Unit 2 introduced the core activations; here's the fuller picture, including the functions powering today's largest models — and a decision framework for picking one.

Sigmoid

σ(x)=1/(1+e⁻ˣ). Output layer of binary classifiers, LSTM/GRU gates. Smooth, probabilistic — but vanishing gradients for large |x| and not zero-centered.

Softmax

eˣⁱ/Σeˣʲ. Multi-class output layer, Transformer attention weights. Clean probability distribution — but sensitive to outlier logits, output-layer only.

ReLU

max(0,x). Default hidden-layer activation. Cheap, strong gradients for x>0 — but can "die" for x≤0.

Beyond the big three

Tanh

Zero-centered sigmoid, range (−1,1). RNN/LSTM hidden states. Still saturates at the extremes.

Leaky ReLU

max(0.1x, x)-style. Small negative slope keeps "dead" neurons recoverable. Adds a tunable hyperparameter.

ELU

Smooth negative saturation pushes mean activation toward zero — faster convergence, costs an exponential for x<0.

GELU

x·Φ(x). Smooth, probabilistic gating — the default in Transformer blocks (BERT, GPT, ViT).

Swish / SiLU

x·σ(x). Self-gated, non-monotonic — found via search to beat ReLU in EfficientNet-style nets.

Linear

f(x)=x. No non-linearity — used only in the output layer for regression.

Quick decision guide

Hidden layers, general use?

Start with ReLU — fast and effective.

Hidden layers, dying neurons?

Switch to Leaky ReLU, ELU, or GELU.

RNN / LSTM hidden state?

Use Tanh for zero-centered outputs.

Output: binary classification?

Use Sigmoid for a probability score.

Output: multi-class classification?

Use Softmax for a probability distribution.

Output: regression?

Use Linear (identity) — no squashing.

02 · How a model scores its own mistakes

Loss Functions, Compared

A loss function is a single number that scores how far a prediction is from the truth. Small loss → close to the truth; large loss → far from it. Training = adjusting weights to push this number down.

Mean Squared ErrorBinary Cross-EntropyCategorical Cross-Entropy
Task typeRegressionBinary classificationMulti-class classification
Output activationLinear (none)SigmoidSoftmax
Target formatReal-valued number0 or 1One-hot vector
PenalizesSquared distanceWrong-confidence, log scaleWrong-confidence, log scale
Typical usePrice / demand forecastSpam / fraud detectionImage / digit classification

Decision rule: is the output a continuous number → MSE (linear output). Exactly two classes → Binary Cross-Entropy (sigmoid output). One of many mutually exclusive classes → Categorical Cross-Entropy (softmax output). The activation and the loss are always chosen as a pair.

Why cross-entropy beats MSE for classification: cross-entropy's gradient stays large when a prediction is confidently wrong; MSE paired with a saturated sigmoid/softmax produces tiny gradients in exactly that regime, slowing learning right when it matters most.

03 · Why models fail to generalize

The Bias-Variance Trade-off & Regularization

Every model is trying to approximate an unknown true function f(x). A model that's too simple can't bend to fit it (underfitting); one that's too flexible chases noise in the training data instead of the real pattern (overfitting).

No Free Lunch Theorem (Wolpert, 2002): no single classifier works best for every possible problem. Every model is a simplified version of reality built on assumptions, and those assumptions inevitably fail on some tasks — which is exactly why the field needs a whole toolkit of architectures and regularization strategies rather than one universal best model.

High bias — underfitting

Model too simple to capture the underlying pattern. High error on both training and test data. Example: fitting a straight line through a sine wave.

High variance — overfitting

Model too flexible, memorizes noise. Low training error but high test error. Example: a high-degree polynomial wiggling through every point.

Diagnosing errors in practice

Training errorValidation errorCauseFix
HighHighHigh biasIncrease model complexity, train more epochs
LowHighHigh varianceMore data, regularization, early stopping
LowLowSweet spotYou're done!

The regularization toolkit

L2 penalty

Add λ(θ) to the loss so large weights are penalized. The gradient update becomes ∇w += λw on top of the usual gradient — every step nudges weights gently toward zero, giving a smoother, less noise-sensitive function.

Dataset augmentation

A complex model can memorize a small dataset outright. More (realistic, varied) data raises the bar — the model can't memorize what it hasn't seen distinctly, and augmented data can resemble the held-out distribution.

Early stopping

Track validation error during training; stop (and keep) the checkpoint at its minimum. Past that point, training error keeps falling but validation error climbs — the tell-tale of overfitting.

Dropout

Randomly zero each neuron with probability p every training pass, forcing the network not to over-rely on any one neuron. See the deep dive below.

Dropout is secretly an ensemble

With M neurons in a layer, there are 2M possible "thinned" sub-networks depending on which neurons survive a given pass. Each mini-batch effectively trains one randomly-sampled thinned network (with shared parameters across all of them) — training with dropout is like training a huge ensemble of networks simultaneously, at the cost of one.

Ideal test-time behaviour

Run every possible thinned sub-network on the test input and average their outputs — the true ensemble prediction. Completely impractical: 2M networks.

The practical shortcut — weight scaling

Use the single full (no-dropout) network, but multiply every weight that was subject to dropout by its keep probability (1−p). This single full-network pass closely approximates averaging the whole ensemble.

Two equivalent conventions — know both: the classical version above scales weights by (1−p) only at test time, leaving training untouched. The inverted dropout version (the modern default, and what's on the Numericals page) instead scales the surviving activations by 1/(1−p) during training, so test time needs no scaling at all and inference is simply the plain forward pass. Both land at the same expected activation — they just move the division to opposite ends of training vs. testing.

Practical workflow: (1) split data into train/validation/test, (2) start with a sensible baseline architecture, (3) use sound defaults — ReLU/tanh activation, He/Xavier initialization, Adam optimizer, (4) monitor train vs. validation error — but never touch the test set until the very end.

04 · How networks actually descend the loss

Optimization Algorithms

Training = minimizing the average loss over the data by iteratively adjusting parameters θ. We never see the whole loss landscape — only the local gradient — so every method here is a different strategy for using that local slope well.

Gradient descent — the foundation

θ ← θ − η·∇L(θ) — step opposite the gradient, scaled by learning rate η.
η too small → painfully slow. η too large → overshoot, oscillate, diverge.

The zig-zag problem: when the loss surface is ill-conditioned (steep in one direction, flat in another — a high condition number), gradient descent bounces across the steep walls while barely progressing along the valley floor. Momentum and adaptive methods exist largely to fix exactly this.

How much data per step?

Batch GD

Full dataset per step — exact gradient, smooth path, expensive per step.

Stochastic GD

One random point per step — cheap, noisy, jittery path. The noise helps escape sharp minima.

Mini-batch GD

b points per step (b=32–512) — the practical sweet spot every real training run uses.

Momentum & Nesterov

Momentum: v ← βv + η·∇L, then θ ← θ − v — an exponentially-decaying average ("velocity") of past gradients. Consistent directions build speed; oscillating ones cancel out.
β=0.9 is the common default, giving an effective memory of 1/(1−β) ≈ 10 past steps.

Nesterov (NAG): evaluates the gradient at the look-ahead point θ+βv instead of the current point — "momentum acts then looks; Nesterov looks then acts," braking earlier before overshooting.

Adaptive methods — one learning rate per parameter

AdaGrad

Divide the step by the square root of the accumulated sum of squared gradients per parameter. Great for sparse features — but the accumulator only grows, so the effective rate can vanish on long runs.

RMSprop

AdaGrad, but the sum is replaced by an exponentially-decaying average — old gradients are "forgotten," so the rate never vanishes. The de-facto standard before Adam.

Adam

RMSprop + momentum + bias correction. Tracks EMAs of both the gradient (m) and its square (v), bias-corrects each, then steps with the momentum scaled by the magnitude. Defaults: β₁=0.9, β₂=0.999, ε=1e-8.

Beyond Adam: AdamW (decouples weight decay — today's default for training Transformers), Nadam (Adam + Nesterov look-ahead), AMSGrad (fixes a convergence edge case).

Timeline, for reference: Nesterov momentum (1983) → AdaGrad (2011) → RMSprop (2012) → Adam (2015) — each one arriving specifically to fix the previous method's failure mode.

Local minima vs. saddle points

A common misconception: deep nets rarely get stuck in bad local minima. The real obstacle in high dimensions is saddle points — where some directions curve up and others down, and the gradient nearly vanishes. Plain gradient descent crawls near a saddle; momentum carries speed through the flat region, and adaptive scaling amplifies the small escape direction.

Optimizer cheat sheet

OptimizerAdvantagesDisadvantages
SGDSimple, easy to implementSlow convergence, requires tuning
Mini-batch SGDFaster than full-batch SGDComputationally expensive, can get stuck at local minima

RMSpropPrevents AdaGrad's too-fast decayComputationally more expensive

Adam is the default choice for most problems thanks to its robust, low-tuning-effort performance — but the "right" optimizer still depends on the dataset, the architecture, and the compute budget available.

05 · Don't just pick η — change it over time

Learning-Rate Scheduling

Early in training you're far from the minimum — big steps make fast progress. Late in training you're near it — big steps overshoot and bounce. A constant learning rate under SGD leaves you orbiting the minimum in a "noise ball" whose radius scales with η; shrinking η shrinks that ball toward a point.

Step decay

Drop η by a factor every s epochs — e.g. halve it every 5 epochs, or divide by 10 every 20. Produces the visible "staircase" in loss curves — still extremely common in practice.

Exponential decay

Smooth, continuous version of step decay — η shrinks by a fixed ratio every epoch.

Cosine annealing

η follows a cosine curve down to (near) zero over training — today's common default, especially for large-model training.

ReduceLROnPlateau

Watch the validation loss instead of the epoch count — cut η by a factor (e.g. ÷10) only once validation loss stops improving for a set number of epochs ("patience"). Reactive rather than a fixed schedule.

Warmup

The mirror image of decay: gradually increase η from near-zero at the very start of training, then let the chosen decay schedule take over. Avoids destabilizing large early updates when weights are still randomly initialized.

Unit 3 — Summary

  • ReLU is the hidden-layer default; GELU/Swish power today's largest Transformer/CNN architectures
  • Match the loss to the output activation: Linear→MSE, Sigmoid→BCE, Softmax→CCE
  • Simple models underfit (high bias); complex models overfit (high variance) — regularization (L2, augmentation, early stopping) buys back generalization
  • Plain gradient descent zig-zags on ill-conditioned surfaces; momentum adds inertia, adaptive methods (AdaGrad→RMSprop→Adam) give every parameter its own rate
  • Saddle points, not bad local minima, are the real obstacle in high-dimensional training
  • Learning-rate schedules trade early speed for late precision — start high, decay low
