01 · The big picture

Optimization Algorithms — the Family at a Glance

Training a deep network means minimizing a loss L(θ) over millions of parameters using only the local gradient. Every optimizer below is a different recipe for turning that gradient into a step. Unit 3 already explained SGD, Momentum, Nesterov, AdaGrad, RMSprop and Adam in depth (Unit 3 → Optimization Algorithms), so here each gets a compact exam-style treatment, and the new ones (Adadelta) get the full 5-part write-up.

Choosing (faculty note): for sparse data use an adaptive method (Adagrad, Adadelta, RMSprop, Adam). RMSprop, Adadelta and Adam behave similarly in many cases; Adam = RMSprop + bias correction + momentum, and does better than RMSprop as gradients get sparse.

02 · Gradient descent and its three flavours

Gradient Descent & SGD

  • Definition: gradient descent updates each parameter against its gradient: θ ← θ − α·∇L(θ), α = learning rate.
  • Intuition: the gradient points uphill (steepest ascent); stepping the opposite way walks downhill. α sets the step length.
  • Working: Batch GD: ∇L = (1/N)Σ∇Lᵢ over all N examples, m = N, one update per epoch. SGD: ∇L ≈ ∇Lᵢ from one random example, m = 1, N updates per epoch, noisy. Mini-batch: ∇L ≈ (1/m)Σ∇Lᵢ over m ≈ 32–256 examples, vectorizes on GPUs, the practical default.
  • Example (deck): L(w,b) = w² + 4b², ∇L = (2w, 8b), α = 0.1 gives w ← 0.8w, b ← 0.2b. From (4, 2): step 1 → (3.2, 0.4), loss 32 → 10.88; after 8 steps w = 4·0.8⁸ ≈ 0.671, b ≈ 0, loss ≈ 0.4504. b converges first because its curvature (coefficient 4) is steeper, so one global α is a compromise, which motivates momentum and adaptive methods.
  • Conclusion: batch GD is exact but slow and memory-hungry; SGD is cheap but noisy (its noise can help escape saddles; a decaying α is needed); mini-batch balances both. Too small α is slow, too large oscillates or diverges.

03 · Give the ball inertia

SGD with Momentum

Mind map
  • Optimisers
    • Gradient descent
      • Batch: exact, slow
      • SGD: noisy, fast
      • Mini-batch: default
    • Momentum family
      • Momentum: velocity v
      • NAG: look ahead, then step
    • Adaptive family
      • Adagrad: sum of g squared
      • RMSprop: decaying average
      • Adadelta: no learning rate
      • Adam: m + v, bias correction
  • Definition: SGD plus a velocity term, an exponentially weighted average of past gradients: v ← βv + α∇L, θ ← θ − v.
  • Intuition: a heavy ball rolling downhill keeps part of its previous direction. Consistent gradient directions build speed; sign-flipping (zig-zag) components cancel.
  • Working: β = 0 is plain GD; β = 0.9 gives an effective memory of 1/(1−β) ≈ 10 steps (deck range 0.8–0.99).
  • Example: L = w², w₀ = 4, α = 0.1, β = 0.9. Step 1: g = 8, v = 0.8, w = 3.2. Step 2: g = 6.4, v = 0.9·0.8 + 0.1·6.4 = 1.36, w = 3.2 − 1.36 = 1.84. (Plain GD would be at 2.56 after step 2.) The deck's run (α = 0.04, β = 0.7) reaches loss 0.0137 against 4.2477 for vanilla GD after 8 steps.
  • Conclusion: faster on shallow consistent slopes and less zig-zag; costs one extra hyperparameter and can overshoot the minimum before settling.

04 · Look before you leap

Nesterov Accelerated Gradient (NAG)

  • Definition: momentum variant that evaluates the gradient at the look-ahead point where the velocity is about to carry the weights: v ← βv + α∇L(θ − βv), θ ← θ − v (equivalent to the deck's θ + βv with the opposite sign convention for v).
  • Intuition: "momentum acts then looks; Nesterov looks then acts". By peeking at the slope ahead, it feels an approaching wall one step early and brakes before overshooting.
  • Working: (1) compute look-ahead θ̃ = θ − βv; (2) gradient at θ̃; (3) update velocity; (4) move. Better theoretical convergence on convex problems, and it tracks curved valleys (the deck's Rosenbrock valley) more tightly.
  • Example: same L = w², w₀ = 4, α = 0.1, β = 0.9. Step 1: v = 0 so look-ahead is 4, g = 8, v = 0.8, w = 3.2. Step 2: look-ahead = 3.2 − 0.9·0.8 = 2.48, g = 4.96, v = 0.72 + 0.496 = 1.216, w = 3.2 − 1.216 = 1.984. Because the gradient is taken at 2.48 (closer to the minimum) instead of 3.2 (g = 6.4), the velocity is smaller (1.216 vs 1.36), so NAG is braking earlier than classical momentum, which would be at 1.84.
  • Conclusion: same cost as momentum, less overshoot. Nadam = Adam with this look-ahead.

05 · The first adaptive method

Adagrad (Adaptive Gradient)

  • Definition: gives every parameter its own learning rate, scaled by the history of that parameter's squared gradients: Gₜ = Gₜ₋₁ + gₜ², θ ← θ − α·g / (√Gₜ + ε) (ε ≈ 1e-8 only avoids division by zero).
  • Intuition: sparse (rare) features have small accumulated gradient, so they keep large steps; dense features accumulate quickly and get small steps.
  • Working: the accumulator Gₜ is a running sum, so it only grows and the effective rate α/√Gₜ shrinks monotonically.
  • Example: L = w², w₀ = 4, α = 0.5. Step 1: g = 8, G = 64, step = 0.5·8/8 = 0.5, w = 3.5. Step 2: g = 7, G = 64 + 49 = 113, √G = 10.63, step = 0.5·7/10.63 = 0.329, w ≈ 3.171. Step 1 is always ≈ α·sign(g); later steps shrink as G grows.
  • Conclusion: good for sparse data and removes manual rate tuning, but on deep or long runs the rate decays toward zero and learning stalls (the "dead neuron" problem in the faculty notes). Fix: forget old gradients (RMSprop, Adadelta).

06 · Adagrad, but it forgets

RMSprop

  • Definition: replaces Adagrad's cumulative sum by an exponentially decaying average of squared gradients: E[g²]ₜ = ρE[g²]ₜ₋₁ + (1−ρ)gₜ², θ ← θ − α·g / (√E[g²]ₜ + ε), ρ ≈ 0.9.
  • Intuition: same per-parameter scaling, but old gradients fade, so the effective rate never collapses. Introduced in Hinton's lecture, never formally published.
  • Working: ρ controls how fast the past is forgotten; the average acts on gradient magnitude where momentum acts on gradient direction.
  • Example: w₀ = 4 (g = 8), ρ = 0.9, α = 0.1: E[g²] = 0.1·64 = 6.4, √ = 2.53, step = 0.1·8/2.53 = 0.316, w = 3.684. Compare Adagrad's first step (α·1): the (1−ρ) factor makes the first RMSprop step larger than α.
  • Conclusion: a steady well-scaled step all the way in; the de-facto standard before Adam and still strong for RNNs. Still needs a base α.

07 · No learning rate to set

Adadelta

  • Definition: an extension of Adagrad that fixes its aggressively shrinking rate and removes the need to choose a global learning rate. It keeps two decaying averages: of squared gradients and of squared parameter updates.
  • Intuition: the update should have the same "units" as the parameter. Instead of multiplying the gradient by a fixed α, multiply by the ratio RMS(past updates) / RMS(past gradients), so the step size is learned from the running history of how large past steps were.
  • Working (formulas):
    1. E[g²]ₜ = ρE[g²]ₜ₋₁ + (1−ρ)gₜ² (decaying average of squared gradients, as in RMSprop)
    2. Δθₜ = − [ √(E[Δθ²]ₜ₋₁ + ε) / √(E[g²]ₜ + ε) ] · gₜ (ratio of RMS values replaces α)
    3. E[Δθ²]ₜ = ρE[Δθ²]ₜ₋₁ + (1−ρ)Δθₜ² (decaying average of squared updates)
    4. θₜ₊₁ = θₜ + Δθₜ
    Typical ρ = 0.9–0.95, ε ≈ 1e-6.
  • Example: first step with g = 2, ρ = 0.9, ε = 1e-6, E[g²] = E[Δθ²] = 0 initially. E[g²] = 0.1·4 = 0.4. Δθ = −√(0+1e-6)/√(0.4+1e-6) · 2 = −0.001/0.6325 · 2 ≈ −0.00316. Then E[Δθ²] = 0.1·(0.00316)² = 1e-6. Early steps are tiny because the update history is empty (ε sets the initial scale) and grow as E[Δθ²] builds up.
  • Conclusion: advantage: no default learning rate to set, no vanishing rate. Disadvantage: extra state and computation. Faculty summary: Adagrad → RMSprop → Adadelta are all adaptive-rate fixes; Adam combines the decaying gradient average (momentum) with the decaying squared-gradient average (RMSprop/Adadelta).

08 · The default optimizer

Adam (Adaptive Moment Estimation)

  • Definition: keeps decaying averages of both the gradient (1st moment, like momentum) and the squared gradient (2nd moment, like RMSprop), bias-corrects them, and steps with momentum scaled by magnitude.
  • Intuition: direction memory from m, per-parameter scaling from v; the bias correction fixes the fact that m and v start at zero.
  • Working:
    1. mₜ = β₁mₜ₋₁ + (1−β₁)gₜ and vₜ = β₂vₜ₋₁ + (1−β₂)gₜ²
    2. m̂ₜ = mₜ/(1−β₁ᵗ), v̂ₜ = vₜ/(1−β₂ᵗ) (bias correction)
    3. θ ← θ − α·m̂ₜ / (√v̂ₜ + ε)
    Defaults: β₁ = 0.9, β₂ = 0.999, ε = 1e-8.
  • Example: t = 1, g = 2: m = 0.1·2 = 0.2, v = 0.001·4 = 0.004; m̂ = 0.2/0.1 = 2, v̂ = 0.004/0.001 = 4; step = α·2/√4 = α. So the first Adam step is about α·sign(g) regardless of gradient size; without bias correction it would be 0.2/0.063 ≈ 3.2α, a step more than three times too big (see Unit 3 for the t = 2 worked case).
  • Conclusion: easy to implement, efficient, robust defaults, but stores two extra numbers per weight. Variants: AdamW (decoupled weight decay, default for Transformers), Nadam (Nesterov), AMSGrad. See Unit 3 for the full comparison table.

09 · Keep every layer's inputs well-behaved

Batch Normalization In syllabus · not in slides

  • Definition: a layer that normalizes each feature of a layer's inputs over the current mini-batch to zero mean and unit variance, then restores flexibility with a learnable scale γ and shift β (Ioffe and Szegedy, 2015).
  • Why: as earlier layers change, the input distribution of later layers keeps shifting ("internal covariate shift", the original motivation). Normalizing keeps pre-activations in a healthy range, so activations do not saturate and gradients stay usable.
  • Working (training, per feature, batch of m values x₁..xₘ):
    1. Batch mean: μ_B = (1/m) Σ xᵢ
    2. Batch variance: σ²_B = (1/m) Σ (xᵢ − μ_B)²
    3. Normalize: x̂ᵢ = (xᵢ − μ_B) / √(σ²_B + ε)
    4. Scale and shift: yᵢ = γ·x̂ᵢ + β (γ, β learned by backprop; they let the network undo the normalization if that is optimal)
  • Train vs inference: at training time μ_B, σ²_B come from the batch. At inference there may be a single example, so the layer instead uses running averages collected during training: μ_run ← λμ_run + (1−λ)μ_B (same for variance, λ ≈ 0.9–0.99). Using batch statistics at test time is a classic bug.
  • Example: batch x = [2, 4, 6, 8]: μ = 5, σ² = (9+1+1+9)/4 = 5. With ε = 1e-5, x̂ ≈ [−1.342, −0.447, 0.447, 1.342]. With γ = 2, β = 1: y ≈ [−1.683, 0.106, 1.894, 3.683].
  • Benefits: faster training and higher usable learning rates; less sensitivity to weight initialization; helps with vanishing/exploding gradients; mild regularizing effect (batch noise), sometimes reducing the need for dropout.
  • Limits: unreliable for very small batches; awkward for RNNs. Alternatives: Layer Norm (Transformers), Group Norm.
  • Conclusion: normalize with batch statistics, rescale with learned γ and β, use running statistics at inference. Placed between the linear layer and the activation (or just after it, both are used).

10 · When backprop breaks down in deep nets

Exploding and Vanishing Gradients In syllabus · not in slides

  • Definition: in a deep network the gradient reaching early layers is a product of many per-layer factors. If those factors are mostly < 1 the product shrinks toward 0 (vanishing); if mostly > 1 it grows without bound (exploding).
  • Intuition: by the chain rule ∂L/∂w₁ = ∂L/∂aₙ · ∏ (wₖ·f′(zₖ)) ⋯. Multiply 10 numbers around 0.25 and you get ≈ 1e-6; multiply 10 numbers around 1.5 and you get ≈ 58.
  • Causes: saturating activations (sigmoid′ ≤ 0.25, tanh′ ≤ 1 and ≈ 0 when saturated); weights initialised too small (vanish) or too large (explode); very deep stacks; long sequences in RNNs (the same weight matrix multiplied over every time step).
  • Effects: Vanishing: early layers barely learn, loss plateaus, training stalls. Exploding: huge updates, loss oscillates or becomes NaN/Inf, weights diverge.
  • Numerical illustration: sigmoid gradient factor max 0.25 across 10 layers: 0.25¹⁰ ≈ 9.5×10⁻⁷. A per-layer factor of 1.5 across 10 layers: 1.5¹⁰ ≈ 57.7. With 1.5 across 50 layers: ≈ 6×10⁸.
  • Fixes:
    FixHow it helpsTargets
    ReLU / Leaky ReLU / GELUderivative is 1 for positive inputs, so no shrinkagevanishing
    Weight initialisationXavier/Glorot: Var(w) = 2/(n_in + n_out) for tanh/sigmoid. He: Var(w) = 2/n_in for ReLU. Keeps activation and gradient variance roughly constant across layers.both
    Batch normalizationkeeps pre-activations in range; see aboveboth
    Residual (skip) connectionsy = x + F(x), so ∂y/∂x = 1 + ∂F/∂x: a direct gradient highway (ResNet)vanishing
    Gradient clippingif ‖g‖ > τ then g ← g·τ/‖g‖. Example: ‖g‖ = 10, τ = 5 scales g by 0.5. Standard for RNNs.exploding
    LSTM / GRU gatesthe cell state is updated additively (c_t = f⊙c_{t−1} + i⊙c̃), giving a near-constant error path through timevanishing in RNNs
    Smaller learning rate, warm-uplimits damage from large early updatesexploding
  • Conclusion: detect via gradient norms per layer or a NaN loss; use ReLU-family activations + He/Xavier init + batch norm + residual connections as the default recipe, add clipping for recurrent models.

11 · Choosing the knobs the optimizer cannot learn

Hyperparameter Tuning In syllabus · not in slides

  • Definition: hyperparameters are settings fixed before/outside training (learning rate, batch size, epochs, architecture, momentum β, dropout p, weight decay λ). Parameters (weights, biases) are learned; hyperparameters are searched.
  • Key hyperparameters:
    • Learning rate: the most important one (the lecture deck's first pitfall: "not tuning η, it dominates everything else"). Search on a log scale, e.g. 1e-5 to 1e-1; a schedule (Unit 3) or an LR-range test helps.
    • Batch size: larger gives smoother gradients and better hardware use but more memory and possibly poorer generalization; smaller adds helpful noise. Typical 32–256.
    • Epochs: too few underfit, too many overfit; use early stopping on validation loss.
    • Architecture: depth, width, activation, dropout rate, weight decay.
  • Search strategies:
    MethodIdeaPros / cons
    Manualintuition and trialcheap start, not reproducible
    Grid searchtry every combination of a fixed grid. 3 learning rates × 3 batch sizes × 2 dropouts = 18 runsexhaustive but cost explodes exponentially with the number of hyperparameters
    Random searchsample each hyperparameter from a distribution (Bergstra and Bengio, 2012)usually better than grid for the same budget, because only a few hyperparameters really matter and random sampling tries many distinct values of each
    Bayesian optimizationbuild a surrogate model (e.g. Gaussian process) of validation score vs hyperparameters; pick the next trial by an acquisition function that balances exploration and exploitationsample-efficient for expensive runs; harder to parallelize
    Early-stopping schemes (e.g. Hyperband)run many configs briefly, keep the best, give them more budgetsaves compute
  • Validation protocol: split into train / validation / test. Tune hyperparameters on the validation set only; touch the test set once, at the end. For small data use k-fold cross-validation. Average over a few seeds, because one lucky run can mislead.
  • Practical tips (lecture deck): use log axis for loss; compare optimizers each at their own best η, not one shared η; standardize inputs; if it diverges lower η first, add warm-up, clip gradients; if too slow raise η via an LR-range test.
  • Conclusion: tune the learning rate first, prefer random over grid search, use Bayesian/Hyperband when each run is expensive, and keep the test set untouched.

12 · Opening the black box

Interpretability of Deep Networks In syllabus · not in slides

  • Definition: interpretability (explainability) is the ability to explain why a model produced a given output, in terms a human can inspect.
  • Why needed: trust and adoption (medicine, finance, law), debugging (spotting shortcuts such as a classifier looking at a watermark), fairness audits, and regulation requiring explanations.
  • Scope: global (how the model behaves overall) vs local (why this one prediction); intrinsic (simple transparent models) vs post-hoc (explain a trained black box).
  • Main techniques:
    TechniqueHow it worksOutput
    Saliency / gradient mapstake ∂(class score)/∂(input pixel); large magnitude means the output is sensitive to that pixel. Variants: Gradient×Input, SmoothGrad, Integrated Gradients.pixel-level heatmap
    Grad-CAMfor a conv layer with feature maps Aᵏ, weight each map by αₖ = average over positions of ∂yᶜ/∂Aᵏ; heatmap = ReLU(Σ αₖAᵏ), upsampled onto the imagecoarse class-specific region map
    LIMEperturb the input around one example, query the black box, fit a simple weighted linear model locally; its coefficients are the explanationlocal feature importances, model-agnostic
    SHAPassign each feature its Shapley value φᵢ from cooperative game theory (average marginal contribution over feature subsets), with f(x) = baseline + Σ φᵢadditive, consistent per-feature attributions (local and global)
    Feature visualisationoptimise an input to maximally activate a neuron/channel (activation maximisation), or inspect filters and embeddingswhat a unit has learned to detect
  • Example: a chest X-ray classifier says "pneumonia". Grad-CAM highlights the lung opacity (good) or a hospital marker in the corner (a shortcut, so retrain or fix the data). SHAP on a tabular credit model might say: baseline 0.30, income +0.25, debt −0.10, age +0.05 → output 0.50.
  • Accuracy vs explainability: linear models and shallow trees are transparent but often less accurate; deep nets are accurate but opaque. Post-hoc tools narrow the gap but give approximations: explanations can be unstable or misleading, so they should be validated, not trusted blindly.
  • Conclusion: use gradient/CAM methods for vision, LIME/SHAP for model-agnostic local explanations, feature visualisation to understand units, and always remember the explanation describes the model, not necessarily the real-world cause.

Unit 4 — Summary

Mind map
  • Training Deep Nets
    • Batch normalisation
      • Normalise per batch
      • Scale gamma, shift beta
      • Running stats at inference
    • Gradient problems
      • Vanishing
      • Exploding

  • GD family: batch (exact, slow), SGD (noisy, fast), mini-batch (default). Momentum adds velocity, NAG adds look-ahead.
  • Adaptive family: Adagrad (sum, rate vanishes) → RMSprop (decaying average) → Adadelta (ratio of averages, no η) → Adam (momentum + RMSprop + bias correction).

  • Tune learning rate first; random search beats grid; Bayesian for costly runs; tune on validation, test once.
  • Interpretability: saliency, Grad-CAM, LIME, SHAP, feature visualisation; there is a trade-off between accuracy and explainability.
